# 面试复盘与沉淀 Skill

用户每场面试结束后，用本 skill 将面试材料（录音转写原文、问答整理等）做三件事：
1. 在本场面试文件夹中生成复盘文档；
2. 将问题合并进《面试问题沉淀汇总》；
3. 将复盘要点合并进《面试资料总汇总》。

## 固定路径

- 面试根目录：`/home/ubuntu/projects/WiseSentinel/docs/interview/`
- 沉淀文档 1（按主题归档问题+短板）：`面试问题沉淀汇总-202608.md`（面试根目录下）
- 沉淀文档 2（按来源汇总准备资料）：`面试问题与资料汇总/面试资料总汇总-202608.md`
- 每场文件夹命名：`MMDD-公司名` 或 `YYYYMMDD-公司名`，沿用既有格式（0813-海康 / 20260820-遥望）

## 执行流程

### 第 1 步：定位与读取材料
1. 用户提供面试原文（`原文_*.txt`）或问答整理 md。若文件夹尚无复盘文档，按本 skill 生成。
2. 读取原文/整理文档全文，同时读两份沉淀文档的结构（至少各读 100 行以了解章节结构）。

### 第 2 步：生成本场复盘文档
写入本场文件夹：`<公司名>面试复盘与问题分析.md`，结构（参照同花顺/遥望既有复盘文档）：

```markdown
# <公司名>面试复盘与问题分析（YYYY-MM-DD）

> 岗位方向 / 面试性质一句话定性

## 一、面试问题清单（按时序）
编号列出面试官全部问题；面试官的关键评价/质疑用**加粗**标出。

## 二、问题分析
- 面试官提问模式定性（如"连环确认式深挖"/"AI 含量审判"）
- 答得较好的部分（引用具体回答，说明为何好）
- 暴露的短板：与跨场 P0/P1/P2 清单对照，标注是第几次出现

## 三、本场结论
一两段：通过概率判断、最需优先补强的 1-2 点。
```

### 第 3 步：更新《面试问题沉淀汇总-202608.md》
1. 头部"覆盖场次"追加本场景次。
2. 将新问题按主题归入既有章节（架构/框架选型/RAG/上下文与Memory/评测/沙箱安全/幻觉治理/模型底层/后端八股/项目背景/AI Coding/职业动机等），格式：`- 问题（公司）`；追问合并到主问题下的【追问】。
3. "公司索引表"追加一行（场次/方向/核心考察）。
4. "高频主题统计"如计数变化需更新。
5. "自身短板复盘（按严重性排序）"章节：
   - 若暴露既有短板 → 对应条目场次计数 +1（如 ★6场→★7场），追加暴露实证；
   - 若是新短板 → 判断严重性插入 P0/P1/P2 合适位置；
   - 文末"各场短板速查表"追加一行。

### 第 4 步：更新《面试问题与资料汇总/面试资料总汇总-202608.md》
1. "快速导航"表追加本场景次与主题。
2. 按既有格式追加一节：`## 来源：<目录名>/<复盘文件名>`，三部分：核心问题清单、高分回答要点（保留关键数字与话术）、自身短板与对策。
3. 若"补强优先级"结论有变，更新该节。

### 第 5 步：汇报
向用户简要汇报：复盘文档路径、两份沉淀文档各更新了什么、本场最值得优先补强的 1-2 点。

## 质量要求

- **数字口径一致性**：涉及平台数据时使用统一口径（200 条 Case、工具成功率 88.62%、平均 3.8 步、L0=7/L1=3/L2=0），发现面试回答与口径冲突要在复盘中标出。
- **短板必须跨场对照**：孤立短板标注"新出现"，重复出现的必须写"第 N 次"，这是本 skill 的核心价值。
- 复盘分析要引用原文证据（面试官原话、候选人原回答），不空泛评价。
- 候选人背景：李信达，4 年 Go 后端，WiseSentinel 智能运维 Agent 平台负责人 + 隐私计算沙箱经验，求职 Agent/AI Infra 方向。
- 不修改任何原文/纪要/jd 文件；沉淀文档只做增量更新。
