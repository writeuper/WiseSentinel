# HTTP 5xx 错误率升高排查 Runbook

## 适用范围

适用于服务端 5xx 比例超过 SLO 的故障。示例服务和查询不对应真实环境。

## 排查顺序

1. 按服务、接口、租户、地域和版本拆分错误率，确认全局或局部。
2. 查询错误日志聚合，优先识别 `panic`、依赖 5xx、超时、连接拒绝和参数校验异常。
3. 对比请求量、P50/P95/P99、实例数、CPU/内存、连接池与队列。
4. 检查最近发布、配置、数据库 schema、网关路由和依赖变更。
5. 通过 trace 采样确认最慢或最常失败的下游节点。

示例 PromQL：`sum(rate(http_requests_total{status=~"5.."}[5m])) by (service,route)`。

## 处置

优先回滚已确认相关的变更；依赖故障使用熔断、降级或隔离流量；资源不足时扩容但同步检查根因。禁止通过关闭审计、鉴权或错误告警来“止血”。

## 验证与升级

错误率恢复到 SLO 以下并持续两个窗口，且关键接口成功样本通过后再逐步恢复流量。跨服务或数据写入异常升级到架构和业务负责人。

## 证据

分维度错误率、接口样本、日志摘要、trace 摘要、资源与依赖指标、变更版本、处置动作和恢复时间。
