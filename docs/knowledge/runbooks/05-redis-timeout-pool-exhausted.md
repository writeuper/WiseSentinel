# Redis 超时与连接池耗尽排查 Runbook

## 适用范围

适用于 `redis timeout`、连接拒绝、连接池耗尽或命令延迟升高。

## 排查顺序

1. 按命令、服务、实例和租户统计超时及错误率，确认是否集中在热点 Key。
2. 检查 Redis latency、连接数、拒绝连接、内存、淘汰和慢命令指标。
3. 检查客户端池大小、等待时间、连接泄漏、超时和重试配置。
4. 关联网络、节点切换、发布和流量突增；区分单节点与集群级问题。
5. 检查大 Key、热 Key、阻塞命令和过期风暴。

## 处置

优先限流非核心读写、隔离热点并切换已验证的备用节点；按审批调整连接池。禁止直接删除未知 Key 或清空实例。修复应包含命令治理、Key 分片、连接回收和重试预算。

## 验证与升级

延迟、连接池等待、命中率和业务错误率恢复后再解除限流。数据丢失、主从不一致或集群不可用时立即升级。

## 证据

命令级延迟、连接池指标、慢命令摘要、节点事件、网络指标、配置版本和业务影响。
