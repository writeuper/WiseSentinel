# MySQL 死锁与锁等待排查 Runbook

## 适用范围

适用于 `deadlock`、`Lock wait timeout exceeded`、事务提交失败或写入延迟升高。

## 排查顺序

1. 收集死锁摘要、事务涉及的表/索引和发生时间；禁止导出用户敏感字段。
2. 查询锁等待、活动事务、连接数、慢查询和提交延迟。
3. 关联应用 trace 确认事务边界、访问顺序、重试和幂等设计。
4. 对比发布、索引/schema 变更及流量热点。
5. 判断是短暂竞争、长事务、缺索引还是访问顺序不一致。

## 处置

按审批终止确认的长事务并适度限流；启用有上限、带抖动的死锁重试。修复应缩短事务、统一锁顺序、补充索引并验证幂等。不要盲目提高锁等待超时。

## 验证与升级

死锁频率、锁等待、写入错误率和延迟恢复，且数据一致性校验通过。出现重复扣款、库存不一致或跨库事务异常时立即升级。

## 证据

死锁摘要、活动事务、锁等待图、慢查询摘要、应用版本、请求幂等键和数据校验结果。
