# Kubernetes 节点 CPU/磁盘/内存压力排查 Runbook

## 适用范围

适用于节点 `MemoryPressure`、磁盘空间不足、inode 耗尽、CPU throttling 或 Pod 驱逐。

## 排查顺序

1. 确认受影响节点、压力类型、开始时间和被驱逐工作负载。
2. 检查节点 CPU、内存、磁盘、inode、容器日志和临时目录增长。
3. 对比调度分布、Pod request/limit、DaemonSet 和最近扩缩容。
4. 检查镜像、日志轮转、临时文件、批任务和异常 Pod 是否占满资源。
5. 评估业务容量、PDB、可用区分布与故障转移能力。

## 处置

先迁移或扩容节点并保护关键工作负载；按审批清理已确认的临时数据，不能删除未知业务数据。修复应包含资源配额、日志轮转、拓扑分散和容量预测。

## 验证与升级

压力状态清除、驱逐停止、关键 Pod Ready 且业务 SLO 恢复后结束。多个可用区受影响、持久卷异常或有数据丢失风险时升级。

## 证据

节点 conditions、资源曲线、驱逐事件、Pod 分布、磁盘/inode 使用、扩缩容记录、清理审批和业务影响。
