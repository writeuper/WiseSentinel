# API 网关限流与 429 升高排查 Runbook

## 适用范围

适用于网关 `429 Too Many Requests` 增加、租户流量突增或限流规则误配。

## 排查顺序

1. 按租户、用户、IP、接口和规则统计 429，确认影响边界。
2. 对比请求速率、突发流量、鉴权结果和下游容量。
3. 检查网关 CPU、连接数、规则版本、分布式限流状态和时钟偏差。
4. 关联营销活动、重试风暴、爬虫/WAF 事件与最近配置变更。
5. 判断是真实容量保护还是规则/计数器异常。

## 处置

仅对已确认的租户或接口按审批临时调整阈值；对异常来源启用 WAF/隔离策略。不得全局关闭限流或泄露租户身份信息。修复应包含弹性配额、重试退避和规则版本审计。

## 验证与升级

目标流量可用、429 在预期范围、下游错误率稳定后恢复默认配额。疑似攻击、跨租户影响或规则无法回滚时升级安全与平台负责人。

## 证据

429 分布、规则版本、流量曲线、下游容量、网关资源、WAF/变更事件和审批记录。
