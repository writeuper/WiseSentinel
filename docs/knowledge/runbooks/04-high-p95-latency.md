# P95/P99 延迟升高排查 Runbook

## 适用范围

适用于关键接口延迟超过 SLO 的场景，重点关注长尾和级联超时。

## 排查顺序

1. 按接口、状态码、租户、版本和地域确认延迟分布，避免只看平均值。
2. 通过 trace 找出耗时占比最高的下游调用、锁等待、队列和数据库查询。
3. 检查 CPU throttling、GC、连接池、线程/协程、队列长度和网络重传。
4. 对比发布/配置变更与流量突增，确认是否存在容量拐点。
5. 检查超时预算是否层层递减，避免重试放大流量。

示例 PromQL：`histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le,route))`。

## 处置

可按审批降低非核心流量、启用缓存或降级；修复慢查询、锁竞争和不合理重试。不要简单把客户端/服务端 timeout 无限调大。

## 验收

P95/P99、超时率、吞吐和资源使用恢复，且无错误率反弹；至少覆盖一个高峰窗口。

## 证据

分位数曲线、trace 摘要、依赖耗时、资源/队列指标、变更记录、重试量和降级结果。
