# 发布后故障与安全回滚 Runbook

## 适用范围

适用于发布后错误率、延迟、资源或数据一致性异常，需要回滚或暂停放量。

## 排查顺序

1. 确认发布批次、版本、灰度比例和异常开始时间。
2. 对比新旧版本的错误率、延迟、工具调用、数据库和依赖指标。
3. 检查迁移、配置、特性开关和兼容性；确认是否存在不可逆 schema 变更。
4. 评估回滚对消息、缓存、任务和数据格式的影响。
5. 记录审批人、回滚目标和验证标准。

## 处置

优先停止继续放量并关闭已验证的特性开关；具备兼容性和审批后执行回滚。涉及数据迁移时采用前向修复或兼容版本，不直接覆盖生产数据。

## 验证与升级

回滚后用小流量验证关键路径、错误率、P95、任务完成率和数据一致性，再逐步恢复。无法确认数据安全或影响支付/订单时升级。

## 证据

版本与变更单、灰度范围、指标对比、迁移状态、回滚审计、验证请求摘要和恢复时间线。
