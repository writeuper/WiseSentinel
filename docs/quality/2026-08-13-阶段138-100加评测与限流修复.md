## 根因与修复

原 API 对 `42901 请求过于频繁` 没有返回 `Retry-After`，评测客户端只能使用固定指数退避，在 60 秒滑动窗口内重复失败。现已：

1. 对 `42901` 返回 `Retry-After: 60`；
2. 评测客户端解析该头，并采用 `max(指数退避, Retry-After)`；
3. 增加中间件和评测客户端回归测试。

真实 HTTP 验证：第 31 次 Ops 请求收到 `429`，响应头为 `Retry-After: 60`。

## 企业级结论

当前 100+ 评测结果应同时报告业务质量和基础设施可用性，不能把限流样本直接算作 Agent 推理失败。后续生产评测应按 60 秒窗口分批、使用该重试提示，并单独统计限流率、准入拒绝率和模型超时率。
