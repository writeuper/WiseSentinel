# 阶段 130：RAG 库存故障注入与恢复验证

## 目标

验证新增的 RAG 库存错误分层指标能够在真实 Milvus 故障注入中准确递增，并确认物理库存统计失败不会污染逻辑库存、RAG 检索或 Chat 业务链路。

## 故障注入结果

1. 记录 Milvus 健康状态后执行受控 `docker kill --signal=KILL milvus-standalone`；
2. 请求 `/metrics` 触发库存刷新：
   - `ws_rag_inventory_refresh_errors_total{stage="physical"}` 从 1 增至 2；
   - 逻辑库存 gauge 保持可读，没有把物理失败伪装成逻辑库存失败；
3. `/health/ready` 返回 HTTP 503，`milvus=down`；
4. `docker start milvus-standalone` 后，readiness 自动恢复为 `ready=true`；
5. `ws_milvus_reconnects_total{outcome="failure"}` 从 4 增至 5，表示 wrapper 重连尝试失败次数；
6. 恢复后指标重新可读，物理向量仍为 198。

## 业务回归

- RAG-001：1/1 通过；工具命中 1/1；关键词 4/4；端到端 10.467 秒；
- Chat 4 请求/并发 2：4/4 成功；P50 6656 ms；P95 10701 ms；
- session cleanup：4/4；admission rejection：0；
- 恢复后没有发现 RAG 或 Chat 功能回归。

## 当前集成指标

- 成功/完成 Trace：1597；终态失败：97；Finished：1694；
- 成功 Agent 平均耗时：7415.64 ms；全部终态平均：7537.18 ms；
- Chat 全部平均：12680.45 ms；Ops 全部平均：3137.51 ms；
- 工具成功率：2339/2538 = 92.16%；
- 当前进程 RAG 样本：1，均值 604.216 ms，P95 为 750 ms Histogram 桶上界；样本不足，不作为稳定基线；
- 逻辑库存：24 active documents、78 published chunks、11 legacy documents；
- 物理向量：198；不等同逻辑 Chunk 数量；
- 没有真实生产用户或生产流量证据，以上为本地/集成环境。

## 结论与剩余风险

指标分层和故障恢复链路已得到真实证据：Milvus 物理统计失败被标记为 `physical`，逻辑库存和业务请求仍保持独立；恢复后平台无需重启即可继续服务。生产仍需使用 Prometheus 持久化抓取跨进程聚合，并分别监控 logical/physical refresh error、Milvus health、SDK reconnect 和 RAG error rate。
