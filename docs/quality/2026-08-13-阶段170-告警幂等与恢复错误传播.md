# 阶段 170：告警幂等与恢复错误传播

## 发现

Alertmanager Webhook 处理依赖事件表实现幂等和恢复关联。原实现对重复事件查询、resolved 事件查询与更新、事件创建冲突后的重查、以及任务 ID 绑定更新部分忽略数据库错误，可能把“无法确认状态”误报成成功响应，造成重复任务、恢复状态丢失或 Trace 关联断裂。

## 修复

- 重复事件 `Get`、创建冲突后的重查、resolved `GetByIncident` 和 `MarkResolved` 失败时返回统一内部错误。
- `UpdateTaskID` 失败时不再返回成功 Webhook 响应。
- 保留原有租户隔离、事件唯一键幂等、失败清理和异步任务绑定逻辑。

## 影响与剩余风险

数据库不可用时，Webhook 会明确进入错误路径，由调用方或 Alertmanager 重试，而不会生成无法追踪的假成功。失败清理仍是 best-effort；若清理本身失败，既有 AlertEventReaper 会按租户、事件和任务存在性继续回收孤儿预约。
