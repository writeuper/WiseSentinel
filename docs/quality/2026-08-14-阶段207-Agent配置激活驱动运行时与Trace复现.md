# 阶段 207：Agent 配置激活驱动运行时与 Trace 复现

## 面试缺口

平台原先可以在管理端切换 `ws_agent_config.is_active`，但 Chat/Ops 运行链路没有读取活动版本，导致“配置激活成功”不能证明 Agent 行为已经变化；异步 Ops 任务还可能在提交后被新版本覆盖，无法复现历史结果。

## 实现范围

- 新增租户隔离的 `AgentConfigRepo`，读取活动版本或指定历史版本并解析 `system_prompt`、`max_iterations`、工具元数据；非法迭代上限（小于 0 或大于 100）拒绝进入运行时；
- Chat 每次请求读取活动配置，使用配置 Prompt，并将最大步数限制在内置安全上限 `25` 以内；
- Ops 在任务提交时冻结活动配置版本，写入 `ws_ops_task.config_version`；Worker 执行时按持久化版本读取，不受后续激活影响；
- Chat/Ops Trace 写入 `ws_agent_trace.config_version`，Portal Trace API 可返回该版本；
- 未配置活动版本时保持原有内置 Prompt/步数默认值；历史任务没有版本时兼容内置默认行为；
- 配置中的工具列表本阶段仍作为元数据解析，未绕过 Tool Gateway 的 allowlist/schema/risk 校验。

## 剩余风险

当前仍不是完整 ConfigOps：尚无配置创建/Schema 预检 API、灰度比例、双人审批、运行时缓存失效广播和按配置版本的质量对比看板。下一阶段应补充激活前校验、回滚/灰度审计，并将配置版本纳入评测基线和发布门禁。
