# 阶段 48：遥测内容最小化与安全投影

日期：2026-08-11

## 背景与根因

真实 HTTP 评测发现，RAG 文档正文、工具输入/输出、模型输出和上游错误曾可沿 Trace、工具调用记录、Ops 任务的 `result/detail_json`、日志或 SSE 错误路径进入运营平面。已有的凭据正则脱敏只能处理 token、DSN 等已知模式，不能保证自由文本不泄露。

另一个真实负向用例表明：不存在的 Chat `session_id` 被数据库的 `sql.ErrNoRows` 映射成 500，并将 SQL 诊断带到 API 响应。

## 架构决策

- 执行/模型上下文在受控内存路径保留原值；普通 telemetry 不是 evidence vault。
- `redact.TelemetryProjection` 对任意自由文本 fail-closed，只保留 `suppressed=true` 和字节数。
- Trace、ToolCallRecord、工具日志/Evidence、Ops 任务的 `result/detail_json/last_error` 都在最终持久化 sink 再投影一次；这避免上游遗漏时的旁路。
- SSE 和 HTTP 错误只输出稳定、可行动的用户消息及 trace ID；不回显 provider 或数据库原始错误。
- 如有原始取证需求，应另建 KMS 加密 evidence vault（目的绑定、RBAC、留存期、访问审计），不得复用 Trace/Ops 表。

## 实现

- 新增 `internal/pkg/redact.TelemetryProjection`。
- Agent Trace、ToolCallRecord、Tool Gateway、Eino Tool 日志、审批 payload 均使用安全投影。
- `OpsTaskRepo` 对终态结果、明细与错误做防御性投影，保持 `detail_json` 为合法 JSON。
- Chat stream 对 current-time、构建和 provider stream 失败输出稳定消息；日志不再格式化原始错误。
- `SessionRepo.Get` 把 `sql.ErrNoRows` 标准化为不存在，Chat 缺失会话返回 `40401` 而非 500。
- 静态敏感 sink 门禁认可 `TelemetryProjection`，同时继续拒绝原始输入、查询和错误直接写日志。

## 真实评测与并发模拟

评测命令：

```bash
python3 scripts/run_agent_eval.py --base-url http://127.0.0.1:8090/api/v1 ...
```

- 评测集：24 个可执行真实 HTTP 场景，24/24 通过（100%）。
- 路由准确率：100%。
- 必需工具调用：25/25 成功（100%，由持久化 Trace tool step 验证）。
- 关键词/受控结论命中：61/68（89.7%）；这是结论表达质量指标，不替代任务完成率。
- 端到端响应：P50 259ms，P95 19.20s。P95 受真实模型/RAG 场景影响，应继续按 Chat/Ops/RAG 和 provider 分桶治理。
- 并发：10 个已认证 Chat 时间查询 + 10 个 Ops 日志/指标诊断，同时 10 worker；20/20 成功，失败 0，P50 208.1ms、P95 272.1ms、最大 304.7ms、总墙钟 637.7ms。

首次并发探针的 10 个 500 是压测脚本传入占位 session ID 触发的负向路径；该发现促成上述 404 修复，正式复测使用服务端返回的真实 session ID。

## 剩余风险与后续门禁

- 当前为开发环境真实依赖与模型 API 验证，并非生产流量；不得将其外推为生产容量承诺。
- Ops `input_query` 为异步执行所需，仍在任务表保存；若该字段包含高敏感用户输入，需迁移到独立加密的执行上下文存储，并向 Ops 表仅保留引用/投影。
- 门户首屏 JS gzip 约 398KB，建议按 Ops、知识库和可观测页面分包。
- 在生产前补充：逐步增压、长稳压测、租户隔离混沌、模型 provider 限流/超时故障注入，以及基于真实标注反馈的评测集扩容和置信区间监控。
