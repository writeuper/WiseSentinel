# 阶段 23：Embedding 数值完整性

## 根因

阶段 21 已校验 index 与维度，阶段 22 已限制 body 大小，但向量元素本身没有有限数（finite number）不变量。`NaN` 和正负 `Inf` 进入向量库后可能破坏距离计算、排序稳定性、序列化或下游索引任务；仅依赖当前 JSON 解码器拒绝部分非标准字面量不是跨适配器、缓存和未来解码实现的可靠防线。

## 企业级方案

在供应商适配器边界完成向量的语义验证：所有维度满足后，逐元素拒绝 NaN/正无穷/负无穷。该防线与大小、索引和维度验证同层执行，返回稳定错误，避免部分结果写入。向量库、索引 Worker 与检索服务仍可保留独立校验作为防御纵深，但不应把不可信外部响应直接交给它们。

## 落地

- 新增 `validateEmbedding(index, embedding, dimensions)`，集中完成维度与有限数验证。
- `DashScopeEmbedder.Embed` 在每条向量写入输出切片前调用该验证。
- 新增回归用例覆盖 NaN、正无穷与负无穷，且先在缺少校验函数时验证用例失败，再加入最小实现。
- 有限的、维度正确的正常 embedding 保持原有行为；阶段 21 的乱序映射和阶段 22 的字节预算测试持续覆盖。

## 回归证据

```text
go test ./internal/rag/embedder
```

通过。随后执行的全仓离线门禁也通过，覆盖 Go 短测试、Portal TypeScript 编译与敏感 sink 静态检查。

## 遗留项

- HTTP JSON 路径中标准 `encoding/json` 会在多数非有限字面量前报错；本测试直接验证语义校验函数，以保证未来适配器或解码策略变更仍受契约约束。
- 仍需在真实 Milvus 集成环境验证非法向量导致 Index Task 失败且无部分向量残留。
- 应为 embedding 请求数、总维度/元素数、模型版本和 generation fencing 建立端到端的配额与一致性测试。
