# 阶段 84：并发报告准入拒绝归因

日期：2026-08-11

## 问题与根因

并发 Chat 工件此前只有模型调用与时延增量。发生 `50304` 时，报告无法证明这是本地 admission budget 的预期拒绝，还是网关、供应商或响应解析问题；容量测试的失败归因不完整。

## 落地

`run_concurrent_chat_load.py` 现在从 Prometheus 仅聚合受控计数：

```text
model_metrics_delta.admission_rejections
```

不保留 provider 标签、模型名、tenant、提示词或错误正文。对应脚本单测覆盖指标解析和增量计算。

## 真实回归

5 请求 / 5 并发同步 Chat：

| 指标 | 结果 |
| --- | ---: |
| success | 3 |
| `api_50304` | 2 |
| cleanup verified | 5/5 |
| admission rejections delta | 2 |
| P50 / P95 | 8.709s / 13.593s |

HTTP 过载类别与模型 admission rejection 增量一致，证明该场景是预期容量保护，而不是隐藏的模型/网络错误。

## 使用边界

拒绝数不等于用户失败数：一个业务请求可能重试，或一个 Agent 任务包含多次模型调用。企业仪表盘应同时按请求、模型调用、tenant cohort 和时间窗展示 success、50304、rejection rate、in-flight 与端到端时延。
