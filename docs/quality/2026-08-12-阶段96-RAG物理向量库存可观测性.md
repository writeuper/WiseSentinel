# 阶段 96：RAG 物理向量库存可观测性

日期：2026-08-12

## 问题

阶段 95 已能统计 active logical documents/chunks，但无法量化 Milvus collection 实际占用。将逻辑 chunk 直接等同 physical vectors 会掩盖 legacy、superseded generation、待 GC 和 compaction 差异。

## 实现

- `MilvusClient.PhysicalVectorCount` 调用 SDK `GetCollectionStatistics`，严格解析 `row_count`。
- `/metrics` scrape 与 logical inventory 同一受控刷新路径更新无标签 `ws_rag_physical_vectors`。
- Milvus 无连接、无 `row_count` 或数值非法时只增加 `ws_rag_inventory_refresh_errors_total`，保留上次值；不输出零或将 logical chunks 冒充 physical rows。

`ws_rag_physical_vectors` 的口径是 **配置 collection 的全部物理行，跨所有 tenant**。它可能包含 legacy、已替代 generation、已删除 document 尚待 GC 的向量，不能用作 tenant 容量、权限范围或 Recall 分母。

## 验证

- 单元：正常 `row_count=42` 被接受；缺失、负数和非数字均被拒绝。
- observability/race 门禁通过，指标无标签。
- 重启后真实指标快照：`ws_rag_physical_vectors 130`；同时 logical active published chunks 为 10。

该 130/10 差异是生命周期盘点信号，不是检索准确率或错误。环境是开发/集成环境，不能外推为生产向量规模。

## 后续

生产应增加按 collection 生命周期、GC backlog、embedding version、tenant visibility 的受控离线盘点，并结合冻结评估集的 Recall@K、MRR、nDCG、citation 到达率与越权泄漏数。Prometheus 不应附加 tenant/doc/source/vector id 标签。
