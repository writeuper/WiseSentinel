# 阶段 45：深度边界、脱敏持久化与评测负向用例

## 本轮风险矩阵

| 域 | 边界/失败模式 | 自动化断言 | 结果 |
| --- | --- | --- | --- |
| 请求成本 | 超长会话标题、Chat 问题、Ops 查询、审批/反馈评论造成内存、模型上下文或持久化放大 | 分别限制 256 / 12000 / 8000 / 2000 Unicode rune；超限在依赖调用前返回 400 | 通过 |
| 国际化边界 | UTF-8 多字节文本被按字节错误截断或绕过限制 | 三/四个中文字符的精确 rune 边界 | 通过 |
| Trace | 用户自定义 Trace ID 进入日志、审计与持久化关联，可能造成高基数、日志污染或超长值放大 | 仅接受 128 字符以内的字母、数字、`-`、`_`、`.`；其余重新生成平台 ID | 通过 |
| 审批审计 | 审批意见中粘贴 Token 后原样进入 `ws_approval.comment` | 真实 MySQL 写入 canary；原文明文为 0，保留 `<redacted:authorization>` | 通过 |
| Agent 负向行为 | 信息不足时 Agent 自行扩大排障工具调用，产生无效成本或越权证据 | `BAD-001` 禁止 Prometheus、日志、部署、trace 等工具；仍检查澄清关键词 | 数据集契约通过，待在线执行 |

## 实现与门禁

- 新增 `make test-boundaries`，覆盖 Handler、Middleware、脱敏库与工具网关。
- 对平台生成的 32 位 Trace ID 和兼容上游的安全格式保持兼容；不向客户端返回“非法 Trace ID”细节，直接替换为平台生成值。
- 对审批意见在 repository 落库边界执行 `redact.Summary`，而不是依赖调用者记得处理；当前业务请求仍可在内存中使用原始输入。
- Agent HTTP 评测集中的 `BAD-001` 从“必须调用工具”的错误预期改为显式 forbidden-tools，避免将不必要的探测当成功。

## 仍需补齐的深度验证

1. **在线 HTTP 契约**：认证、RBAC、同租户跨用户对象读取、上传 MIME/大小、分页上限、SSE 断连、WebHook 重放与时钟边界；应在隔离进程中以真实路由完成黑盒测试。
2. **Agent 评测集分层**：将现有 24 条拆成冻结冒烟集与人工复核扩展集；补充提示注入、缺失/冲突证据、工具超时、429、模型空输出、RAG 空命中/越权密级、审批过期和 Trace 缺失。LLM 场景采用属性断言与版本化人工判定，不能以整段文本匹配。
3. **负载阶梯**：在专用租户按 1/10/50/100 并发运行 Chat、Ops、RAG，记录成功率、P50/P95/P99、工具错误率、429、Trace 完整率、GC/Index backlog 和 MySQL/Milvus 资源；设定 SLO 后才可判断容量。
4. **故障注入**：模型、Milvus、Redis、Prometheus/MCP 分别注入超时/5xx/限流/部分响应，验证 context deadline、数据库围栏、重试上限、降级提示与 canary 零泄露。
