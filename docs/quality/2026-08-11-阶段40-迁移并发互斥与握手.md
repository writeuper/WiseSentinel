# 阶段 40：迁移并发互斥与握手

## 问题与影响

阶段 39 的摘要账本可发现同名迁移被篡改，但两个独立部署 runner 同时读取“尚未登记”的 migration 时仍可能并行执行 DDL，再竞争插入账本。现有 migration 大多幂等，不能把这一偶然特性视为部署互斥保证。

影响是升级期间的 schema 竞争、不可预测的 DDL 等待和审计记录竞争；对于 Agent 平台的租户、审批、RAG 任务状态等持久化边界，这属于发布阻断风险。

## 企业级方案与取舍

1. 只由 CI/CD 编排保证单 runner：应作为生产部署流程约束，但本地/集成的 Compose job 仍需要自身保护。
2. Redis 分布式锁：Redis 不是本项目迁移持久化正确性边界，且 Redis 故障/过期会放大升级风险，未采用。
3. MySQL advisory lock（`GET_LOCK`）持有整个 migration 过程：锁与 schema 同属同一权威数据库，连接断开自动释放；采用。
4. 普通账本行或进程文件锁：仅能提供辅助可见性，不能代替跨 runner 的数据库互斥；未作为正确性边界。

## 设计不变量

- 同一 MySQL 实例内，任意时刻仅一个 `wisesentinel_schema_migration` holder 可执行 migration。
- 未取得锁的 runner 在配置的等待期后以非零状态失败，因此 `platform` 的 `service_completed_successfully` 依赖不会放行。
- 锁 holder 进程或数据库连接异常结束时，MySQL 自动释放 advisory lock；后续 runner 可以继续。
- `ws_schema_migration_lock` 只保存当前 holder 的非敏感标记与时间，用于跨连接就绪握手和诊断；它不替代 advisory lock，也不承载迁移正确性。

## 实现与修复

- 新增 `manifest/docker/migrate.sh`，把 Compose 内联脚本变为可语法检查、可测试的迁移程序。
- 程序创建账本和锁标记表，启动一个长连接取得 `GET_LOCK`；成功后写入带唯一 token 的标记行，主流程轮询该标记才开始执行 SQL。
- 每个 migration 前检查 holder 进程仍存活；退出路径终止 holder 客户端，使 MySQL 释放 session lock。
- `manifest/docker/docker-compose.yml` 将 migration service 挂载并执行该脚本。
- `scripts/test_migration_ledger.sh` 增加并发回归：一个 runner 显式持锁，第二个 runner 使用零等待，必须得到 `migration lock unavailable after 0s`。

首版长连接实现尝试从 MySQL client 的标准输出读取 `GET_LOCK` 结果。client 会在后续 `SLEEP` 语句完成前缓冲结果，造成 migration job 启动卡住。最终使用数据库标记表作跨连接握手，保留 advisory lock 为唯一互斥依据，消除了缓冲依赖。

## 验证证据

```bash
sh -n manifest/docker/migrate.sh
bash -n scripts/test_migration_ledger.sh
docker compose -f manifest/docker/docker-compose.yml config
make test-migration-ledger
make verify
git diff --check
```

结果：

- 正常 job 获得锁后，五条既有 migration 均以已验证摘要跳过。
- 并发回归确认等待期为 `0` 的第二个 job 被明确拒绝；持锁 job 结束后锁可释放。
- 原有首次登记、重复跳过、账本计数与篡改摘要拒绝回归继续通过。
- `make verify` 通过 Go 短测试、Portal TypeScript 类型检查和敏感 sink 静态门禁。

## 角色协作与后续

- Agent 架构：将迁移互斥绑定到 MySQL 权威状态，定义发布阻断与故障释放语义。
- Golang/平台后端：实现可重复的迁移 runner、advisory lock 与安全诊断标记。
- 自动化测试：将真实 Compose 并发拒绝加入可重复回归，而非仅做设计推断。
- 前端：本阶段无 API 或 Portal 交互变更；仍执行跨栈类型回归。

生产环境仍应由部署系统提供单 runner、受管 secret、最小权限 migration account、超时与发布审计；该 Compose 实现不替代这些控制。新增 migration 后必须运行 `make test-migration-ledger` 并保持历史 SQL 不可变。
