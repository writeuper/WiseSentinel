# 阶段 17：Redis 限流集成回归

## 背景

阶段 15 修复了同毫秒 ZSET member 覆盖，但纯单元测试无法证明 Redis Lua 的实际执行、成员计数和拒绝阈值。限流是 Agent 成本与资源保护的关键控制，必须在真实 Redis 上回归。

## 落地

- 将生产 `slidingWindowScript` 提升为包级常量，生产中间件与集成测试使用完全相同的 Lua 工件。
- 新增 `ratelimit_integration_test.go`（`integration` build tag）。
- 新增 `make test-rate-limit-integration`，要求 `OPS_TEST_REDIS_ADDR`。

## 验收场景

在同一毫秒、窗口上限为 2 的情况下：

1. 第一次 Eval 返回允许；
2. 第二次 Eval 返回允许；
3. 第三次 Eval 返回限流；
4. Redis `ZCARD` 必须为 2，证明两次允许请求未因相同毫秒而覆盖。

## 回归证据

```text
OPS_TEST_REDIS_ADDR=127.0.0.1:6379 make test-rate-limit-integration
make verify
```

均通过。

## 遗留项

- 仍需 HTTP 级并发测试，覆盖 middleware 的 tenant/user key、429 响应与 Redis 故障 50302。
- 真实生产 Redis 集群需要覆盖 failover、脚本缓存丢失、时钟偏差及跨节点容量测试。
- 该集成测试仅创建精确的 `ws:test:ratelimit:*` key，并在测试结束清理。
