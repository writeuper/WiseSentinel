# 阶段 75：SSE 断连取消与会话历史回归

日期：2026-08-11

## 验证目标

阶段 74 将 Portal 接入真实 SSE 后，需要验证最关键的负向不变量：用户在收到部分回答后主动断连，服务端不得把不完整的 user/assistant 对话写入后续上下文。否则下一次请求会把未经用户确认的半截内容当作会话历史。

## 场景与结果

真实 HTTP 回归使用真实模型依赖执行以下流程：

1. 创建精确测试 session；
2. POST `/chat/stream`；
3. 收到第一个 `message` data frame 后立即关闭客户端响应流；
4. 等待服务端取消传播；
5. GET 该 session 的 messages；
6. 精确 DELETE 测试 session。

结果：首个分片已收到，取消后的持久化消息数为 **0**。测试 session 已删除。

## 结论

现有后端逻辑正确检测 `ctx.Err()`，不会把断连/失败流的部分结果写入 Memory；Portal 的 AbortSignal 传播在真实 HTTP 链路上满足该不变量。本次未发现缺陷，因此没有为制造“修复”而修改业务代码。

## 剩余范围

该验证覆盖客户端主动断连。仍需在部署前验证反向代理 idle timeout、网络中断、浏览器页面关闭和多副本下取消传播；这些场景需要接近生产的代理/负载均衡环境。
