# 阶段203：评测证据来源与新鲜度门禁

## 面试缺口

评测、质量聚合和发布门禁虽然已经有结构校验，但如果 artifact 来自不同数据集、不同代码提交或过期时间窗，仍可能把旧结果误归因于当前版本。企业级发布需要同时校验来源一致性和证据新鲜度。

## 实现

评测覆盖报告现在包含：

- `dataset_sha256`
- `generated_at`

Agent Eval 也在 `evaluation_metadata` 中记录 `dataset_sha256`、`git_commit` 和 `generated_at`。

发布门禁新增可选参数：

```bash
--require-provenance
--max-artifact-age-hours 24
```

启用后会校验：

- coverage/evaluation 的数据集 SHA-256 一致；
- coverage/evaluation/quality 都有时间戳；
- evaluation 有代码提交指纹；
- 所有 artifact 未超过允许时效，且不来自未来时间；
- 缺失、非法、数据集不一致或过期时 fail-closed。

## 当前事实

默认本地门禁仍不强制 provenance，兼容历史 artifact；生产发布建议显式开启 `--require-provenance --max-artifact-age-hours 24`。当前已有 130 Case 的 coverage SHA-256 和生成时间，真实 Agent Eval summary 尚未形成，因此不能宣称完整 provenance 门禁已通过。

## 验证

- 覆盖来源完整且数据集一致的 ready 场景；
- 覆盖 SHA-256 不一致和过期 artifact 的阻断；
- 覆盖旧格式 artifact 在未开启强门禁时保持兼容；
- 不读取或输出模型原文、Prompt、租户 ID或密钥。
