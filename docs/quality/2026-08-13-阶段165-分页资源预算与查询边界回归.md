# 阶段 165：分页资源预算与查询边界回归

## 发现

多个列表仓储只处理 `size <= 0`，没有限制正数超大页大小。内部调用或恶意请求可通过 `size=1000000` 放大数据库扫描、响应内存和 Portal 渲染压力。Vector GC 列表已有单独上限，但会话、文档、故障知识、审批和 Ops 任务列表缺少统一约束。

## 修复

新增仓储层统一 `normalizePageBounds`：

- 默认页大小：20
- 最大页大小：100
- `page <= 0` 归一化为 1
- `size <= 0` 或 `size > 100` 归一化为 20

已应用于 Session、Document、FaultKnowledge、Approval、OpsTask 和 VectorGC 列表查询。约束位于仓储层，不能被 HTTP、Worker 或内部调用绕过。

## 验证

- 新增边界矩阵测试，覆盖负数、零、100 和 101。
- `go test ./...`：通过。
- `go vet ./...`：通过。
- Repository/Handler race 测试：通过。
- Python 自动化测试 50 项：通过。
- 敏感信息静态检查：通过。

## 影响

该修复降低了列表接口的数据库和响应资源放大风险，不改变分页默认行为和既有租户过滤、对象级授权语义。
