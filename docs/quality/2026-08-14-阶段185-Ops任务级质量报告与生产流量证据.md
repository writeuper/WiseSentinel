# 阶段185：Ops 任务级质量报告与生产流量证据

## 问题

原质量报告主要以 `ws_agent_trace` 统计 Agent 完成/失败和延迟，但面试指标中的“任务完成率、失败率、平均响应时间”还需要直接对应 durable `ws_ops_task` 状态机。否则 Trace 与用户可见 Ops 任务可能因早期失败、重试、超时或审批状态产生口径差异。

## 实现

- `scripts/report_agent_quality_metrics.py` 新增 `aggregate_ops_tasks`，按受控状态聚合：
  - 总任务数、终态任务数、在途任务数；
  - success 数、failed/timeout 数；
  - 完成率、失败率、平均端到端耗时；
  - 全量和最近 24 小时窗口。
- SQL 只取状态、计数和耗时求和，不读取任务 ID、输入问题、结果正文、租户或工具参数。
- 未知状态归入 `other`，不会把数据库中的任意字符串变成报告维度。
- 报告新增 `traffic_evidence.status=not_claimed`，明确当前数据来自应用持久化聚合和 Prometheus，未接入经过证明的真实生产用户/流量馈送。

## 口径

- 完成率 = `success / finished`；失败率 = `(failed + timeout) / finished`。
- `pending/running/retrying` 计入在途，不进入完成/失败分母。
- `awaiting_approval` 保留为非终态，不能被误算成成功或失败。
- 没有终态样本时所有比例和平均耗时为 `N/A`，但在途数量仍可报告。

## 验证

- 测试覆盖 success、failed、timeout、running、retrying、未知状态混合输入。
- 测试覆盖只有在途任务时的 N/A 口径。
- 既有 Trace、工具、RAG、模型和索引任务聚合测试继续保留。

## 当前限制

该报告仍是本地/集成环境的运行态快照，不能证明真实生产用户数量、DAU、业务采纳率或事故恢复效果。生产化需要将匿名租户 cohort、业务成功事件、人工升级/反馈和保留期限纳入受控数据管道，并对外部报表做权限和脱敏投影。
