# 阶段201：Agent 分桶完成率与长尾指标

## 面试缺口

全局平均耗时和全局成功率会掩盖 Chat、Ops、SSE 或其他 Agent 类型之间的差异。企业级平台至少需要按 Agent 类型区分业务终态完成率、失败率、样本量和 P95/P99，并将 `abandoned` 恢复终态与业务失败分开。

## 实现

`scripts/report_agent_quality_metrics.py` 新增 `agent_outcome_latency` 聚合：

- 按 `agent_type` 统计 Trace 样本；
- `success/completed` 计入业务成功；
- 其他非 `abandoned` 终态计入业务失败；
- `abandoned` 单独统计，不污染业务完成率；
- 每个 Agent cohort 输出业务终态样本、完成率、失败率、P50/P95/P99；
- 未形成业务终态样本时输出 `N/A`，不把空样本当成 0% 或 0ms。

## 当前本地事实

当前本地数据库的分桶结果：

- Chat：1069 条 Trace，平均耗时约 12339 ms；
- Ops：1236 条 Trace，平均耗时约 2342 ms；
- 全局业务终态平均耗时约 7033 ms，P95/P99 约 29011/40723 ms。

上述数据来自本地开发/评测持久化 Trace，不是生产 SLO，也未经过真实用户 cohort 或业务结果 Attestation 证明。

## 验证

- 覆盖成功、失败、abandoned 混合 cohort；
- 覆盖仅有 abandoned 样本的 `N/A` 语义；
- 保持原有全局 Trace、工具、RAG、模型和 SLO 聚合测试。
