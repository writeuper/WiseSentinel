# 阶段 115：RAG 可审计检索与全链路回归

## 本阶段发现与修复

### 1. Milvus 依赖中断

真实 RAG 回归首先发现 `milvus-standalone` 容器已停止，平台自身 readiness 仍然可用，但 RAG 请求连接 `127.0.0.1:19530` 被拒绝，20 条 RAG Case 均失败。保留数据卷并只执行 `docker compose -f manifest/docker/docker-compose.yml up -d milvus` 恢复服务；Milvus 健康后 `/health/ready` 全部组件恢复 `up`。

### 2. Runbook 检索证据链

显式内部 Runbook 请求以前可能由预加载 RAG 上下文直接回答，导致答案正确但没有持久化 `query_internal_docs` Tool Step。现已改为：

- 明确的 Runbook/内部文档请求同步调用 `query_internal_docs`；
- Runbook 查询 TopK 从 3 提升到 8，避免标题、适用范围和升级章节挤占排查/止血章节；
- 结果仍经过租户、密级和 Generation 过滤；
- Citation 从真实工具返回的检索文档生成，评测工具断言继续只认持久化 Trace Step。

### 3. 评测断言质量

评测生成器的部分 `expected_knowledge` 使用了“Pod OOMKilled”“服务 5xx 错误率升高”等简称，而实际受控 Runbook 标题为“Kubernetes OOMKilled”“HTTP 5xx 错误率升高”等，造成答案已完整命中关键词却被误判 `knowledge_miss`。已将断言对齐到受控文档标题，不放宽匹配规则。
