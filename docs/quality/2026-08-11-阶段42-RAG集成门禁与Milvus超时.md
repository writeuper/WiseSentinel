# 阶段 42：RAG 集成门禁与 Milvus 超时

## 问题根因

`make test-integration` 原本没有要求 MySQL DSN。未配置时，RAG 的五个集成用例以 `t.Skip` 跳过，Make 仍以成功状态退出，形成“集成测试通过”的假阳性。

配置真实 MySQL 与 Milvus 后，首个 RAG 写入-检索闭环停在 Milvus `Flush`。goroutine 证据显示 SDK 在 `RateLimit` 响应上重试，而调用上下文没有 deadline；Index Worker 可能无限占有 DB lease，无法进入既有重试、退避和死信策略。

## 企业级方案与实现

- 集成依赖缺失必须是门禁失败，不能静默跳过。
- 外部向量库的 Query、Delete、Upsert 与 Flush 统一使用 15 秒 operation deadline；超时由 durable Worker 状态机接管，而不是在单次 RPC 内无限重试。
- `make test-integration` 显式要求 `OPS_TEST_MYSQL_DSN`，并增加 `RAG_TEST_TIMEOUT`（默认 `3m`）防止 CI 执行器永久阻塞。
- 无法连接 Milvus 的集成测试改为失败；删除和索引发布仍保持 Flush 的持久化语义，不以取消 Flush 或吞错换取通过。

## 回归证据

```bash
make test-integration # 未配置 DSN，预期 exit 2
OPS_TEST_MYSQL_DSN=... go test ./internal/rag -tags=integration \
  -run '^TestRAGIndexRetrieveLoop$' -v -timeout 45s
make verify
git diff --check
```

- 缺少 DSN 时目标明确以 exit 2 失败，五个测试不再被静默跳过。
- 修复后真实 `TestRAGIndexRetrieveLoop` 在约 12 秒内通过，覆盖 MySQL 文档记录、Milvus 写入/Flush、检索和租户过滤链路。
- `make verify` 通过 Go 短测试、Portal TypeScript 类型检查和敏感 sink 静态门禁。

完整 RAG 套件在本地共享 Milvus 已累积大量测试删除段时仍可能长时间运行；已受 3 分钟总超时约束，本阶段不将其虚报为通过。后续应在 CI 专用 Milvus 数据库或集合运行，并建立段清理、速率和时延基线。

## 角色协作

- Agent 架构：定义外部向量库失败由 durable Worker 接管的边界。
- Golang 后端：落实 operation deadline 和带操作上下文的错误。
- 自动化测试：移除 Skip 假阳性，保存 timeout goroutine 证据并完成最小真实闭环回归。
- 前端：本阶段无 Portal 契约变更；继续纳入 TypeScript 门禁。
