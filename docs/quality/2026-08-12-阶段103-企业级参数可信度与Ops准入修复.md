# 阶段 103：企业级参数可信度与 Ops 准入修复

日期：2026-08-12

## 目标

为“工具数、故障覆盖、知识规模、评测规模、执行步数、任务完成率、RAG P95、Citation/工具命中率”建立可审计参数口径，同时修复 Ops 入口仅依赖模糊词黑名单的最小权限缺陷。

## 缺陷与根因

原 `NeedsOpsClarification` 只在命中“慢、卡、异常、帮忙”等词时拦截。仅给出服务名、仅要求“查一下日志”、或没有服务目标的“服务 down”可能进入 Plan-Execute 图，读取告警、指标、日志或部署数据。黑名单随着表达变体增加会持续漏判，不符合企业级最小权限原则。

## 推荐方案与落地

采用正向准入策略：

- 明确 Trace 引用可直接进入 Trace 日志路径；
- 明确“当前/哪些/列表”等全局告警盘点可进入告警只读路径；
- 其他诊断必须同时具备受控服务目标和诊断信号（告警、日志、指标、错误码、超时、Redis/MySQL、发布、限流、锁、失败等）；
- 目标或信号缺失时返回结构化澄清，不创建 Ops task、不调用工具。

新增负向 Case：`BAD-003`（仅服务名）、`BAD-004`（仅数据源）；将 `ALERT-002` 补为带明确服务目标的告警+日志场景，避免把全局模糊“down”误当成可操作查询。

## 回归证据

- `go test ./internal/domain ./internal/agent/ops ./internal/gateway/handler -count=1`：通过。
- `go test ./... -count=1`：已通过定向阶段并持续执行全量门禁；未因新增策略弱化断言。
- `python3 -m unittest` 在线脚本合同：18 条通过。
- `BAD-001/BAD-002` 历史在线澄清合同：通过，工具数为 0。
- 当前重启后的完整在线评测未纳入新鲜成功率：readiness 发现 MySQL/Redis/Milvus/etcd 异常，Ops 还出现 context canceled 和模型长尾；这批失败被保留为环境阻塞证据，不计入质量提升百分比。

## 参数可信度结论

详见 [Agent 平台参数与质量可信度报告](../Agent平台参数与质量可信度报告.md)。当前可以对外使用“10 个已配置工具、27 个冻结 Case、历史 25/25 工具命中基线、13/10/130 历史 RAG 库存快照”；不能把历史快照或单样本直接描述为当前生产规模、当前 RAG P95、平台级 Citation 有效率或生产任务完成率。

## 遗留风险

1. 当前基础设施 readiness 未恢复，27 Case 新鲜在线回归、平均 Trace 步数和 RAG P95 暂不可证实。
2. 服务目录仍是窄 allowlist；接入新服务必须同步更新目录、正向准入单测和负向评测，不能直接扩大关键词。
3. 生产质量仍需真实用户/影子流量、100+ 人工 RAG 标注集、分层置信区间和容量错误预算。
