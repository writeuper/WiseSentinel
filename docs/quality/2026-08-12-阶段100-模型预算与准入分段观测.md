## 根因与解决方案

### 流式路径绕过 profile 总预算

**问题**：同步 `Generate` 的 30 秒 profile timeout 覆盖重试和退避，但 `Stream` 使用固定五分钟 HTTP client timeout。供应商或网络悬挂时，一个 SSE 流可占用本地 admission slot 远超 profile 预算，造成成本、并发容量和用户等待失控。

**企业级方案**：将每个逻辑模型请求放在一个 parent deadline 中：握手、重试、首 token 和完整 body 都使用同一 context；释放并发 slot 必须在 stream reader 终止时发生。流式首块到达不代表完整请求成功，完整读取超时必须明确分类为 timeout。

**落地**：`OpenAIEinoModel.Stream` 使用 profile timeout 的 `streamCtx` 覆盖 HTTP 请求和 body 读取，移除独立 5 分钟 client timeout；所有握手失败都释放 slot/取消 context，完整 stream goroutine 完成时再释放。确定性测试模拟“先返回一个 chunk、随后阻塞”，验证最终 Recv 收到 profile deadline。

### 准入与执行耗时混淆

**问题**：`generate` 指标过去从调用入口开始计时，无法表达本地准入开销；将来若从 fail-fast 改为有界队列，排队时间会被误算为供应商执行长尾。

**落地**：

- `ws_model_admission_wait_seconds{provider,outcome}`：只记录本地 admission decision 时间，outcome 仅为 `accepted/rejected/canceled`。
- `ws_model_call_duration_seconds{provider,operation,outcome}` 的 Generate 时钟从取得 slot 后开始；拒绝仍以零执行时长计入 overloaded，明确其不属于供应商执行。
- 标签仍只有 provider class 和有界状态；没有模型部署名、credential、tenant、prompt、URL 或 trace。

当前实现没有排队队列，因此 accepted/rejected wait 都应接近零；它是“准入决策开销”，**不是排队时延**。只有未来引入有界、可取消、按租户公平的队列后，才能报告真正 queue latency。

## 真实验证

| 场景 | 结果 |
| --- | --- |
| API / RAG 状态 | `/health/ready=200`，完整依赖均 up |
| SSE 基本合同 | 通过，`success_done`；新增指标 accepted wait 约 1.7µs |
| 独立低并发 Chat | 请求 2、并发 2：2/2 成功，清理 2/2，admission rejection=0；P50 3.448s、P95 6.605s；模型执行累计 9.75s |
| 独立 SSE 容量保护 | 请求 4：3 `success_done`、1 `sse_50304_retry_2`；rejections=1，rejected decision wait 约 0.9µs |
| 流式 profile timeout | 确定性单测通过：首块后阻塞的 stream 在 40ms profile budget 到期时终止 |

容量场景的成功/拒绝比例会随请求同时到达与实际释放时机变化；其验收标准是“至少一个成功、至少一个结构化可重试 50304、无幽灵会话”，不是宣称固定成功率或生产吞吐量。

## SLO 与后续

本阶段仅提高观测和预算一致性，未凭单次开发环境样本宣布 SLO 达标。阶段 98/99 的端到端 P95（约 7–20 秒）仍需按 Chat/Ops、RAG、工具、模型 profile、区域和并发档位分桶。

生产化前应：

1. 与业务共同定义用户可见 SLO（例如成功响应/TTFT/完成时间）与错误预算，再在独占模型配额环境跑 2→5→10→目标容量阶梯。
2. 如需排队，设计有界队列、等待 deadline、取消、tenant 公平配额和全局 deployment budget；持久幂等与 Retry-After 语义必须随之验证。
3. 用仪表盘分开展示 admission accepted/rejected/canceled、execution timeout/upstream error、SSE 完成时间和 TTFT；禁止按 tenant/prompt/trace 建 Prometheus labels。
4. 对模型长尾补充供应商侧 request ID 的受控审计关联，而不是将上游正文落到 Trace/指标。
