# 阶段190：审批等待时延与工具治理指标

## 面试缺口

平台已有审批状态机、风险分级和审计记录，但质量报告此前只有工具调用成功率，无法回答高风险工具审批是否积压、审批决策率和人工等待时延是否影响 Agent 端到端体验。

## 实现

`scripts/report_agent_quality_metrics.py` 新增匿名审批聚合：

- 总审批数、已决策数、待处理数；
- `approved`、`rejected`、`expired` 和未知状态分布；
- 决策率；
- 决策等待平均值、P50、P95；
- 全量窗口和最近 24 小时窗口。

查询只返回状态和时间差，不读取 approval ID、task ID、approver、payload 或评论；没有已决策样本时延迟输出 `N/A`，不把空样本当成零延迟。

## 口径边界

- 审批决策时延定义为 `updated_at - created_at`，适用于终态记录；`pending` 不进入延迟分母。
- `approved` 表示审批状态已记录，不等价于下游副作用已成功执行；工具/VectorGC 执行结果仍需通过任务状态和审计证据确认。
- 该指标是人工审批等待信号，不是 Agent 任务完成率或业务成功率。

## 验收

- 覆盖 pending、approved、rejected、expired、未知状态、无决策样本和 P50/P95 聚合。
- 继续沿用质量报告的脱敏出口和低基数状态归一化规则。

工具治理补充口径：工具报告现在区分真正可用率（`success / dependency_attempts`）与依赖响应率（`(success + error) / dependency_attempts`），并分别统计 unavailable、timeout 和 rejected。`rejected` 是平台权限/风险治理决策，不计入上游依赖分母；没有调用样本时输出 `N/A`。
