# 阶段 125：终态指标聚合口径修复

## 发现

`report_agent_quality_metrics.py` 原先仅把 `failed/error/timeout/canceled` 计为失败。Trace 表的真正终态标记是 `finished_at IS NOT NULL`，如果未来增加新的终态（例如 `aborted`、`rejected` 或 `expired`），固定枚举会导致：

- `finished` 样本数包含该记录；
- 失败样本数和失败平均耗时却遗漏该记录；
- 全部终态平均耗时的分母与样本集合不一致。

这会直接影响 Agent 任务完成率、失败率和平均响应时间等企业级质量指标。

## 修复

成功集合保持 `success/completed`；所有 `finished_at IS NOT NULL` 且状态不属于成功集合的记录均计为终态失败。Chat/Ops 分组平均失败耗时采用相同口径。

新增测试检查报告 SQL 不再依赖旧失败状态枚举，并保留 Prometheus RAG 成功/错误分层测试。

## 验证

- 修复前新增口径测试失败；
- 修复后报告测试：3/3 通过；
- 当前数据库终态分布：success 1586、failed 96，未发现未知终态；
- 当前未完成 Trace：14 条，不进入 finished 或终态平均耗时；
- 修复后当前聚合数值保持不变，证明改动只修正未来状态扩展的口径风险。
