# 阶段 19：Go Race 并发回归

## 目标

对 Agent 编排、Worker、Redis 租约、MCP 客户端互斥和流式对话等并发路径执行 Go race detector。普通单元测试只验证功能结果，无法检测非确定性共享内存访问。

## 执行

```text
make test-race
go test ./internal/... -count=1 -short -race
make verify
```

所有命令以退出码 0 完成，未报告 data race。常规离线门禁也通过。

## 结论

本轮未发现可复现的内存数据竞争，因此未修改业务实现。该结果仅覆盖现有 short test 实际触发的并发路径，不表示生产负载下不存在时序、分布式锁或外部服务层面的并发问题。

## 后续门禁

- 对 Ops/Index Worker 添加可控时钟、并发任务与失租取消的 race/压力测试。
- 在真实 MySQL/Redis 环境组合 `-race` 执行租约集成测试。
- 对流式 Chat、MCP 并发调用和 Portal polling 增加持续压测与 goroutine 泄漏检查。
