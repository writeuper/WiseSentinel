# 阶段 120：Milvus 恢复与并发评测复验

## 本阶段目标

复核当前运行态依赖、恢复 RAG 基础设施后验证平台 readiness、同步/SSE/幂等/Trace 契约，并补充真实 HTTP 并发和 Ops 评测抽样，避免把依赖故障或历史聚合指标误判为 Agent 能力结论。

## 运行态问题与处理

- 初始 `/health/ready`：`ready=false`，唯一异常组件为 `milvus=down`；
- 通过既有 `manifest/docker/docker-compose.yml` 仅执行 `docker compose ... up -d milvus` 恢复 Milvus，未删除或重建任何共享数据卷；
- 恢复后 API readiness 全部组件 `up`，Milvus `:9091/healthz` 返回 `OK`；
- 该问题属于向量数据库依赖可用性故障，不能通过放宽应用层超时掩盖。

## 结论与剩余风险

1. Milvus 恢复后平台基础 readiness、RAG 依赖和关键在线契约均可用；本轮未发现新的可复现代码缺陷。
2. Chat 仍明显慢于 Ops，且并发 3 的 P95 约 13.6 秒；普通模型上游长尾仍是主要性能风险，不能直接宣称生产 SLA。
3. RAG 样本量已达到当前脚本的 30 条 provisional 门槛，但 P95 仍是桶上界，不是精确百分位；生产前应持续采样并按 confidence、outcome、租户和查询类型拆分。
4. 前端已有构建通过但存在约 798 KB 主 bundle 警告；代码分割仍是后续性能优化项。
