# 阶段184：评测基线差异与优化归因

## 面试缺口

平台已经能够输出单轮通过率、业务通过率、置信区间、延迟和 RAG 排序指标，但没有统一的“优化前/优化后”比较器。若两次运行使用了不同数据集、模型、Embedding 或环境，直接相减会把数据变化误认为代码优化收益。

## 实现

新增 `scripts/compare_agent_eval.py`：

- 校验 `dataset_sha256`、模型 profile、Embedding profile 和环境是否一致。
- provenance 不一致时默认返回 `incomparable`，不输出可误读的差异；显式使用 `--allow-incompatible` 才允许生成带警告的对比。
- 对通过率、路由/工具/Citation（含独立 Trace grounding）、RAG Recall/MRR/nDCG 和 P50/P95 计算绝对差、相对差及改善方向。
- 对总体/业务通过率附带 CI 是否重叠的描述性字段；不把 CI 重叠判断冒充统计显著性或因果证明。
- 只读取已脱敏的 summary JSON，不读取或输出模型原文、工具参数、租户 ID、Token 或密钥。
- 样本量和 verified RAG 样本量始终随差异报告输出。

示例：

```bash
python3 scripts/compare_agent_eval.py \
  --before artifacts/eval-before.json \
  --after artifacts/eval-after.json \
  --output artifacts/eval-diff.json
```

## 可信度口径

- 只有相同数据集 SHA、模型/Embedding profile 和环境才可作为默认可比结果。
- 延迟指标按“越低越好”，质量指标按“越高越好”标记 `improved`。
- Recall/MRR/nDCG 仍受 verified relevance 样本门禁约束；没有人工/专家复核标注时继续是 `N/A`。
- Citation grounding 只有两次运行都拥有独立 Trace 文档证据时才比较；任一运行不可验证则不把 `N/A` 当作 0%。
- 差异报告用于回归和发布决策，不代表生产用户效果；真实生产结论还需要按租户 cohort、流量窗口和业务成功事件复核。

## 测试证据

- 覆盖可比运行的质量/延迟方向差异和 CI 重叠。
- 覆盖数据集 provenance 不一致时 fail-closed。
- 覆盖显式允许不兼容比较时保留 mismatch 标记。
- 覆盖缺失、NaN 指标不会被当作零值。
