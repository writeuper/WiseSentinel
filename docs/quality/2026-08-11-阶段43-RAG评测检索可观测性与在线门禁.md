# 阶段 43：RAG 评测、检索可观测性与在线门禁

## 目标与口径

本阶段把“能检索”升级为可复现、可统计和可告警的质量结论。RAG 排序指标采用带标注查询集：

| 指标 | 口径 |
| --- | --- |
| Recall@K | 标注相关文档是否出现在前 K 条 |
| Precision@K | 前 K 条中标注相关文档占比 |
| MRR | 首个标注相关文档排名的倒数均值 |
| nDCG@K | 按排名折损后的相关性收益，单相关文档时理想值为 1 |
| 隔离正确性 | 跨租户泄漏数、密级越权命中数；两者必须为 0 |

Agent 在线评测指标采用可执行用例数、整体通过率、路由准确率、真实 Trace 工具成功率、关键词命中率、p50/p95 端到端时延和失败分类。工具断言只接受已持久化的 Trace tool step，不能由模型文本或响应中的伪造 tool_calls 通过。

## 发现与修复

1. 本地 `HashEmbedder` 原先将整段文本的 SHA-256 字节重复为向量，任何词项/短语重叠都几乎不保留。它并不适合做本地排序回归，首轮三条带标注查询的 Recall@1 为 33.3%、MRR 为 0.556。
2. 改为确定性的词项 feature hashing：英文按词，中文额外按相邻双字；不保存词典、查询或租户信息。它仅用于本地开发和测试，生产语义质量仍必须由实际嵌入模型的独立评测决定。
3. 每个 RAG 集成测试创建唯一 `it_<uuid>` Milvus collection，结束时只 Drop 自己创建的集合。避免共享 `biz` collection 的 tombstone/删除段累积干扰时延和准确率，也不触碰共享数据。
4. 新增 `ws_rag_retrievals_total{outcome,confidence}` 与 `ws_rag_retrieval_duration_seconds{outcome,confidence}`。标签仅是稳定的 `success/error` 和 `high/mid/low`，不含 tenant、query、doc_id、source 或错误正文；关联排障仍使用受控 Trace/audit。
5. 在线评测脚本增加聚合 JSON，记录整体/路由/工具/关键词/时延统计；脱敏后才写入 CSV。无用例、未执行用例或任一失败默认非零退出，`--allow-failures` 仅供诊断，不能用于 CI 门禁。

## 回归结果

在本机隔离 MySQL/Milvus 环境、`HashEmbedder`、TopK=3、三条单相关标注查询上，修复后：

| 指标 | 结果 |
| --- | ---: |
| Recall@1 | 100.0%（3/3） |
| Recall@3 | 100.0%（3/3） |
| Precision@3 | 33.3%（每条仅标注 1 个相关文档） |
| MRR | 1.000 |
| nDCG@3 | 1.000 |
| 跨租户泄漏 | 0（`TestTenantIsolation`） |
| 密级越权命中 | 0（`TestSecretLevelFilter`） |

执行证据：

```bash
OPS_TEST_MYSQL_DSN=... make rag-eval
OPS_TEST_MYSQL_DSN=... make test-integration
make verify
python3 -m py_compile scripts/run_agent_eval.py
```

上述命令均已通过；RAG 评测日志输出 `RAG_EVAL` 指标。完整集成回归还覆盖索引—检索、增量代际发布、租户/密级过滤和 legacy 精确删除。

在线 Agent HTTP 评测未在本阶段执行：本机没有运行中的平台 HTTP 服务（`127.0.0.1:8090` 拒绝连接），因此没有把历史 `agent_eval_results_round3.csv` 的 13/24 当作当前结果。部署到隔离集成环境后执行：

```bash
make agent-eval-smoke EVAL_BASE_URL=http://host:8090/api/v1 EVAL_API_KEY=... \
  EVAL_OUTPUT=/secure-artifacts/agent-eval.csv \
  EVAL_SUMMARY=/secure-artifacts/agent-eval-summary.json
```

该命令会在失败时失败；JSON 只含聚合指标，CSV 中诊断摘要会脱敏。

## 限制与下一阶段门禁

- 三条合成标注只能作为回归探针，不代表生产语料、真实 DashScope/其他嵌入模型，样本太小不能给出统计置信区间或对外宣称 100% 准确率。
- 上线前至少建设 100+ 人工复核、按租户/密级/文档版本分层的冻结评测集，固定嵌入模型版本、TopK 和时间窗口；按版本比较 Recall@1/3、MRR、nDCG、P95 与泄漏率。
- Prometheus 已有指标合约与告警配置，但本机未启动平台进程，未验证 scrape/告警触发；部署后用 `scripts/verify_prometheus_metrics.sh` 验证抓取，再基于检索 error rate 和 p95 增加 SLO 告警阈值。
- 在线 Agent 通过率必须按路由、工具、RAG、权限拒绝和审批场景分层报告；任何 `trace_unavailable`、`forbidden_tool_called` 或跨租户/脱敏 canary 失败均阻断发布。
