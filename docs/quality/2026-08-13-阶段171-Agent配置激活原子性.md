# 阶段 171：Agent 配置激活原子性

## 发现

Agent 配置激活原实现先停用旧版本，再尝试激活请求版本。请求版本不存在时会返回 `is_active=false`，但旧版本已被停用，造成租户无 active 配置；同时影响行数读取错误也未被传播。

## 修复

- 在事务内先校验目标 `agent_type + version` 存在。
- 只有目标存在时才停用旧版本并激活新版本。
- 传播 `RowsAffected()` 错误，并对空更新返回冲突错误。
- 增加 AgentType/Version 非空边界校验。

## 影响与剩余风险

配置激活从“两次独立更新”变为数据库事务内的原子指针切换，避免无 active 配置窗口。真实 MySQL 并发激活仍应使用独立租户运行集成测试，以验证数据库隔离级别和唯一约束与部署配置一致。
