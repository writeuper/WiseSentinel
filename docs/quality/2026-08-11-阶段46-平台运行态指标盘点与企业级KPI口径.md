## 企业级平台应如何回答这些问题

1. **评估集数量**：报告“冻结核心集 / 扩展集 / 红队集 / 人工复核集”四个规模及版本，而不只报总数。当前 24 条不足以量化模型质量；上线门槛建议至少 100+ 人工标注 RAG 样本、50+ 工具/权限/审批样本、独立红队安全集，并按租户、密级、服务、版本和语言分层。
2. **RAG 规模与质量**：同时报告 active docs、active chunks、向量 rows、deleted rows、GC backlog、embedding model/version、维度、TopK、时间窗。检索质量除 Recall@K、MRR、nDCG 外，必须报告跨租户泄漏=0、密级越权=0、无结果率、citation 有效率和 P95。
3. **工具成功率**：定义为 `success / (success + terminal_error + timeout + rejected)`，按工具、风险级别、租户层级、上游、错误类别和时间窗切分；同时报告工具选择准确率、未授权拒绝正确率、重试成功率、超时率和证据可用率。禁止将 L0 mock 成功率与真实 L1 上游成功率混合。
4. **任务完成率与时延**：任务“完成率”应区分终态率、成功率、失败率、超时率、取消率、重试耗尽率和死信率；时延拆为 queue/run/e2e 的 P50/P95/P99。Ops 8.12s 平均值不能替代百分位和端到端用户响应时间。
5. **优化对比**：只比较相同冻结数据集、相同模型/提示词/工具版本、相同 TopK 和相同时间窗的结果；记录样本量、置信区间、显著性和成本。当前 RAG 对比是有效的本地回归证据，不是生产模型效果结论。
6. **真实用户与生产流量**：当前没有证据表明存在真实业务用户或生产流量。生产上线前应在合法同意、最小化采集和脱敏前提下，以匿名化 tenant cohort 报告 DAU、会话数、任务数、采纳率、人工转接率、事故恢复时间、业务 KPI，并隔离测试/生产数据。

## 下一步仪表盘与 SLO

应建立按环境隔离的 dashboard：请求/任务/工具/RAG 四条链路通过 Trace ID 关联，Prometheus 仅使用低基数标签，详细证据走受控脱敏 Trace/Audit。建议先设置：RAG 或工具越权泄漏 0、Trace 完整率 >=99.9%、高风险拒绝正确率 100%、工具成功率和 RAG P95 按真实上游基线确定、队列/死信 backlog 为 0 或有明确错误预算。
