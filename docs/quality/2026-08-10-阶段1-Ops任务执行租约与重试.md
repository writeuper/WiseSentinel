# 阶段 1：Ops 任务执行租约与重试

- 日期：2026-08-10
- 状态：已完成代码、真实基础设施集成回归与离线门禁
- 协作角色：Agent 架构师、Golang 后端工程师、自动化测试工程师

## 1. 目标

将异步 Ops 任务从“Redis 锁 + 无条件更新”的最佳努力实现，收敛为具有明确所有权、可重试、可超时回收的持久化执行状态机。该能力是企业级 Agent 工具调用、故障分析和后续审批恢复的基础：任何陈旧执行器都不能覆盖新执行器的结果。

## 2. 问题、根因与风险

原实现存在以下缺陷：

1. Redis 锁写入固定值 `locked`，并用无条件 `DEL` 释放。锁 TTL 过期后，新 Worker 获得锁，旧 Worker 仍可能删除新锁。
2. `MarkRunning`、`MarkFinished`、`Retry` 仅按 `(tenant_id, task_id)` 更新；Redis 租约过期或 Worker 失联时，旧 Worker 可以覆盖新尝试的状态和结果。
3. Agent 与 Worker 都会无条件更新任务状态。Agent 已标记失败后，Worker 仍可能将任务改为 `retrying`，造成终态复活；重试耗尽时任务还会永久停留在 `retrying`。
4. 任务运行时间可达 30 分钟，旧锁 TTL 为 10 分钟且不续约；没有超时回收、退避计划或所有权屏障。

影响包括重复 Agent/工具副作用、跨尝试结果污染、无限重试、任务悬挂和不可审计的故障恢复。

## 3. 企业级方案与取舍

采用“数据库状态机 + fencing token + Redis lease”的组合模式：

- MySQL 是执行所有权的最终来源。每次 Claim 生成新的 `execution_token`，并以条件更新原子写入 `running`、`started_at`、`timeout_at`。
- 所有完成、失败、重试和超时更新均要求 `status=running AND execution_token=:token`。受影响行数为 0 表示所有权已失去，禁止继续提交结果。
- Redis 用于降低 Worker 间竞争；锁值使用同一 token，Lua 脚本只允许 owner 续约或释放，避免删除新 owner 的锁。
- 可重试失败采用有界指数退避；达到 `max_retry` 后原子转 `failed`。运行超时默认转 `timeout`，不自动重试，避免对潜在 L2/L3 工具产生重复副作用。

这是业界常见的 lease/fencing 设计。相比仅提高 Redis TTL 或仅使用悲观锁，它能在锁过期、进程暂停、网络抖动和重复投递时阻止陈旧执行器写入。

## 4. 落地实现

| 组件 | 变更 |
| --- | --- |
| Schema | `ws_ops_task` 新增 `execution_token`、`next_attempt_at` 和 runnable 索引；新增可重复部署的 SQL migration |
| Repository | 新增 `ClaimRunnable`、`FinishIfOwned`、`RetryOrFailIfOwned`、`ExpireTimedOut`；所有权通过 `RowsAffected` 判定 |
| Ops Agent | `ExecuteTask` 显式接收 token；同步路径也先 Claim；只有当前 owner 才能落结果或创建知识草稿 |
| Ops Worker | token 化 Redis 锁、compare-and-delete / compare-and-PEXPIRE Lua、锁续约、租约丢失时取消运行、定期超时回收 |
| 自动化测试 | 新增纯退避测试、MySQL CAS 集成测试、Redis 租约集成测试与 Makefile 门禁 |

现有环境已应用 `manifest/sql/migrations/20260810_ops_task_execution_lease.sql`，该迁移只新增列和索引，未删除或改写已有任务数据。
