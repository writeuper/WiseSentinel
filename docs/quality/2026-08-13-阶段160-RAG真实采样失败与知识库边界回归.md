# 阶段 160：RAG 真实采样失败与知识库边界回归

## 真实 RAG 验证

执行了 3 次隔离知识库闭环：上传文档、等待索引、Chat 开启 RAG、校验 Citation、删除文档。3 次均在索引阶段失败，错误均归因为 Milvus `Flush` `DeadlineExceeded`，没有伪造 RAG 成功率或 P95。

数据库中的 durable `ws_index_task` 记录确认失败状态与错误原因，Index Worker 将此类超时归入 retry/dead-letter 策略。当前 `/metrics` 的 RAG retrieval 样本仍为 0，因此 RAG P95 必须标记为 N/A；待 Milvus Flush 恢复后重新执行闭环才能产生有效样本。

## 修复

为知识库相关 Handler 统一增加 nil 请求防护：

- UploadDocument
- ListDocuments
- DeleteDocument
- ReindexDocument
- GetIndexTask
- ListFaultKnowledge
- ApproveFaultKnowledge
- RejectFaultKnowledge
- FeedbackFaultKnowledge

所有路径返回 `ErrBadRequest`，不会访问 RAG、数据库、文件存储或模型依赖。

## 回归证据

- 新增知识库 Handler nil 请求矩阵测试。
- `go test ./internal/gateway/handler`：通过。
- RAG 失败由真实 Milvus 错误驱动，未将失败计入成功样本。
- 现有 RAG 版本围栏、删除最终一致性、Index Worker retry/dead-letter 测试保持有效。

## 当前风险

RAG 真实质量指标仍受当前运行环境 Milvus Flush 超时阻断。平台已经具备可观测失败记录和恢复重试，但在依赖恢复前不能宣称 RAG P95、Citation 有效率或端到端 RAG 任务完成率。
