# 阶段 126：Milvus 自动重连与平台恢复验证

## 发现

Compose 增加 restart policy 后，Milvus 容器可以恢复，但旧平台进程仍持有已经失效的 Milvus SDK client。容器恢复为 healthy 后，平台 `/health/ready` 仍报告 `milvus=down`，RAG 会长期处于不可用状态，必须重启整个 Agent 平台。

## 修复

`internal/rag/client/MilvusClient` 现在：

- 用 `sync.RWMutex` 保护共享 SDK client；
- `Ping` 失败时，在受控超时内重建 default/agent DB client；
- 原子替换失效连接，继续复用同一个 wrapper，RAG retriever、indexer 和 Vector-GC worker 无需重新装配；
- 新连接失败时保留原始 ping 错误和重连错误，readiness 继续明确返回 down；
- 增加逻辑测试，保证指标报告对未来新终态不丢失样本。

## 真实恢复验证

1. 构建新平台二进制并启动，初始 readiness 全部组件 `up`；
2. 对 `milvus-standalone` 执行受控 `docker kill --signal=KILL`，平台 readiness 降为 `false`；
3. 手动 `docker start milvus-standalone`，Milvus 从 `starting` 到 `healthy` 约数秒；
4. 无需重启平台，readiness 自动恢复为 `true` 并持续稳定；
5. Milvus 自动重连后真实 RAG-001：1/1 通过，工具命中 1/1、关键词 4/4，端到端约 9.3 秒。

这证明依赖短暂重启后，平台不会永久持有失效 SDK 连接。

## 本轮其它验证
