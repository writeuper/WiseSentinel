# 阶段 108：Ops 评测失败归因与工具约束修复

## 评测基线

对 85 条 Ops Case 执行真实 HTTP 评测，初始结果：

- 通过率：56/85=65.9%
- 路由准确率：91.8%
- 工具成功率：70/114=61.4%
- 关键词命中率：83.3%
- P50：149ms，P95：14152ms
- 失败分布：证据源缺失 19、限流 6、禁止工具被调用 3、HTTP 错误 1

## 根因分析

1. `NEG-011/012/014` 表明用户明确禁止发布、指标或回滚相关工具时，旧的 focused tool 分支优先级仍可能重新启用这些工具，属于最小权限边界缺陷。
2. `METRIC-004/005` 等使用“内存使用率、请求量、成功率、积压”等指标术语的请求没有被指标信号识别，部分请求进入通用 Planner 并产生澄清或超过最大步数。
3. `COMBO-*` 实际已经调用多个证据工具，但评测器对 `expected_source=prometheus|logs` 使用了整体字符串匹配，导致多来源证据被误报为缺失。
4. 6 条 429 和部分长尾来自模型准入/接口限流压力，需要和功能断言分开统计。

## 修复

- focused tool 路由优先解析显式禁止词：禁止发布、Prometheus 不可用、禁止写操作和权限不足回滚时，不再进入会调用被禁止工具的分支。
- 扩展指标语义识别：使用率、请求量、成功率、命中率、积压、重试率、连接池、同步延迟、握手及对应英文表达直接路由到指标工具。
- 评测器 `check_evidence_source` 支持 `|` 分隔的多来源全量断言，不再将多个来源拼成一个字符串匹配。

## 修复后真实验证

- `NEG-011`：通过，日志+指标执行，未调用发布工具。
- `NEG-012`：通过，日志执行，未调用指标和发布工具。
- `NEG-014`：通过，日志+指标执行，未调用发布工具。
- `METRIC-004`：通过，指标工具成功，关键词 4/4。
- `COMBO-001`：通过，告警、日志、指标 3/3 工具成功，多来源证据断言通过。
- Go 定向测试：`internal/domain`、`internal/agent/ops` 通过。
- Python 评测测试：7/7 通过。

## 剩余风险

- 85 条 Ops 全量结果中的 429/长尾需要在限流隔离和固定并发下重新测量，不能直接作为纯功能失败率。
- 其余多工具 Case 需继续分批回归，确认所有组合均能保持证据来源和工具约束。
- 当前仍为本地开发/集成环境，暂无生产用户流量证据。
