# 阶段 151：异步恢复与 RAG 一致性集成回归

## 集成测试结果

- Index Worker 注入一次 Milvus `DeadlineExceeded`：进入 retry_wait，随后成功完成。
- Index/Repository lease 与 CAS：通过；旧 owner 无法覆盖新 owner 终态。
- 文档 generation 发布围栏：通过；旧 generation 不会覆盖新 generation。
- Vector GC lease fencing：通过。
- Vector GC retry backoff/dead-letter：通过。
- Vector GC redrive：通过；要求不同审批人并以专用原子流程重新入队。
- 审批过期、决策 CAS、脱敏 comment 和 generic high-risk 拒绝：全部通过。
- 迁移账本：连续执行两次，全部 checksum verified。

## 运行态 RAG 指标

当前数据库/Prometheus 快照显示：

- Vector GC：`succeeded=84`、`dead=27`、`pending=0`、`retry_wait=0`、`running=0`。
- 近 24 小时 dead 任务 4 个，主要错误为 Milvus `DeadlineExceeded`；历史 dead 任务不应直接计入当前 Agent 业务失败率。
- `ws_rag_vector_gc_attempts_total` 已记录成功清理尝试；dead backlog 由独立告警和审批 redrive 流程治理。
- `/health/ready` 所有核心组件仍为 `up`，说明当前是 RAG 清理数据面 backlog，而非平台核心服务不可用。

## 架构结论

1. RAG 文档版本一致性、索引重试和向量 GC 的 durable 状态机均有真实数据库集成证据。
2. dead 任务必须单独作为运维队列、告警和人工审批指标展示，不能混入任务完成率或模型业务失败率。
3. 近 24 小时出现 Milvus deadline 的 dead 任务，建议在生产执行 redrive 前先确认 Milvus Flush/写入容量和错误预算；不能通过无条件重试掩盖上游容量问题。
