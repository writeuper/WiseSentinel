# 阶段 146：Webhook 与审批安全链路验证

## 验证环境

- 本地平台进程已启动，`/health/ready` 返回 `ready=true`；MySQL、Redis、Milvus、模型、RAG、Ops Worker 均为 `up`。
- Webhook 使用测试密钥，通过环境变量注入；未记录密钥、完整请求原文或模型输出。

## Alertmanager Webhook

验证入口：`POST /internal/webhooks/alertmanager`。

| 场景 | 结果 | 结论 |
|---|---:|---|
| 正确 HMAC-SHA256（timestamp + "." + exact body） | HTTP 200 | 验签链路正常 |
| 错误签名 | HTTP 401 | 拒绝伪造请求 |
| 超出时间窗的 timestamp | HTTP 401 | 拒绝重放/过期请求 |
| 携带伪造 `X-Tenant-ID` | HTTP 200，仍使用固定 webhook tenant | 防止租户边界被请求头覆盖 |
| `resolved` 事件 | HTTP 200，返回 `status=resolved` | 可安全关闭已有 incident，不触发 Agent 分析 |

当前实现对同一请求体先做 event hash 幂等查询；firing 事件创建一个 Agent 任务，重复请求返回原任务。resolved-only 请求在没有已有 firing 记录时仅返回 resolved，不新建事件记录；该行为应作为接口契约明确，若业务要求完整审计 resolved 事件，后续应补充事件落库。

## 审批与高风险工具

- 未认证访问 `GET /api/v1/approvals`：HTTP 401，符合认证门禁。
- 审批决策仅允许 `approved`/`rejected`；非法值返回 400。
- 高风险审批不允许通过通用状态更新伪造执行，缺少专用原子恢复工作流时返回 `ErrHighRiskWorkflowUnavailable`（50303）。
- Vector GC redrive 保留专用 `ApproveRedrive` 流程，包含租户、审批状态、过期时间及任务状态校验。

## 风险与后续门禁

1. 生产环境必须配置非空 webhook secret，并持续监控 401、重放拒绝和限流指标。
2. 建议补充 firing→resolved 全生命周期集成用例，验证 incident 状态、任务关联和重复事件审计。
3. 高风险工具上线前应要求专用 decision-and-resume 工作流、审批人与请求人分离、参数不可变绑定和幂等执行；否则保持 50303 拒绝。
