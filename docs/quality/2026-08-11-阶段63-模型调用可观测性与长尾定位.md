# 阶段 63：模型调用可观测性与长尾定位

日期：2026-08-11

## 触发与根因

阶段 62 部署后的真实 Chat 冒烟耗时 26.386s。HTTP 指标只能说明 `/chat` 总耗时；同一请求的 RAG 检索约 1s，无法进一步分辨是模型首包、模型生成、重试、流式传输还是工具造成了长尾。没有该分桶时，无法为模型供应商或 Agent 配置设置可执行的错误预算。

## 企业级方案

在模型调用边界采集 RED 指标，并用 Trace ID 将细节放在受控 Trace/Audit 中。Prometheus 只允许稳定、低基数标签：供应商类别、操作阶段、结果类别；禁止模型部署名、URL、租户、会话、提示词、工具参数、异常文本和 request ID 作为标签。

## 实现

- 增加 `ws_model_calls_total` 与 `ws_model_call_duration_seconds`。
- 操作阶段固定为 `generate`、`stream_handshake`、`stream_complete`；结果固定为 `success`、`timeout`、`canceled`、`upstream_error`。
- 供应商映射为 `dashscope`、`ark`、`azure_openai`、`openai` 或 `other`，未知/不可信字符串不会形成新的时间序列。
- 非流式模型调用采集覆盖重试后的总耗时；流式调用分别采集 HTTP/SSE 握手和流读完耗时，读流错误被标记为 `upstream_error`。

## 自动化回归

```bash
go test ./internal/model ./internal/observability -count=1
go vet ./internal/model ./internal/observability
```

通过。测试验证未知供应商、操作和原始错误文本会收敛到受控标签，也验证 deadline/cancel/error 的稳定结果分类。

## 验收与后续

重启后端后执行真实 Chat 和 SSE 场景，`/metrics` 应出现模型阶段指标且不包含模型名、密钥、URL、用户或提示词。后续应基于至少 24 个冻结评测场景、相同模型版本和时间窗，分别报告 Chat/Ops/RAG 的 P50/P95/P99、供应商错误率、重试次数与 TTFT；单个 26 秒样本不能直接作为生产 SLO。

部署验证：新实例健康检查通过；真实 `ROUTE-001` 再次通过，端到端 25.129s。`/metrics` 记录两次 `generate/success/openai`，累计 23.33s，验证该样本的主要长尾在模型生成而非 RAG。供应商类别是受控枚举，不代表向 Prometheus 暴露具体模型或上游地址。
