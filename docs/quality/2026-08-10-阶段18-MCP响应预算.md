# 阶段 18：MCP 响应预算

## 根因

阶段 4 已限制 MCP 子进程的命令、参数和环境，但 `TimeAdapter` 会将 MCP 返回的所有文本内容无上限拼接后进入 ToolGateway/Agent。异常或恶意 MCP 服务可借此放大内存、模型 token 成本和提示注入载荷。

## 企业级方案

在 Agent 消费边界设置 hard response budget：按 UTF-8 byte 计数，超过上限立即失败且不返回部分内容；上限通过受控配置提供。这样保留业务正常响应，同时阻断过大内容继续传播。协议 transport 层仍需另行限制单帧和子进程资源。

## 落地

- `TimeAdapter` 新增 `maxResponseBytes` 与 `NewTimeAdapterWithMaxResponseBytes`。
- 默认上限为 64 KiB，配置键为 `mcp.time.max_response_bytes`。
- 文本片段在 Join 前累计长度（包含换行符）；超限返回稳定错误，不回显内容。
- Bootstrap 使用配置实例化 Adapter。
- 新增单元测试覆盖超限拒绝与上限内多文本拼接。

## 回归证据

```text
go test ./internal/toolkit/mcp ./internal/bootstrap ./internal/toolkit
make verify
```

均通过。

## 遗留项

- 当前上限作用于 Adapter 已解析的内容，不能阻止 MCP client 在协议解析前分配大响应；需后续为 transport 添加帧大小/stdio reader 上限。
- 未限制图片、resource、embedded content 等非 Text MCP content；应按工具 profile 明确允许类型和各自预算。
- MCP 子进程 CPU、内存、stderr drain、并发数与熔断器仍需在运行时/容器层治理。
