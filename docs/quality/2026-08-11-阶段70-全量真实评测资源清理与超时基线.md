# 阶段 70：全量真实评测资源清理与超时基线

日期：2026-08-11

## 问题与根因

本轮把冻结评测扩展到 25 场景（新增 BAD-002）并执行全量真实 HTTP 回归，发现三项问题：

1. 评测脚本为 Chat/RAG 创建会话但不删除，长期运行污染会话数据；RAG 在索引失败时也可能遗留上传文档。
2. 首轮 `ROUTE-001` 被供应商长尾卡住 120.920s，客户端先断开，服务端记录 `generate/canceled` 并返回 500。根因是模型 profile 缺省 120s，且每次重试可各自消耗完整 timeout，没有整次生成总预算。
3. 第二轮 `ROUTE-004` citation 已正确命中新文档，但模型正文只说“先查询”；评测仅在正文中匹配流程关键词，忽略已验证 citation snippet，且异常中拼接了完整响应。

## 企业级处理

- 测试资源遵循 create → exact delete → resource-level 404/list verification；失败路径也必须 cleanup。
- 模型 timeout 是一次逻辑调用（含重试/退避）的总预算，不是每次上游尝试的预算；超时需要以稳定 504 语义而非 500 暴露给调用方。
- RAG 评测以“回答或已绑定 citation”作为证据，不把措辞随机性误判为检索失败；失败工件只保存稳定类别，不保存响应正文。

## 落地

- `run_agent_eval.py` 现在删除每个 Chat/RAG session 并通过历史读取 404 验证；上传后的 RAG 文档在索引/Chat 失败时也执行精确删除。
- 增加脚本单元测试，覆盖成功/失败会话 cleanup、失败索引 document cleanup 和 citation 证据判断。
- `OpenAIEinoModel.Generate` 对整次生成建立 profile 总 deadline；`chat_fast.timeout_ms=30000`；Chat 模型 deadline 映射为 `50401`，而不是通用 Agent 500。
- RAG workflow 关键词同时检索回答和 citation，异常信息改为稳定、无正文类别。
