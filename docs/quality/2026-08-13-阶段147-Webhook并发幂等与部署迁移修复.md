# 阶段 147：Webhook 并发幂等与部署迁移修复

## 发现的问题

在 12 并发重复投递同一 firing Webhook 的运行态验证中，原实现会先调用 Agent、再写 `ws_alert_event`。这会让并发请求在唯一键生效前分别创建多个 Agent 任务，造成重复模型/工具执行。另一个部署问题是 `ws_alert_event` 只存在于 `schema.sql`，既有数据库若未重新初始化，迁移容器不会创建该表，firing Webhook 直接返回 50001。

## 修复

- `OpsAgentRequest` 增加可选 `TaskID`，允许入口预留任务身份并由 Agent 复用。
- Webhook firing 路径先按 `(tenant_id,event_id)` 唯一键预留事件，再启动 Agent；重复请求直接返回已预留任务。
- Agent 创建失败或返回空/failed 结果时删除预留事件，避免永久去重坏记录阻塞后续重试。
- 新增幂等迁移 `manifest/sql/migrations/20260813_alert_event.sql`，对已存在表安全执行。
- Webhook 触发的告警使用已签名、已脱敏的告警投影作为准入信号，不再被交互式服务名启发式误拒绝。
- 增加启动期孤儿预留回收：清理超过 5 分钟且没有对应 `ws_ops_task` 的 firing 预留，并记录 `ws_alert_event_orphan_reaped_total`；有效任务绑定和租户边界保持不变。
- 增加常驻 `AlertEventReaper`，每分钟持续执行回收；readiness 增加 `alert_event_reaper=up/down`，并对 15 分钟内出现回收的情况配置 Prometheus 告警。

## 运行态证据

- 迁移容器成功应用 `20260813_alert_event.sql`，重复执行保持幂等。
- 重建并重启平台后 `/health/ready`：所有依赖 `up`。
- 12 并发重复 firing 请求全部返回同一个 `task_id=ops_44d97583-bc78-4be1-b247-b38bc0a699e9`；数据库核验该事件 1 行、对应 `ws_ops_task` 1 行。
- 该用例使用合成告警，且只验证任务创建/去重，不把模型输出质量当作并发幂等证据。
- 数据库集成测试验证：孤儿事件回收数量为 1，有效任务对应事件保留。
- 最新二进制启动日志包含 `AlertEventReaper started`；readiness 已暴露所有依赖为 `up`，metrics 已暴露 `ws_alert_event_orphan_reaped_total`。
- 后续运行态复核：readiness 返回 `alert_event_reaper=up`，指标端点持续暴露该计数器；当前值为 0，表示本次启动后没有新的孤儿回收。

## 剩余风险

预留事件与 Agent 任务写入目前不是同一数据库事务；当前通过启动期年龄保护回收和 Prometheus 计数器覆盖进程崩溃窗口。生产建议进一步增加 reservation lease 或 outbox/补偿扫描，并将回收数量纳入告警阈值。
