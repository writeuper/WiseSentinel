# 阶段202：工具风险与审批绑定证据

## 面试缺口

平台已有工具成功率、审批数量和决策时延，但如果不按风险等级关联，就无法回答“高风险工具是否被拒绝/超时”“审批是否真正绑定到执行”。更重要的是，`ws_tool_call_record` 当前没有 approval execution binding，不能把审批状态统计冒充副作用执行成功。

## 实现

`scripts/report_agent_quality_metrics.py` 新增可选工具策略文件：

```json
{
  "profile": "tool-policy-2026-08",
  "tools": {
    "search_logs": {"risk_level": "L1", "approval_required": false},
    "remediate_service": {"risk_level": "L2_WRITE", "approval_required": true}
  }
}
```

通过 `--tool-policy` 或 `TOOL_POLICY_FILE` 配置后，报告按风险等级统计调用量、成功率、拒绝、不可用和超时，并统计需要审批的调用数。策略缺失或非法时输出 `not_claimed/invalid`，不根据工具名称猜测风险。

报告同时明确：

```text
approval_binding = not_available
```

因为当前工具调用记录还没有 durable approval/execution binding 字段，不能声称“审批已导致副作用执行”。

## 当前事实

本地默认运行未配置工具策略，因此工具治理状态为 `not_claimed`。现有工具成功率仍可作为技术调用指标，但不能替代风险分桶或审批绑定证据。

## 验证

- 缺失/非法策略 fail-closed；
- 风险分桶正确统计成功、错误和拒绝；
- 未知工具调用单独计数；
- 审批绑定明确保持 `not_available`，不产生假成功结论。
