# 阶段202：工具风险与审批绑定证据

## 面试缺口

平台已有工具成功率、审批数量和决策时延，但如果不按风险等级关联，就无法回答“高风险工具是否被拒绝/超时”“审批是否真正绑定到执行”。更重要的是，`ws_tool_call_record` 原先没有 approval execution binding，不能把审批状态统计冒充副作用执行成功。

## 实现

`scripts/report_agent_quality_metrics.py` 新增可选工具策略文件：

```json
{
  "profile": "tool-policy-2026-08",
  "tools": {
    "search_logs": {"risk_level": "L1", "approval_required": false},
    "remediate_service": {"risk_level": "L2_WRITE", "approval_required": true}
  }
}
```

通过 `--tool-policy` 或 `TOOL_POLICY_FILE` 配置后，报告按风险等级统计调用量、成功率、拒绝、不可用和超时，并统计需要审批的调用数。现在也可以直接指定平台唯一配置源 `manifest/config/config.yaml`，避免另建一份 JSON 策略；策略缺失或非法时输出 `not_claimed/invalid`，不根据工具名称猜测风险。

本阶段同时为 `ToolInvokeRequest` 和 `ws_tool_call_record` 增加可选 `approval_id`，并提供幂等迁移和租户索引；质量报告进一步通过租户和 approval ID 联结 `ws_approval`，输出 `approved/pending/rejected/expired/missing` 状态计数。该字段和联结只记录/校验 durable reference，不自动代表副作用已执行。

报告同时明确：

```text
approval_binding = reference_observed | missing_reference | not_applicable
```

即使为 `reference_observed` 且状态为 `approved`，也不能声称“审批已导致副作用执行”；仍需专用执行器校验参数快照、幂等键和最终效果。

## 当前事实

本地显式读取平台配置：

```bash
python3 scripts/report_agent_quality_metrics.py \
  --tool-policy manifest/config/config.yaml --format json
```

得到当前本地工具风险分桶：L0 为 2989 次调用、成功率 95.58%；L1 为 336 次调用、成功率 78.87%。当前配置没有 L2 工具和审批调用，因此 `approval_binding=not_applicable`。这些是本地工具调用技术指标，不是生产风险或业务成功率。迁移未在生产环境执行前，旧数据库的绑定证据仍应视为不可用。

## 验证

- 缺失/非法策略 fail-closed；
- 风险分桶正确统计成功、错误和拒绝；
- 未知工具调用单独计数；
- 审批引用完整性分为 `reference_observed/missing_reference/not_applicable`，并单独统计审批状态，不产生假成功结论。
