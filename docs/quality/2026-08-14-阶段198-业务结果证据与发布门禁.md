# 阶段198：业务结果证据与发布门禁

## 面试缺口

Agent Trace 的 `success`、工具调用成功或 Ops 任务完成，只能证明平台技术链路完成，不能直接证明真实业务任务已经达成。若缺少业务结果事件，平台不应把技术成功率表述为业务成功率，也不应据此宣称真实用户效果。

## 实现

`scripts/report_agent_quality_metrics.py` 新增可选的业务结果 Attestation：

- 只接受 `task_count/success_count/failure_count/unknown_count` 等聚合计数；
- 校验计数守恒、时间窗、来源枚举和生产指纹；
- 输出终态样本量和业务成功率；
- 不输出任务 ID、用户 ID、租户 ID、请求正文或业务事件明细；
- 未配置真实分析/工作流证据时输出 `not_claimed`。

`scripts/check_agent_release_readiness.py` 新增：

```bash
--require-business-outcomes
--minimum-business-outcome-rate 0.99
```

只有业务结果状态为 `production_attested`、存在终态样本且达到阈值时才通过该门禁。默认不强制，避免把没有真实业务事件的开发环境误判为失败；生产发布配置应显式开启。

## 当前事实

本地环境当前没有业务结果 Attestation，因此报告为 `not_claimed`，不能宣称真实业务成功率。现有本地技术链路聚合仅作为工程诊断：Agent 业务终态平均耗时约 `7033.15 ms`，业务终态 P95/P99 约 `29011/40723 ms`；这些数据来自本地持久化 Trace，不代表生产用户体验。

## 验证

- 业务结果 Attestation 缺失、非法计数和敏感字段投影均有自动化测试；
- 默认门禁保持向后兼容并显示 `info`；显式要求业务结果时，缺失证据 fail-closed；
- 真实生产接入前仍需由产品分析或业务工作流系统提供脱敏聚合和可审计指纹。
