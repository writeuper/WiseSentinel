# 阶段 149：真实用户流式并发与权限回归

## 真实运行态结果

| 场景 | 结果 |
|---|---|
| Trace 所有者访问 | 通过；可读取自己的 Trace |
| 不存在 Trace | 404/40401，fail-closed |
| SSE 基础链路 | `connected → message → done` 完整结束 |
| SSE 取消 | 收到 message 后取消，历史不落库，符合取消契约 |
| SSE 删除竞态 | 删除后会话不可读，流未错误完成 |
| SSE 4 路并发 | 3 次正常完成，1 次 50304 准入保护并返回 retry-after=2 |
| Chat 同步幂等回放 | 通过；重复 key 响应一致，冲突 payload 被拒绝 |
| Chat 同 key 并发 | 一成功一冲突，复用同一 Trace |
| 跨租户 Trace 访问 | 伪造 `X-Tenant-ID` 返回 404/40401，不能越权读取 |

## 容量指标

此前 4 请求/2 并发同步 Chat 实测：成功率 100%，cleanup 4/4，P50 约 7.12 秒，P95 约 17.58 秒；本轮 SSE 4 路并发触发 1 次模型准入保护，说明系统在压力下优先保护上游预算，而不是无限排队。

## 结论与剩余风险

- 会话、Trace、幂等和租户边界均有真实用户路径证据。
- 50304 属于预期的资源保护结果，应单独统计为 admission rejection，不能混入 Agent 业务失败率。
- 当前测试为本地模型和依赖环境的小样本容量基线，不代表生产 SLO；上线前需固定模型版本、租户和并发阶梯，持续采集 P50/P95/P99、429/50304、cleanup 和成本指标。
