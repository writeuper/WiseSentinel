# 阶段 30：RAG GC Lease 围栏

## 根因

GC outbox 没有执行所有权时，多 Worker 或崩溃恢复可能并行删除同一目标，且旧 Worker 在 lease 被新 Worker 接管后仍可能错误写成功/失败终态。

## 企业级方案

以 MySQL 条件更新为 GC 所有权权威：pending、retry_wait 或 lease 已过期的 running 任务才可领取；领取写入唯一 execution token 和过期时间。所有终态更新必须同时匹配 `status=running AND execution_token`。Redis 可以降低竞争，但不能代替该 CAS。

## 落地

- 新增 `ClaimVectorGC`，原子领取或接管过期 lease，并增加 attempt count。
- 新增 `FinishVectorGCIfOwned`，仅当前 token 能写终态。
- 新增真实 MySQL 集成测试：token-A 领取后 lease 过期，token-B 接管；A 完成失败，B 完成成功。
