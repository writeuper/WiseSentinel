# 阶段 66：十并发真实 Chat 容量验证

日期：2026-08-11

## 目的

阶段 65 已建立 5 并发质量门禁，但不足以验证较高并发下模型配额、HTTP 限流、会话隔离和 cleanup 是否保持正确。本轮在隔离测试租户上运行 10 个并发只读 Chat 用户，不调用工具或高风险写操作。

## 真实执行

```bash
EVAL_BASE_URL=http://127.0.0.1:8090/api/v1 EVAL_API_KEY=... \
  LOAD_REQUESTS=10 LOAD_CONCURRENCY=10 LOAD_TIMEOUT=120 \
  LOAD_MIN_SUCCESS_RATE=1 LOAD_MAX_P95_MS=60000 \
  make agent-load-chat
```

| 指标 | 结果 |
| --- | ---: |
| 请求/并发 | 10 / 10 |
| 成功率 | 10/10（100%） |
| cleanup 资源级验证 | 10/10 `verified` |
| 429 / 超时 | 0 / 0 |
| P50 | 9.493s |
| P95 / P99 / Max | 20.390s / 20.390s / 20.390s |
| 模型 metrics 增量 | 10 次，109.112s |
| 质量门禁 | 通过 |

## 结论

在当前开发/集成依赖、当前模型配置和固定低风险问题下，平台通过了 10 并发真实 Chat canary。会话在删除后均被历史读取路径以 404 拒绝，说明本轮没有留下可读取的测试会话。

这不是生产容量声明：样本数为 10、只有一个用户路径、模型供应商配额及网络条件未隔离。60s P95 是本环境保护上限，不是业务 SLO。生产前还应在授权环境对 Chat、Ops、RAG 和流式 TTFT 分别进行持续时间更长的阶梯压测，并联合观测 MySQL/Redis 连接池、goroutine、GC、队列、429、模型错误和成本。

本轮相关离线回归 `go test ./... -count=1`（含补跑 repository/toolkit 包）与并发脚本 3 个单元测试均通过。
