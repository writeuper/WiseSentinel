# 阶段 44：真实场景并发与可靠性回归

## 验证范围

本阶段以真实 MySQL、Redis、Milvus 代替 mock，覆盖企业 Agent 平台的高风险路径：

| 场景 | 不变量 | 本次结果 |
| --- | --- | --- |
| 并发知识检索 | 同一 RAG/Milvus/MySQL 链路下，外租户同关键词文档不可返回 | 24/24 成功，泄漏 0，614ms；`-race` 复跑 24/24，泄漏 0，284ms |
| RAG 索引、代际、删除 | 写入—检索、代际发布、legacy 精确删除可回归 | 全部通过 |
| 审批并发决策 | 同一待审批项的 approved/rejected 仅一个 CAS 胜出；过期项不能批准 | 通过 |
| Index/Ops 租约 | 旧 owner 不可续约/释放新 owner；失 DB lease 必须取消执行；Redis 不可用可由 MySQL lease 执行 | 通过 |
| 向量 GC | superseded publisher、删除、重试/死信和审批受控重驱受 DB 事务围栏 | 通过 |
| 限流 | 同一毫秒两次准入、第三次拒绝，ZSET 计数准确 | 通过 |

并发检索场景在 `TestConcurrentRAGRetrievalTenantIsolation` 中创建两个专用租户及同关键词文档，以 `tenant_id` Milvus filter 和 MySQL active-generation resolver 共同作为边界。每次测试使用唯一 Milvus collection，只清理自己创建的数据。

## 可重复门禁

新增组合目标：

```bash
OPS_TEST_MYSQL_DSN='...' OPS_TEST_REDIS_ADDR='127.0.0.1:6379' \
  make test-real-scenarios
```

它顺序执行 RAG 集成、并发 race、Ops/Index 真实租约、审批 CAS 与 Redis 限流；缺少任一连接配置即失败，不允许 `Skip` 伪造通过。

本机验证还执行了：

```bash
OPS_TEST_MYSQL_DSN='...' make rag-eval
make verify
```

RAG 标注排序结果继承阶段 43：Recall@1=100%（3/3）、Recall@3=100%、MRR=1.000、nDCG@3=1.000；样本仅为三条合成探针，不能外推为生产准确率。
