# 阶段 29：RAG GC 精确代际删除

## 根因

阶段 28 已记录 generation GC 意图，但现有 Milvus 删除只有 tenant+doc 或 tenant+source 范围。GC 若按 document 删除，会移除正在读取的 active generation；若只按 generation 删除，则可能影响其他 tenant/document 的相同 generation 值。

## 企业级方案

将 generation GC 删除目标定义为三字段合取：`tenant_id AND doc_id AND generation`。所有 generation worker 调用必须经该方法；document_all 与 legacy 另走独立、显式的清理策略，不能复用此路径或退化为 source 删除。

## 落地与回归

- 新增 `filter.DeleteByGenerationExpr(tenantID, docID, generation)`。
- 新增 `MilvusIndexer.DeleteByGeneration`。
- 先加入失败契约测试；初始因函数不存在失败，实现后通过。

```text

```

均通过。

## 遗留项

- 需完成真实 Milvus generation 选择性删除、worker crash/retry 及 document_all 回归。
