# 阶段 53：审批待办真实计数与权限降级

日期：2026-08-11

## 问题根因

门户侧栏“审批中心”徽标写死为 `3`。它与后端 pending approval 状态没有任何关联，会让管理员对待办规模、SLA 和实际审批风险做出错误判断；普通用户也可能看到不属于自己的运营暗示。

## 企业级解决方案与实现

- 管理员侧栏调用现有 tenant-scoped `GET /approvals?page=1&size=1`，只取 `total`，不拉取审批 payload 或正文。
- 仅 `sre_admin` / `platform_admin` 执行读取；无权限、网络错误或未知状态时隐藏徽标，fail-closed 而非保留旧数字。
- 首次加载、窗口重新聚焦和 30 秒周期刷新，平衡运营及时性与请求成本。
- 仅当真实 total 大于 0 时显示徽标；普通用户仍由前端导航守卫隐藏审批入口，服务端 RBAC 是最终授权边界。

## 验证

| 验收 | 结果 |
| --- | --- |
| Portal TypeScript + production build | 通过 |
| 后端健康检查 | 通过 |
| 当前开发 API key 调用 `/approvals` | 403（非管理员，符合 RBAC） |
| 非管理员徽标行为 | 隐藏，不再显示固定 `3` |

当前环境没有可用的管理员测试身份，因此不能把 403 当作管理员 total 的替代证明；管理员端到端验收应使用受控 admin token 创建精确 pending approval，断言徽标显示 total，并在 decision 后刷新为 0。

## 后续

审批状态机完成 durable intent 后，API 应补充安全 action projection、effect status 和历史查询；Portal 则显示“已重入队/执行中/已完成”，不能将“已批准”误表达为“已执行”。
