# 阶段 153：Vector GC 管理面错误边界修复

## 发现

管理员对不存在的 Vector GC redrive 目标发起申请时，原接口将数据库 `sql: no rows in result set` 包装成 HTTP 500/40001，并把 SQL 细节暴露给客户端。这既误导故障归因，也不符合管理 API 的稳定错误契约。

## 修复

- Repository 将不存在的目标归类为稳定业务错误。
- Handler 统一返回 HTTP 400、业务码 40002：

```text
向量清理任务不存在、不是死信或已不可重驱
```

- 不再把 SQL 驱动错误、表结构或 `no rows` 文本返回给客户端。
- 有效管理员列表查询仍按租户过滤并返回脱敏的 `last_error`。

## 运行态证据

- `sre_admin` 查询 dead 任务：HTTP 200，列表正常返回。
- `sre_admin` 对不存在目标申请 redrive：HTTP 400/40002，未泄露 SQL 细节。
- operator 使用开发 API Key 访问同一管理面：HTTP 403/40301。
- Vector GC redrive 的过期、CAS、不同审批人和专用恢复集成测试均通过。
