# 阶段194：前端 Chat 流竞态与状态一致性

## 面试缺口

企业级 Agent Portal 需要在用户取消流、切换新会话、网络断开和旧请求晚到时保持状态一致。此前旧 SSE 回调可能在新会话中追加文本、Citation 或工具状态；工具事件还可能直接修改 React state 数组。

## 实现

- `Chat.tsx` 增加单调递增的 request epoch；新对话、组件卸载和新请求都会推进代际。
- SSE 的 message/citation/tool/error/done 回调和同步 Chat 结果提交前都校验代际，旧请求只能被丢弃，不能覆盖新会话。
- 延迟完成的 session 创建也绑定 request epoch，避免旧请求重新设置当前 session。
- Citation 与 toolCalls 使用不可变数组更新，避免 React 并发渲染下的共享引用污染。

## 验证

- 新增前端静态契约回归：验证代际围栏、session 绑定和不可变更新。
- `npm --prefix portal run build` 通过；TypeScript 类型检查和生产构建通过。

## 剩余风险

当前仓库未配置浏览器级 Playwright/Cypress 测试，因此本阶段不能宣称真实浏览器断线/切页 E2E 已覆盖；上线前仍应在隔离环境补充真实 SSE 网络故障注入和键盘/可访问性回归。
