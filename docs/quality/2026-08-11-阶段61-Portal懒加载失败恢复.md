# 阶段 61：Portal 懒加载失败恢复

日期：2026-08-11

## 问题

阶段 60 将运营页面改为动态 chunk 后，部署切换、CDN 缓存滞后或网络中断可能让浏览器请求到已经被替换的旧 chunk。此前 `Suspense` 只覆盖加载中；动态导入最终失败会冒泡为未处理渲染异常，用户没有稳定、可恢复的操作入口。

## 实现

- 在每个懒加载页面外增加 `PageLoadBoundary`，捕获 React lazy chunk 的渲染错误。
- 失败态使用 `role="alert"` 和固定中文提示，并提供浏览器重新加载操作；加载中继续使用 `role="status"` 与 `aria-live="polite"`。
- 不在页面中渲染或持久化原始 chunk 错误。异常内容可能携带资源 URL、网关诊断或上游细节；面向用户只给出版本切换场景下的安全恢复指引。
- 路由角色守卫仍位于懒加载页面之前，失败恢复不改变前端防御性授权或服务端 RBAC。

## 验收与回归

```bash
cd portal && npm run build
```

通过。入口 chunk 为 793.66KB（gzip 254.70KB）；阶段 60 的按路由拆包结果保留，Vite 对共享核心 chunk 超过 500KB 的警告仍存在。

建议在预发布浏览器中验证：先加载任一受保护页面，再发布带 hash 变更的前端版本并模拟旧 chunk 404；页面应显示受控提示和“重新加载”，不得出现原始异常、内部 URL 或 token。

## 剩余风险

本变更只提供用户侧恢复，不能消除发布期间的陈旧缓存。生产发布还需要 CDN cache-control、保留上一版本静态资源的时间窗口，以及 RUM 中按 `chunk_load_failed` 类别聚合的告警；遥测事件同样只能记录受控分类和 trace/版本标识，不能上传原始异常正文。
