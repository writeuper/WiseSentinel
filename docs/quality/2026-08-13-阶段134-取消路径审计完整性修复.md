# 阶段 134：取消路径审计完整性修复

## 发现

模型超时或客户端断开时，请求 Context 可能已经 canceled。原审计中间件在 Handler 返回后继续使用 `r.Context()` 写入 `ws_audit_log`，因此会出现业务请求已结束但审计 INSERT 因 `context canceled` 失败的情况，影响企业级审计完整性。

## 修复

- 审计写入使用 `context.WithoutCancel(r.Context())` 保留租户、用户和 Trace 等值，但脱离请求取消信号；
- 增加 2 秒独立写入超时，避免审计写入拖慢响应或无限等待；
- 增加 `ws_audit_write_failures_total{reason="context_canceled|database"}`；
- reason 仅允许两个低基数值，不记录 SQL、DSN、错误原文、租户、Trace 或请求路径；
- 新增指标标签边界测试和竞态测试。

## 质量门禁

- 审计与可观测性单测：通过；
- 审计与可观测性竞态测试：通过；
- 全量 Go/Python/安全/Compose 门禁需保持通过；
- 服务 readiness 必须保持 `ready=true`。

## 真实 SSE 回归

- cancel contract：`cancel_not_persisted`，符合当前“客户端取消不持久化未完成回答”的契约；
- delete-race contract：`delete_race_not_completed`，删除后没有干净完成事件；
- 新增 detached audit context 单测，确认父 Context 已取消时仍保留 Trace 等值且审计 Context 可执行。

## 验收标准

1. 模型超时、客户端取消后仍能尝试写入审计记录；
2. 数据库异常不会阻塞请求超过 2 秒；
3. 审计失败只增加 bounded reason 指标，不泄露敏感数据；
4. 正常请求的审计行为和响应契约保持不变。
