# 阶段 167：VectorGC 抢占后重载失败恢复

## 发现

VectorGC Worker 在数据库 `Claim` 成功后会重新读取任务，以获得最新的 `attempt_count` 和执行令牌。如果这次重载发生数据库错误，原实现直接返回，任务会暂时停留在 `running`，只能等待租约过期后由下一轮重新抢占。这会拉长故障恢复时间，并使运行中任务数量与实际执行状态不一致。

## 修复

- 重载错误时沿用本次抢占令牌调用 `RetryIfOwned`，写入有界的 `retry_wait` 或 `dead` 终态。
- 保留 CAS/令牌围栏：重载返回空任务或令牌不一致时不再写入，避免误修改其他 worker 的任务。
- 新增回归测试，验证“抢占成功、重载失败”会产生持久化重试计划。

## 影响与剩余风险

该修复避免了数据库短暂不可用时的永久/长时间 `running` 假象，并让重试/死信指标保持可解释。若数据库在抢占后完全不可写，CAS 更新仍可能失败，任务会依赖租约恢复；该场景需要结合数据库可用性告警和死信巡检继续观测。
