# 阶段 37：Index Lease 续约故障注入

## 目标

阶段 36 已实现显式 lease，但 repository 测试不能证明 Worker 续约协程的定时行为、或 lease 丢失时是否真正取消正在执行的 context。本阶段针对这两个并发失败模式补齐真实 MySQL 故障注入。

## 测试与发现

1. 以 1.5 秒初始 lease 启动 Worker 续约（TTL=2 秒、1 秒续约节拍），等待初始 lease 到期后断言任务仍不可由 token B 领取。
2. 在续约 tick 前模拟 token 被接管，断言 Worker 的 run context 在 3 秒内被取消。

第二个测试首次通过时暴露观测问题：日志记录为 `DB lease lost ... <nil>`。CAS 未命中是预期的 ownership-lost 事件，不是数据库错误；`<nil>` 会干扰告警和人工排障。

## 修复

- DB/Redis lease renewal 均拆分两类输出：
  - 基础设施调用失败：`Error`，携带实际错误；
  - CAS/compare 未命中：`Warning`，稳定说明 ownership lost，不伪造 `nil` error。
- 两类情况都会取消执行 context；最终 DB token/lease CAS 继续防止 stale worker 写入终态。

## 回归证据

```bash
OPS_TEST_MYSQL_DSN='mysql:ws:ws123@tcp(127.0.0.1:3306)/wisesentinel?charset=utf8mb4&parseTime=True&loc=Local' \
go test -tags=integration ./internal/orchestrator/task \
  -run 'TestIndexWorker(Renews|Cancels|Executes)' -count=1 -v
```

结果：通过；lease lost 场景输出 `DB lease ownership lost`，不再含 `<nil>`。

## 剩余风险

- 定时测试使用秒级真实时间，保持短且有明确 timeout；如后续引入 worker clock 注入，可进一步压缩测试时间并降低调度抖动。
- 仍需在发布环境验证 termination grace period 覆盖 embedding/Milvus 的常见尾延迟。
