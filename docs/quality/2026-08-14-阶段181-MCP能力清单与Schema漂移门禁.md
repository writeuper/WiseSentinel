# 阶段181：MCP 能力清单与 Schema 漂移门禁

## 问题与风险

此前 MCP stdio 客户端虽然执行了 `initialize` 和 `tools/list`，但丢弃了 `serverInfo`、协议版本、完整工具集合和工具 Schema。这样无法证明当前执行器就是发布时批准的能力集合：工具被新增、删除、改名或参数类型变化时，Agent 仍可能继续运行，造成路由错误、参数错误或越权能力扩张。

## 落地内容

- 在启动握手后构建脱敏 `CapabilityManifest`，保存协议版本、服务名称/版本、工具名称、工具数量和 SHA-256 Schema 指纹。
- 消费 `tools/list` 分页结果，检测重复 cursor，并设置 512 个工具的硬上限，避免异常 MCP server 无限分页或资源放大。
- 对空工具名和重复工具名 fail-closed。
- 新增可选 `CapabilityPolicy`，支持固定服务身份、完整工具名称集合、Schema 指纹和最大工具数；不满足策略时启动失败，不进入可调用状态。
- 提供 `Manifest()` 只读快照用于审计/部署比对；快照不包含工具描述、参数值、租户标识、密钥或原始请求。

## 关键不变量

1. 能力清单必须在会话初始化和工具发现都成功后才发布。
2. 工具集合不完整、分页 cursor 重复、工具名冲突或超过硬上限时必须拒绝启动。
3. 生产 profile 应固定服务身份、工具集合和 Schema 指纹；本地兼容 profile 可不配置策略，但不能把未配置策略描述为漂移防护。
4. Schema 指纹只用于能力契约比对，不作为权限本身；工具仍必须经过平台工具注册表、Allowlist、RBAC、风险等级和审批流程。

## 测试证据

- 验证合法服务身份、工具集合、指纹和数量策略可以通过。
- 验证服务版本漂移、工具集合漂移、指纹漂移和工具数量超限均失败。
- 验证参数 Schema 变化会改变指纹。
- 验证分页结果能够合并，重复 cursor 会 fail-closed。
- 既有 MCP 命令/参数白名单、环境最小权限和响应预算测试继续保留。

## 边界与后续

- 当前指纹在启动时生成；运行期间 MCP server 若自行改变能力，需要通过重连/健康检查重新建立会话并重新校验，不能依赖启动快照覆盖热变更。
- 指纹不含描述文本，避免把非执行契约的文案变化当成破坏性变更；若业务要求描述版本化，应将描述摘要纳入单独的提示词契约版本。
- 生产仍应使用固定镜像或二进制 digest、独立低权限身份、网络默认拒绝、stderr/输出预算、工具调用熔断和完整审计。
