# 阶段 123：前端入口分包与性能门禁

## 目标

治理 Portal 构建中约 798 KB 的主 JavaScript 入口，建立可重复的首屏入口体积门禁，同时不把“入口文件变小”误报成所有首屏网络资源均已低于 500 KB。

## 修复

在 `portal/vite.config.ts` 增加 Rollup `manualChunks`：

- `react`：React、React DOM、React Router；
- `antd`：Ant Design 与图标包。

新增 `scripts/test_portal_bundle.py`，构建后检查 `portal/dist/index.html` 的首入口 JavaScript 小于 500 KiB。

## 先失败后通过

修复前门禁失败：

```text
initial entry is 798165 bytes; split vendor dependencies
```

修复后门禁通过：

```text
Ran 1 test ... OK
```

## 构建结果

| 资源 | 修复前 | 修复后 |
|---|---:|---:|
| 主入口 JS | 约 798.17 KB | 28.51 KB |
| React vendor | 未独立拆分 | 164.36 KB |
| Ant Design vendor | 未独立拆分 | 1,047.85 KB |

构建命令 `npm run build` 成功，TypeScript 编译和 Vite 打包均通过。构建仍提示某些 chunk 大于 500 KB，原因是 Ant Design vendor 本身较大。

## 重要口径

当前 `index.html` 会 modulepreload React 与 Ant Design vendor，因此主入口门禁只证明入口代码已拆分，不能证明首屏总下载量低于 500 KB。后续若需要降低首屏网络负载，应按页面和组件继续拆分 Ant Design，或改为按需组件导入，并用真实浏览器 Performance/Lighthouse 采集首屏传输量、LCP 和交互可用时间。
