# 阶段 74：真实 SSE 与取消传播

日期：2026-08-11

## 问题与根因

Portal 过去将同步 `/chat` 响应按字符定时展示，命名为“流式”。停止按钮只终止字符动画，未取消网络请求；用户已离开页面或点击停止时，上游模型仍会继续消耗容量，且前端错误前会遗留空白 assistant 气泡。

后端已具备 `/chat/stream` SSE 入口，但 SSE writer 对含换行的模型 chunk 只写一个 `data:` 前缀，可能让第二行被浏览器解释为协议帧而不是内容。

## 企业级方案与落地

- Portal 改为直接 POST `/chat/stream`，用 `fetch` body reader 解析真实 SSE 帧；`AbortController.signal` 传入 fetch，停止、新建对话与组件卸载可取消在途请求。
- SSE 协议事件 `connected`、`message`、`tool`、`citation`、`error`、`done` 显式分派；工具 payload 只在前端按既有受控结构解析。
- 后端将每个多行 payload 都编码为独立 `data:` 行，保证 SSE framing 与正文边界正确。
- 流错误时仅移除尚无内容的 assistant 占位气泡；已有部分内容保留给用户，同时后端仍不会将取消/失败的部分回答持久化进会话历史。
- 取消是运输层控制，不自动重放请求；模型/工具幂等、审计和容量策略继续由后端负责。

## 验收证据

| 检查 | 结果 |
| --- | --- |
| SSE 多行编码 Go 单测 | 通过 |
| handler/chat Go 测试 | 通过 |
| Portal TypeScript + Vite production build | 通过 |

| 资源清理 | 真实 SSE 验证创建的 session 在 finally 中精确删除 |

真实 SSE 验证不落盘模型回答、提示词或凭据，仅输出事件名和字符数。

## 剩余风险

- 浏览器级 E2E 仍应补充：点击停止后服务端 request context 取消、不会写入部分消息、重新发送可用，以及弱网断连。
- 当前 SSE 没有独立 citation 事件的完整端到端产出证据；需用受控 RAG 文档验证 citation frame 与 Portal 展示。
- 生产代理必须关闭 SSE buffering、配置合适 idle timeout，并在多副本部署验证客户端断连传播。
