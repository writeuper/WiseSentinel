# 阶段 3：索引任务执行租约

- 日期：2026-08-10
- 状态：已完成 MySQL/Redis execution fencing；Milvus generation 一致性待后续阶段
- 协作角色：Agent 架构师、Golang 后端工程师、自动化测试工程师

## 1. 问题与影响

知识库 Index Worker 原先使用固定 Redis 锁值和无条件 `DEL`，数据库索引任务也只按 `running` 状态完成。锁过期并被另一 Worker 接管后，旧 Worker 可以删除新锁或覆盖新尝试的任务终态；不同租户同 task ID 也会争夺同一个 Redis 锁。

## 2. 根因与企业级方案

根因与 Ops Worker 相同：Redis 锁被误当作唯一所有权来源，数据库写入没有 fencing token。

本阶段与 Ops 任务采用同一模式：每个 Claim 生成 UUID `execution_token`；token 同时作为 MySQL owner 和 Redis value；Worker 以 tenant + task 组成锁 key；所有终态更新要求 `running + token`；Lua 脚本仅允许当前 token 续约或释放。服务执行器显式接收 token，失去所有权时不再更新任务或删除其他尝试的结果。

## 3. 落地实现

- `ws_index_task` 增加 `execution_token` 与 runnable 索引，并新增兼容迁移 `20260810_index_task_execution_lease.sql`。
- `IndexTaskRepo.ClaimRunnable`、`MarkFinishedIfOwned` 实现 MySQL CAS。
- `IndexWorker` 使用 token 化锁、租约续约、失租取消和 token-safe release。
- `IndexTaskExecutor` 及 RAG Service 显式传递并校验 token。
- 删除旧 Service 在失去任务状态时执行 `DeleteByDocID` 的补偿行为，避免陈旧 owner 删除新 owner 已完成的索引。
- 新增 MySQL/Redis 集成测试与 `make test-index-integration` 门禁。

本地基础设施已应用上述 migration；该迁移只新增列和索引，未删除或修改既有索引任务。

## 4. 回归证据

```bash
OPS_TEST_MYSQL_DSN='mysql:...' \
OPS_TEST_REDIS_ADDR='127.0.0.1:6379' \
make test-index-integration
```

真实 MySQL 8.0 验证：首次 Claim 成功、并发 Claim 失败、陈旧 running 被接管后旧 token 无法完成、当前 token 可唯一完成。真实 Redis 7 验证：过期 owner 无法释放或续约新 owner 的锁。

## 5. 重要边界与下一步

该阶段保护了 MySQL 状态和 Redis lease，**尚不能对 Milvus 外部向量写入做原子 fencing**。旧索引执行器可能已开始向量删除/写入；数据库所有权变化无法回滚其已发出的外部请求。

要达到端到端企业级一致性，下一 RAG 阶段需引入 index generation：每次索引写入独立 generation，Document 元数据仅在当前 owner 成功时切换 `active_generation`，检索只读取 active generation，异步 GC 清理旧 generation。这将涉及文档 Schema、chunk metadata、Milvus filter/retriever 与发布/回滚策略。
