# 阶段 205：浏览器级隔离 E2E 与前端可访问性回归

## 目标

补齐 Portal 真实 Chromium 浏览器级验证，覆盖登录、权限后的 Chat、Ops 告警分析入口和错误恢复路径。测试使用 Playwright 1.49.1（兼容当前 Node 18）及系统 Chrome，不连接真实模型、生产服务或真实用户数据。

## 新增内容

- `portal/playwright.config.ts`：隔离 WebServer、系统 Chrome、失败保留 Trace。
- `portal/e2e/portal.spec.ts`：3 条浏览器级契约用例。
- `portal/package.json`：新增 `npm run test:e2e`。
- Ops 最大执行步数控件增加 `role="group"` 和可访问名称，避免 Slider 组件未暴露语义导致屏幕阅读器无法定位。

## 验证结果

```text
npm --prefix portal run build       PASS
npm --prefix portal run test:e2e    3 passed
```

覆盖的断言包括：

1. 登录接口成功后进入 `/chat`，RAG、工具调用、流式开关和发送按钮可被语义定位；
2. operator/sre_admin 可进入 `/ops`，空任务列表、异步模式、最大执行步数和刷新控件可被定位；
3. Trace 后端不可用时页面仍保持非空、可渲染的恢复路径，不出现白屏。

## 边界与未覆盖范围

- API 使用 Playwright route mock，仅验证前端交互、权限后的路由和可访问性契约；不代表后端接口、模型质量或生产 SLO 已验证。
- 尚未覆盖真实 SSE 断线、浏览器网络切换、审批竞态、移动端屏幕阅读器和真实多租户生产流量；这些仍需在专用集成环境执行。
- 构建仍有既有的 Ant Design 大 chunk warning，不影响构建成功。
