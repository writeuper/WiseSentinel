# 阶段 20：Embedding 上游错误最小披露

## 根因

DashScope embedder 在非 2xx 响应时会读取完整 body 并拼接到 error。上游 body 可包含输入回显、密钥、请求信息或供应商诊断，随后可能经 RAG task、日志、Trace 或 API 错误链扩散。

## 企业级方案

与阶段 9 的模型/工具适配器保持一致：失败状态在读取 body 前判定，错误只包含 provider、HTTP status 和经过安全摘要的 request ID。成功响应仍完整读取并按既有 OpenAI-compatible schema 解析。

## 落地

- `DashScopeEmbedder` 新增实例 endpoint，默认保持正式 DashScope URL，同时支持受控 HTTP 测试。
- 非 2xx 时不再读取 body，改由 `dashScopeHTTPError` 构造稳定错误。
- 新增 `httptest` canary：500 body 不得出现在错误，`HTTP 502 request_id=...` 必须保留。

## 回归证据

```text
go test ./internal/rag/embedder ./internal/rag
make verify
```

均通过。

## 遗留项

- 成功响应 body 的大小和 embedding 数量/索引范围仍需配置预算与 schema 验证，避免异常成功负载消耗内存。
- 网络层错误仍可能携带 Go transport 文本；阶段 8 统一错误出口继续作为防线，后续可进一步归一化为超时/DNS/连接类别。
- 需在隔离环境验证真实 DashScope 失败时的日志、任务表和 API 全链路零 canary 泄露。
