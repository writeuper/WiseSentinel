# 阶段189：独立 RAG 证据持久化与评测闭环

## 面试缺口

此前 Trace 的输入、输出和错误摘要全部经过 `TelemetryProjection`，只保留大小信号；这满足脱敏要求，但也使 Citation 只能做结构校验，无法证明回答引用的文档确实来自独立检索步骤。

## 实现

- `ws_agent_trace_step` 新增 `evidence_doc_ids JSON`，只保存最多 32 个、单个最多 128 字符、去重后的文档 ID。
- Chat 同步和 SSE 的 RAG retrieve step 持久化 Citation 对应的文档 ID；文档正文、查询、模型输出和工具参数仍走原有脱敏投影。
- Trace API 在授权范围内返回 `evidence_doc_ids`，评测脚本优先从该结构化字段提取独立证据，并与响应 Citation 做 grounding 交叉校验。
- 评测基线比较器纳入 `citation_grounding_rate`；任一运行缺少独立证据时不比较，不把 `N/A` 当作 0%。

## 验收与可信度边界

- 覆盖证据 ID去重、长度/数量上限、API 投影和无证据时 `N/A` 的自动化测试。
- 该字段只证明 Citation 与持久化 RAG 检索证据的文档 ID一致，不等价于人工相关性判断；Recall@K、MRR、nDCG 仍必须使用 verified relevance Gold 集。
- Trace 读取继续受租户、资源归属和管理员角色控制；证据 ID不是公开检索接口，也不包含文档正文或敏感工具参数。

## 数据库变更

新增迁移：`manifest/sql/migrations/20260814_trace_evidence_doc_ids.sql`。上线前需在隔离环境执行迁移、回滚演练和真实 RAG Citation 回归；未执行迁移的旧实例应保持评测 grounding 为 `N/A`，不得误报为已验证。
