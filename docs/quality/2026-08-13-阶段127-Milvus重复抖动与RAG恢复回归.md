# 阶段 127：Milvus 重复抖动与 RAG 恢复回归

## 目标

验证 Milvus 自动重连不是一次性偶然成功，而是能够应对重复的依赖进程终止/恢复，并确保平台无需重启即可恢复 readiness 和 RAG 能力。

## 验证过程

- 对 `milvus-standalone` 连续执行两轮受控 `docker kill --signal=KILL` → `docker start`；
- 每轮故障期间平台 `/health/ready` 明确返回 `ready=false`、`milvus=down`；
- 每轮 Milvus 恢复后，平台 readiness 自动回到 `ready=true`，未重启平台进程；
- 第一轮从恢复启动到 readiness 恢复约 5 个轮询周期；第二轮独立检查确认 `milvus=running/healthy`、平台 `ready=true`；
- 两轮后 RAG-001：1/1 通过，工具命中 1/1、关键词 4/4，端到端约 14.2 秒。

## 结论

Milvus wrapper 的失败探测、连接替换和共享 wrapper 设计在重复抖动场景下有效。依赖不可用期间 readiness 正确降级，避免把不可用 RAG 宣称为健康；依赖恢复后不需要重启整个 Agent 平台。

## 指标口径

本轮平台进程未重启，Prometheus RAG 样本仍属于当前进程生命周期；若平台进程重启，进程内 counter 会清零，不能与前一生命周期样本直接合并。RAG 检索 P95 仍按 Histogram 桶上界解释，不能当作精确百分位。

## 剩余风险

1. 业务请求恰好落在依赖故障窗口时可能失败一次；当前修复保证后续 readiness 和请求恢复，不承诺跨故障请求自动重放。
2. 生产需要将依赖恢复、readiness、RAG error rate 和 SDK reconnect 次数纳入告警，并对重连增加独立计数器；当前仅有日志和 readiness 证据。
3. 多副本部署需要跨实例的 Milvus 连接和依赖健康观测，当前验证为单实例集成环境。
