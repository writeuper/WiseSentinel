# 阶段186：RAG 双人标注与 Gold 集生成

## 背景

阶段182 已经要求 Recall/MRR/nDCG 使用 `verified` relevance 标签，但还缺少从人工/专家复核记录生成这些标签的可执行流程。直接把模型建议或单人猜测写入 `relevant_doc_ids` 会破坏评测可信度。

## 工具与输入

新增 `scripts/validate_rag_judgments.py`，输入是脱敏 CSV：

```text
case_id,annotator_id,doc_id,relevance,review_status
RAG-001,reviewer-a,doc-a,relevant,adjudicated
RAG-001,reviewer-a,doc-b,not_relevant,adjudicated
RAG-001,reviewer-b,doc-a,relevant,adjudicated
RAG-001,reviewer-b,doc-b,not_relevant,adjudicated
```

工具会：

- 拒绝空字段、非法 relevance/status 和重复 `(case, annotator, doc)` 判断；
- 统计双人覆盖、精确一致率和平均 Jaccard；
- 只有至少两名评审、所有判断已 `adjudicated` 且评审集合完全一致的 Case 才进入 Gold 输出；
- Gold 输出标记为 `relevance_label_source=expert_review`、`relevance_label_status=verified`；
- 默认要求至少 100 个 verified Case，未达门禁时返回非零；`--allow-incomplete` 只用于输出诊断，不会伪造通过。

示例：

```bash
python3 scripts/validate_rag_judgments.py \
  --input artifacts/rag-judgments.csv \
  --summary-json artifacts/rag-judgment-summary.json \
  --gold-output artifacts/rag-gold-labels.csv
```

## 隐私与可信度

- 汇总 JSON 不输出查询、文档 ID、文档内容、评审者身份或租户信息；Gold CSV 只应写入受控评测制品目录。
- 不一致 Case 不会自动多数投票成为 Gold，必须经过业务 adjudication 后重新提交。
- 一致率和 Jaccard 是标注质量诊断，不等于 RAG Recall；Recall/MRR/nDCG 仍需把 Gold 标签与实际检索结果关联后运行阶段182的严格评测。

## 验证证据

- 测试覆盖双人一致生成 Gold、分歧拒绝、重复/非法输入、100 样本门禁和汇总脱敏。
- 当前仓库没有虚构的人工标注数据；默认 130 Case 仍保持 unlabeled，直到真实评审产出 Gold 制品。
