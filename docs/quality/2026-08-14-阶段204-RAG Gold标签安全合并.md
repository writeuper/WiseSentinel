# 阶段204：RAG Gold 标签安全合并

## 面试缺口

阶段186/199 已能从双人复核生成 Gold 标签和审阅模板，但缺少把 Gold 安全合并回企业评测 CSV 的工具。手工复制标签容易出现 Case ID 不存在、重复 Gold、覆盖已有标签或把 draft/model_seed 误当 verified 的问题。

## 实现

新增 `scripts/apply_rag_gold_labels.py`：

```bash
python3 scripts/apply_rag_gold_labels.py \
  --dataset docs/整理与提升/enterprise_agent_eval_cases_130.csv \
  --gold artifacts/rag-gold.csv \
  --output artifacts/enterprise_agent_eval_cases_gold.csv \
  --summary-json artifacts/rag-gold-merge-summary.json
```

工具会：

- 只接受 `verified` 且来源为 `human/expert_review/golden_set` 的 Gold 行；
- 拒绝未知 Case ID、重复 Gold 和与现有标签冲突的合并；
- 默认不覆盖已有标签；完全相同的重复执行保持幂等；
- 保留非 RAG Case 和原有字段；
- 输出 dataset/gold SHA-256 和聚合计数，不输出查询、文档正文或文档 ID。

`--replace-existing` 仅在人工确认标签变更并经过评测 provenance 校验后使用。

## 当前事实

当前仓库仍没有真实双人复核 Gold 集，因此 Recall@K、MRR、nDCG 仍为 `N/A`。该工具只建立可审计的合并路径，不制造标签或质量数字。

## 验证

- 通过合并、幂等、冲突、未知 Case、重复 Gold 和未验证来源测试；
- 后续可直接把合并后的 CSV 交给 `run_agent_eval.py --require-verified-relevance`。
