## 3. 已闭环缺陷：`/api/v1/me` 绕过认证

### 问题与影响

`/api/v1/me` 的处理器读取请求上下文中的用户、租户和角色，但该路径此前被列入公共路径。因此无 Bearer Token 的调用会绕过 Auth/RBAC，接口语义与 README 的“当前 JWT 身份”约定不一致，并且缺少回归保护。

### 根因

认证中间件的公共路径清单把身份查询接口与健康检查、登录接口混在一起。RBAC 复用了相同的公共路径判断，因此两个防线同时被绕过。

### 企业级方案与取舍

主流做法是：仅将存活检查、就绪检查、指标（受网络策略约束）和登录/令牌交换列为匿名入口；身份、会话、租户、配置、审批和 Trace 一律使用认证后身份派生。路由权限应由显式 allowlist 或声明式策略统一维护，并通过匿名/有效令牌/无权限令牌矩阵进行黑盒回归。

本轮采用最小修复：将 `/api/v1/me` 从公共路径中移除。它不改变正常携带 Bearer Token 的调用行为，也不会影响新加入的内部 Webhook 专用放行规则。

### 落地与回归

- 修改：`internal/gateway/middleware/auth.go`，移除 `/api/v1/me` 的匿名放行。
- 测试：新增 `internal/gateway/middleware/auth_test.go`，断言 `/api/v1/me` 非公开，同时防止真正的匿名端点被误收紧。
- 回归证据：`go test ./internal/gateway/middleware -count=1` 通过。

## 4. 已闭环缺陷：开发 API Key 的租户选择与生产暴露

### 问题与影响

认证中间件先由 `X-Tenant-ID` 写入上下文；此前开发 API Key 分支仅填充用户和角色，不覆盖租户。因此持有开发 Key 的调用可自行选择租户，违背“认证身份决定租户”的隔离原则。同时生产环境仍可接受一个被配置为非默认值的开发 Key。

### 根因

开发便利逻辑没有建立服务身份到 tenant 的确定映射，也没有按运行环境禁用开发认证机制。

### 企业级方案与取舍

生产环境应使用专用 API Key/工作负载身份服务：密钥只存哈希，映射唯一服务账号、tenant 和 scopes，并支持轮换、撤销与审计。JWT/API Key 的认证成功后必须覆盖请求头提供的租户；请求头只能作为未认证入口的候选信息，不能成为授权依据。

本阶段未引入完整服务账号表和密钥轮换（需要数据库/API/运维协同），先采用兼容的安全收敛：开发 Key 固定绑定 `default` 开发租户，生产环境拒绝开发 Key。完整服务账号与资源级跨租户黑盒测试仍列为下一阶段 P0。

### 落地与回归

- 修改：`internal/gateway/middleware/auth.go` 新增开发 Key 身份构建函数，覆盖任意头部租户为 `default`；`APP_ENV=production` 时拒绝开发 Key。
- 测试：`internal/gateway/middleware/auth_test.go` 覆盖攻击者预置租户被覆盖、生产禁用开发 Key，以及 `/api/v1/me` 必须认证。
- 回归证据：`go test ./internal/gateway/middleware -count=1` 通过。

## 6. 已闭环缺陷：不完整 JWT 与开发登录的租户混淆

### 问题与影响

此前 JWT 解析成功但 `tenant_id` 为空时，认证中间件会保留 `TenantResolver` 从 `X-Tenant-ID` 写入的值。这使不完整或遗留 JWT 可以由请求头选择租户。另一个关联问题是开发登录接口本身为匿名入口，却用当前上下文中的租户查角色，最终却始终签发 `default` 租户 Token；恶意请求头可能将另一租户同名用户的角色带入默认租户 Token。

### 企业级方案与落地

企业身份令牌应自包含 subject、issuer、audience、expiry、tenant 与权限声明；授权不接受客户端提供的租户回退。生产环境应接入 OIDC/企业 IdP，不保留密码换取开发 JWT 的入口。

本轮采用兼容性修复：认证中间件拒绝缺少 `tenant_id` 的 JWT；开发登录在 `APP_ENV=production` 时拒绝；开发登录角色查询固定使用签发目标 `default` 租户，消除请求头影响。完整 OIDC、服务账号和资源级跨租户黑盒矩阵仍为 P0 后续项。

### 回归证据

- `internal/gateway/middleware/auth_test.go`：JWT 租户声明覆盖已有请求租户，空租户声明被拒绝。
- `internal/gateway/handler/auth_test.go`：生产环境拒绝开发登录。
- `go test ./internal/gateway/middleware ./internal/gateway/handler -count=1` 通过。
