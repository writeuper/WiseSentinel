# 阶段 5：敏感数据脱敏与观测治理

## 目标与范围

将 Agent 平台的工具、Trace、Ops 证据、故障知识和 API 展示从“原文截断”改为“统一脱敏后摘要”。本阶段保护新产生的观测与展示数据；工具实际执行输入和模型运行期上下文保持原始值，避免破坏查询和编排语义。

## 问题根因

原有 `truncateJSON` 只限制长度，不识别任何凭据或个人信息。工具输入/输出及错误因此会同时进入日志、`Evidence`、Trace Step 和 `ws_tool_call_record`；Ops 进一步把模型输出、工具证据写入任务详情和知识草稿。Chat 的 RAG 故障日志也会打印原始 Query。同步 API 路径还可能在持久化前直接把模型或工具结果回显给 Portal。

这会把一次临时工具调用的 Bearer Token、API Key、Cookie、连接串、邮箱或上游错误回显扩散为可长期查询、展示甚至进入知识库的内容。

## 企业级方案与取舍

采用“执行面原值、观测/展示面安全投影”的分层模式：

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 仅截断 | 拒绝 | 密钥可在截断窗口内完整泄露，且无结构化保护。 |
| 在工具调用前全局替换原值 | 拒绝 | 会破坏合法查询、受控写操作与模型编排。 |
| 日志、Trace、持久化摘要和 API 统一脱敏 | 本阶段采用 | 保持诊断字段、工具名、状态、耗时和 JSON 结构，同时避免明文扩散。 |
| 保存原始证据供排障 | 后续专项 | 必须使用独立 KMS 信封加密、短保留期、服务身份、用途审批与访问审计，不能复用 Trace/ToolCallRecord 表。 |

脱敏流程先递归处理 JSON 的敏感字段名，再扫描自由文本中的 Authorization/Bearer/Basic、JWT、`sk-` API Key、常见 DSN、敏感 URL 参数和邮箱；截断只发生在脱敏之后，并按 rune 截断以避免破坏 UTF-8。

## 落地实现

| 层 | 变更 |
| --- | --- |
| 通用组件 | 新增 `internal/pkg/redact`：无 I/O 的 `Text`、`JSON`、`Summary`，可保留安全 JSON 结构并做 UTF-8 安全摘要。 |
| Tool Gateway | Adapter 仍接收原始 input；日志、Evidence、StepSink、ToolCallRecord 和错误响应使用安全投影。Eino wrapper 不再打印原始 arguments。 |
| Trace | `AgentTraceRepo` 对 query、步骤入/出参及错误进行防御性脱敏，避免调用方遗漏时直写库。Chat 的 RAG 失败日志也不再打印原始 query/error。 |
| Ops/知识 | 任务 result/detail、错误、知识草稿字段及 evidence 写入前使用投影；Ops API 再次防御性处理 result/detail/evidence/conclusion。 |
| Chat/API/会话 | 同步和流式聊天 API、会话持久化及 Citation 摘要在展示/写入边界做脱敏，避免模型或工具回显直接进入客户端和会话历史。 |
| 审批 | 新建审批记录的 payload 仅保存已脱敏的工具输入。 |

## 自动化测试与回归证据

新增 `internal/pkg/redact/redact_test.go`，覆盖嵌套 JSON 敏感字段、Bearer/DSN/URL 参数/邮箱以及“先脱敏后截断”。新增 `internal/toolkit/gateway_redact_test.go`，以 canary 验证：

1. Adapter 能收到原始工具输入，不改变执行语义；
2. Evidence 和 StepSink 不包含 canary；
3. 业务响应在 ToolGateway 边界仍保留 adapter 原始结果，最终对外 API 再进行展示投影。

本轮已执行且通过：

```text
go test ./internal/pkg/redact ./internal/toolkit ./internal/agent/chat ./internal/agent/ops ./internal/repository ./internal/gateway/handler
make verify
```

`make verify` 覆盖 Go 全量 short test 和 `portal/./node_modules/.bin/tsc -b --pretty false`。

## 未完成项与下一阶段门禁

- 历史 MySQL/Redis/Milvus/日志与备份中的既有明文不会被本次在线脱敏自动删除；需要资产盘点、密钥轮换、保留/清理 runbook 和受控回填。
- 目前无独立 KMS 加密原始证据库、HMAC 关联指纹、字段级数据分类或保留期治理。
- `ws_ops_task.input_query` 仍是运行中任务的业务输入；如要做到持久化零明文，需要先实现受控原始请求仓和 opaque reference，不能直接删除而破坏 Worker 重试。
- Trace、Ops task 和 Chat session 当前仍缺少完整 owner/admin 对象级授权；同租户横向读取风险须在下一阶段以 ABAC、读取审计和前端路由防御修复。
- 需要补充真实 MySQL/API/Portal canary 集成测试、日志采集断言、fuzz 测试以及 CI 的敏感 sink 静态扫描；生产环境须在隔离测试租户执行。

下一阶段验收至少应证明：任意 canary 不会出现在数据库、日志、Trace API、Ops API 或 Portal；普通用户只能读取本人会话/Trace/任务，管理员读取产生审计；原始受控证据的读取具备短 TTL 与审批链。
