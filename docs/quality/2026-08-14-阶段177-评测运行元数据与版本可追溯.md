# 阶段 177：评测运行元数据与版本可追溯

## 背景

面试中要求评测优化前后可比较，但仅保存通过率和延迟会把不同评测集、模型、Embedding 或代码版本混在一起，无法证明优化来自哪一次变更。

## 实现

`run_agent_eval.py --summary-json` 现在附带 `evaluation_metadata`：

- `environment`、`run_label`；
- `model_profile`、`embedding_profile`；
- 输入评测集 SHA-256；
- 当前 Git commit；
- Python 版本；
- 脱敏的租户 fingerprint；
- case 筛选条件。

元数据不包含 API Key、Bearer Token、原始租户 ID、模型输出或工具 Body。通过 CLI 参数显式传入版本标签，避免脚本猜测运行环境。

## 使用示例

```bash
python3 scripts/run_agent_eval.py \
  --environment staging \
  --run-label prompt-v3 \
  --model-profile provider-model-v2 \
  --embedding-profile hash-embed-v1 \
  --summary-json /secure-artifacts/eval-summary.json
```

## 验证与边界

- 新增元数据脱敏和数据集指纹单测。
- Python 自动化测试：56/56 通过（提交前全量门禁复核）。
- 元数据只保证可追溯，不代表真实生产流量；模型/Embedding 标签必须由发布流水线提供并与实际部署配置核对。
