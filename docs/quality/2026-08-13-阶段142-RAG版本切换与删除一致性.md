# 阶段 142：RAG 版本切换与删除一致性

## 验证范围

在真实 MySQL/Milvus 环境执行 `go test -tags integration ./internal/rag`，耗时约 120 秒，全部通过，覆盖：

- 增量重索引与 Generation 发布；
- 第二代只读过滤；
- 租户隔离与并发检索；
- Secret Level 过滤；
- legacy 向量删除及精确分页边界；
- RAG 评测指标采集。

## 新增不变量

增量重索引后，同一文档的当前命中必须同时满足：

```text
metadata.generation == 2
metadata.version == "generation-2"
```

这保证 Citation 的版本字段与 Active Pointer/Generation 读侧过滤一致，而不是仅凭文档 ID 判断新旧。

## 结论

真实集成测试未发现旧代际误召回、跨租户泄露或删除分页遗漏。legacy 文档仍允许没有版本字段，但新建/重索引文档由 durable Generation 自动生成 `generation-N` 版本，客户端 Citation 可审计。
