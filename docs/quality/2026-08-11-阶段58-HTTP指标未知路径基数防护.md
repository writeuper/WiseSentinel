# 阶段 58：HTTP 指标未知路径基数防护

日期：2026-08-11

## 问题

阶段 56 已模板化 Trace 等已知动态路由，但 `normalizePath` 对任何未知 URL 仍直接返回原路径。攻击者或扫描器可请求无限随机 404 URL，使 Prometheus `path` label 生成无限时序，造成内存、存储、查询和告警稳定性风险。

## 企业级方案与实现

- HTTP metrics 采用 route allowlist：保留健康、metrics、OpenAPI、已注册 API 静态路由和已模板化动态路由。
- 未知路径统一标记为 `/unknown`，不携带任何请求路径片段。
- 这只影响 metrics 标签，不影响 HTTP 路由、状态码、审计或应用日志行为。

## 回归

| 验收 | 结果 |
| --- | --- |
| 动态路由与随机未知路径 normalize 单元测试 | 通过 |
| 后端构建 | 通过 |
| 真实 `/scanner/cardinality-a` 与 `/scanner/cardinality-b` | 均 HTTP 404 |
| 真实 `/metrics` | 仅 `path="/unknown"` 一条时序，计数 2 |

## 剩余风险

路由 allowlist 是手工维护的；新增 API 时应在发布检查中验证它获得期望模板标签，否则会安全地归入 `/unknown`，但失去细粒度端点可观测性。长期建议从 router 的已匹配路由模板自动生成 metrics label。
