# 阶段 144：真实并发阶梯与容量指标聚合

## 验证范围

本阶段在本地 Docker 依赖健康、平台进程已运行的条件下，执行真实 HTTP Chat、同步幂等和 SSE 合同，并补充质量报告对模型准入容量信号的聚合：

- `/health/ready`：MySQL、Redis、Milvus、Prometheus、Chat/Ops Model 和 Worker 均为 `up`；
- 同步 Chat 幂等 replay：通过，重复请求响应摘要一致，删除后的会话不可读；
- SSE basic：通过，收到正常 `done` 终态；
- Chat 阶梯并发：1、2、3 路各 1 次，均 100% 成功；
- Chat 4 路并发、8 请求：3/8 成功，5 个 `50304`，属于共享模型本地准入上限触发，非 HTTP 解析异常。

## 实测结果

| 档位 | 请求/并发 | 成功率 | 成功路径最大耗时 | 过载终态 | 清理 |
|---|---:|---:|---:|---:|---:|
| 单路 | 1/1 | 100% | 7.612 s | 无 | 1/1 |
| 双路 | 2/2 | 100% | 9.727 s | 无 | 2/2 |
| 三路 | 3/3 | 100% | 14.053 s | 无 | 3/3 |
| 过载 | 8/4 | 37.5% | 19.963 s | `50304`: 5 | 8/8 |

过载档位中，5 个请求的 `50304` 与模型 admission rejection 计数一致，过载会话历史均为空，说明拒绝发生在生成前且没有产生幽灵消息。当前配置的共享模型本地准入上限为 3；因此 4 路以上并发不能被表述为稳定吞吐能力。

## 指标改进

`scripts/report_agent_quality_metrics.py` 现在额外输出：

- `model_admission.rejections`：模型准入拒绝总数；
- `model_admission.in_flight`：当前占用的准入槽位；
- accepted/rejected decision count 与平均决策等待时间；
- `rejection_rate`：基于准入决策样本计算，不与 Agent 业务失败率混淆。

当前运行窗口聚合值为：准入拒绝 5、当前占用 0、决策拒绝率 33.33%，平均准入决策等待约 0.001 ms；模型熔断四类事件仍为 0。该窗口样本量较小，只用于容量归因和回归，不构成生产 SLA。

## 结论与剩余风险

1. 成功路径的主要耗时来自真实模型上游，当前 1–3 路并发最大耗时从 7.6 s 增至 14.1 s，应单独观察成功 P95/P99。
2. `50304` 是明确的容量保护信号，报告必须同时展示成功率、过载率、准入拒绝率和过载路径延迟。
3. 当前准入是单实例、本地共享信号；多副本生产环境仍需跨实例供应商预算、租户公平配额和集中式 admission。
4. RAG 当前运行窗口成功样本仍少于 30，P95 仅为 Histogram bucket 上界，不能当作生产承诺。
