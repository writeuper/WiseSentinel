# 阶段 79：SSE 自动化契约门禁

日期：2026-08-11

## 问题与根因

阶段 74–77 的 SSE 真实性能、取消、证据链和过载验证依赖一次性命令，不利于后续版本持续回归；尤其流式事件中 `error` 后仍可能有 `done`，若脚本只检查 `done` 会产生假成功。

## 落地

新增 `scripts/run_sse_chat_contract.py` 和 `make agent-sse-contract`：

- `basic`：要求 `connected + message + done`，并删除后验证 session 不可读；
- `cancel`：首个 message 后关闭流，要求 session history 为 0，再精确删除；
- `capacity`：并发流要求同时观察至少一个 `success_done` 与一个结构化 `sse_50304_retry_2`；
- 先调用 `/me` 校验认证 tenant，禁止 Header 伪造隔离；
- 仅输出稳定事件类别和聚合结果，不输出模型内容、citation 片段、问题、HTTP body 或凭据。

新增 3 个脚本单元测试，确保完整流、`error + done` 过载流、普通错误流不会被误判。

## 真实回归

| 场景 | 结果 |
| --- | --- |
| basic | `success_done` |
| cancel | `cancel_not_persisted` |
| capacity（10 并发） | 3 个 `success_done`，7 个 `sse_50304_retry_2` |

三种场景均通过，所有创建的 session 完成精确删除和不可读验证。

## 运行方式

```bash
EVAL_BASE_URL=http://127.0.0.1:8090/api/v1 EVAL_API_KEY='...' \
  SSE_SCENARIO=capacity SSE_REQUESTS=10 make agent-sse-contract
```

`EVAL_API_KEY` 必须通过受控 CI secret 或预配测试身份注入，禁止写入日志或工件。
