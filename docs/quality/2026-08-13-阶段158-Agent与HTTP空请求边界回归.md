# 阶段 158：Agent 与 HTTP 空请求边界回归

## 发现与修复

本轮对企业级 Agent 的内部调用面和 HTTP Handler 面进行 nil 请求审计，发现以下路径此前会直接读取请求字段，传入 `nil` 时可能触发 panic：

- Ops Agent `Analyze`
- Chat Agent `Invoke`
- Chat Agent `Stream`
- V1 `Chat`
- V1 `ChatStream`
- V1 `OpsAnalyze`
- Alert Webhook 与 Alertmanager Webhook Handler

现已统一在入口返回 `ErrBadRequest`（40001），不创建任务、不访问模型/RAG/工具依赖，也不写入业务数据。

同时将 Webhook event ID 计算简化为直接使用 `sha256.Sum256(body)`，去除无效的中间哈希表达式，降低审计歧义。

## 回归证据

- 新增 Chat Agent nil 请求测试。
- 新增 Ops Agent nil 请求测试。
- 新增 HTTP Handler nil 请求测试。
- `go test ./internal/agent/chat ./internal/agent/ops ./internal/gateway/handler`：通过。
- 既有输入长度、Webhook 签名、并发幂等、跨租户和权限测试保持覆盖。

## 企业级影响

该边界属于模型、Worker、Eino 包装器和 HTTP 请求共用的输入契约。统一拒绝可避免异常请求升级为进程级 panic，并保证错误可被 HTTP 指标、审计和评测 Harness 归类为 4xx，而不是误判为 5xx 或 Agent 失败。
