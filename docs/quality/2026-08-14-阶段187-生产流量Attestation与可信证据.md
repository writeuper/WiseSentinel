# 阶段187：生产流量 Attestation 与可信证据

## 面试缺口

平台此前只能说明“当前没有真实生产用户/流量证据”，但缺少一个安全接入外部生产聚合结果的契约。若直接把环境变量或本地请求数改成 production，会造成不可审计的宣传数字。

## Attestation 契约

质量报告支持通过 `--traffic-attestation` 或 `TRAFFIC_ATTESTATION_FILE` 读取匿名 JSON：

```json
{
  "status": "production_attested",
  "source": "gateway_aggregate",
  "window_start": "2026-08-14T00:00:00Z",
  "window_end": "2026-08-14T01:00:00Z",
  "request_count": 1000,
  "tenant_count": 12,
  "user_count": 80,
  "attestation_fingerprint": "<sha256 hex>"
}
```

允许的 `status`：`synthetic`、`staging`、`production_attested`；允许的来源：`gateway_aggregate`、`analytics_aggregate`、`load_test`。

## Fail-closed 规则

- 文件缺失或未配置：`not_claimed`。
- JSON、枚举、时间窗口、计数、SHA-256 指纹不合法：`invalid`，不暴露原始错误内容或文件路径。
- `production_attested` 必须有 64 位十六进制 attestation fingerprint。
- tenant/user/request 计数必须非负，tenant/user 数不能超过 request 数。
- 报告只保留窗口、聚合计数、状态和来源；忽略原始租户 ID、用户 ID、请求明细和额外字段。

## 可信度边界

Attestation 只证明外部管道提供了符合契约的匿名聚合制品，不自动证明业务成功率、用户采纳率或数据未被上游误配。生产上线仍应由独立发布/数据平台签发 fingerprint，并将制品 SHA、时间窗口、租户 cohort 和保留策略纳入审计。

## 验证

- 覆盖缺失制品、合法 production 制品、伪造 fingerprint、反向窗口、负数/超范围计数。
- 测试确认原始租户字段不会进入报告。
- 未提供真实生产制品，因此当前仓库的生产流量状态仍为 `not_claimed`，没有虚构生产用户数量。
