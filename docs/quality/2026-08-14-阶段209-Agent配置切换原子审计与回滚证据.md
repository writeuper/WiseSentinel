# 阶段 209：Agent 配置切换原子审计与回滚证据

## 面试缺口

配置 Schema 门禁解决了“非法版本激活”，但发布/回滚还缺少明确的旧版本、新版本和内容摘要证据。仅依赖 HTTP 审计路径，无法证明切换前后指针状态，也无法在评测中关联配置版本。

## 实现

- 激活事务读取当前 active 版本和目标配置；
- 校验通过后原子切换 active pointer，并在同一数据库事务写入 `ws_audit_log`；
- 审计只保留 `agent_type`、旧版本、新版本和 `config_sha256`，不写入 Prompt、工具参数或配置正文；
- 审计写入失败时整个激活事务回滚，避免出现“切换成功但无证据”；
- 激活响应返回 `previous_version` 和 `config_sha256`，可供发布门禁、评测基线和回滚记录关联；
- 重新激活旧版本天然形成受审计的回滚路径。

## 验证

- 单元测试验证摘要稳定、固定长度且不包含配置正文；
- Integration build-tag 测试覆盖非法版本不改变旧 active、合法切换返回旧版本和摘要、审计不泄露 Prompt；
- 无 `OPS_TEST_MYSQL_DSN` 时集成测试跳过，不把未执行的真实数据库证据冒充通过。

## 剩余风险

仍未实现灰度比例、双人审批、自动回滚阈值、配置 diff 展示和按配置版本的线上质量对比。当前“回滚”是管理员重新激活旧版本，不是自动化发布控制器。
