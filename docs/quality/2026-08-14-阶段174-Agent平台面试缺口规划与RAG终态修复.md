# 阶段 174：Agent 平台面试缺口规划与 RAG 终态修复

## 面试暴露的主要缺口

结合已有评测和运行态证据，当前平台的核心链路已经具备，但以下能力仍不能直接按生产级承诺描述：

| 能力域 | 当前证据 | 缺口/风险 | 优先级 |
| --- | --- | --- | --- |
| RAG 质量评测 | 已有 130 条企业评测集和真实闭环脚本 | Recall@K、MRR、nDCG、citation truthfulness 仍需冻结标注集和 >=100 有效样本；不能用端到端 P95 替代检索 P95 | P0 |
| 异步任务可靠性 | Ops/Index/VectorGC 有 lease、CAS、retry/dead 状态 | 数据库不可用时仍可能暂留 running，需要运行中任务巡检、租约回收和死信运营看板 | P0 |
| 生产 SLO | 已采集开发/集成环境 P50/P95、模型和 RAG histogram | 尚无真实生产流量；需按 Chat/Ops/SSE、模型 profile、租户、工具/RAG 依赖分桶并定义 P99、TTFT、错误预算 | P0 |
| 工具治理 | 已有 allowlist、风险等级、审批、审计和调用指标；阶段190已补审批决策率与等待时延 | 仍需工具级上游依赖可用率和成本分布；审批状态仍不等价于副作用执行成功 | P1 |
| 评测闭环 | 支持 CSV/HTTP Harness、关键词/Citation/Trace 检查 | 需固定 prompt/model/embedder 版本，关联 Bad Case、修复 commit 和前后置信区间 | P1 |
| 多租户与安全 | 有租户过滤、RBAC、脱敏和敏感 Sink 门禁 | 需持续做跨租户负向矩阵、密级越权、删除最终一致性和生产审计留存验证 | P1 |
| 前端质量 | Portal 构建和契约脚本已覆盖 | 缺少浏览器级 Chat/SSE/审批/Trace/知识库 E2E、可访问性和错误恢复门禁 | P1 |
| 运营与真实用户 | 当前样本主要来自本地集成环境 | 生产用户数、活跃租户、请求量、业务成功率和反馈闭环尚未接入，不能虚报“真实生产流量” | P0 |

## 分阶段补充计划

1. **P0-指标可信度（当前迭代）**：所有报表强制带样本量、环境、模型/嵌入版本和时间窗；样本不足时输出 `N/A`；完善 RAG 终态、running 巡检和死信告警。
2. **P0-RAG 评测**：冻结带 relevance 标注的 100+ query/document 集，计算 Recall@1/3/5、MRR、nDCG、citation 到达率、citation 有效性和越权泄漏数；每次优化绑定 commit。
3. **P1-容量与成本**：按 1/2/5/10/20 并发阶梯采集 TTFT、完成延迟、模型 token/cost、admission wait、429/50304、工具和 RAG 依赖错误。
4. **P1-生产运营**：接入真实用户/租户匿名聚合、业务反馈和人工复核；建立按版本的回归门禁与错误预算。
5. **P1-前端与安全**：引入浏览器 E2E、SSE 断线重连、审批竞态、Trace 脱敏、键盘可访问性和跨租户负向用例。

## 本次实现

`RAGService.ExecuteIndexTask` 在发布代际失败后，原实现忽略 `MarkFinishedIfOwned` 的错误和 CAS 未命中。现在：

- 持久化失败向上返回 `ErrRAGFailed`，由 Worker 进入统一错误/重试分类；
- CAS 未命中返回冲突，避免把失去租约的旧 worker 误报为成功；
- 只有确认任务仍由当前 token 持有时才认为“代际被替代”的失败终态已落库。

## 可信度声明

本阶段不新增生产流量或虚构 RAG 质量数字。已有 P50/P95、工具成功率、任务完成率和文档/Chunk/向量库存仍须按各阶段报告中的环境、样本量和 histogram 桶上界解释；生产结论必须在独立租户和真实观测窗口重新采集。
