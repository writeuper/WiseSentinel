# 阶段 104：130 评测集、告警 Runbook 与真实指标验证

## 目标

在开发/集成环境中验证企业级 Agent 平台的真实用户路径，覆盖路由、工具、RAG、并发、失败归因和可观测性；所有数字均标注统计口径，不作为生产 SLA。

## 落地变更

- 新增 `scripts/generate_enterprise_eval_cases.py`，生成确定性的 130 条评测集。
- 新增 `docs/整理与提升/enterprise_agent_eval_cases_130.csv`。
- 新增 `scripts/test_generate_enterprise_eval_cases.py`，校验数量、唯一性、字段兼容性和敏感信息。
- 新增 10 份 `docs/knowledge/runbooks/` 告警排查文档，覆盖 Kubernetes、HTTP、Redis、MySQL、Kafka、网关、发布和节点资源故障。
- 新增 `scripts/report_agent_quality_metrics.py`，只输出脱敏聚合指标。

- 依赖：MySQL、Redis、etcd、MinIO、Milvus healthy；后端 `/health/ready` 全部组件 up；Portal `:5173` 返回 HTTP 200。

## 当前实测聚合指标

- 已完成 Trace：926。
- 平均 Agent 执行步数：3.795 步/trace；Chat 约 2.0，Ops 约 4.8。
- 工具调用成功率：88.62%（1479/1669）。该口径包含历史 trace，需按时间窗和场景分层后作为发布门禁。
- RAG 检索样本：4，低于企业级最低建议 30；RAG 检索 P95：`N/A`。不得用端到端延迟替代 RAG P95。

## 失败、根因与风险

- 130 条全量实时评测尚未完成：早期 Chat/RAG 请求出现超时/HTTP 错误，说明模型长尾或检索链路仍需分层压测和超时归因。
- 10 份 Runbook 批量上传未完成：上传后索引任务出现 `DeadlineExceeded`。失败测试文档已用精确 `doc_id` 删除，未执行全量清库。
- Milvus health 仅证明服务存活，不能证明向量写入在当前模型/负载下满足时延与成功率要求。
- 当前没有真实生产用户或生产流量证据；所有结论属于本地开发/集成环境。

## 下一步准入条件

1. 先修复/定位 Milvus 写入超时，完成至少 30（建议 100）条有效 RAG retrieval 样本后再报告 P95。
2. 按 Chat、Ops、RAG、负向场景分批执行 130 条评测，并保存聚合结果与失败分类。
3. 以独立测试租户执行并发 Chat、SSE、幂等、Trace 访问和 cleanup 合同测试。
4. 只有在固定模型版本、时间窗、样本量和依赖健康证据齐备后，才可形成发布或生产 SLO 结论。
