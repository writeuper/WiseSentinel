# 阶段 172：同步 Chat 幂等终态错误传播

## 发现

同步 Chat 使用 `ws_chat_turn` 保存幂等执行状态。原实现对 Agent/会话失败后的 `Fail` 写入错误完全忽略，成功响应的 `Succeed` 写入错误和 CAS 未命中也统一返回内部错误，无法区分“数据库故障”和“执行令牌已被其他请求处理”，会造成重试语义和指标解释不一致。

## 修复

- 失败终态写入错误向上返回，避免数据库异常被吞掉。
- 成功终态持久化错误向上返回，并尝试将 turn 标记为失败（仍受同一执行令牌 CAS 保护）。
- `Succeed` CAS 未命中返回冲突，明确表示幂等执行权已丢失或状态已被其他请求改变。
- 响应序列化失败时也执行失败终态收口，并传播收口错误。

## 影响与剩余风险

幂等 turn 的成功/失败/冲突语义更可观测，客户端重试不会把未知持久化结果误判为普通 Agent 失败。若数据库完全不可写，终态仍无法落库，需要依赖数据库恢复后的巡检和专门的 running-turn 回收策略；本轮未扩大该策略范围。
