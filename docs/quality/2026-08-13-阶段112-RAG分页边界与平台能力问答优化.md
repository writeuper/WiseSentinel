# 阶段 112：RAG 分页边界与平台能力问答优化

## 修复一：legacy 向量分页删除边界

`DeleteLegacyByDocID` 使用 512 行分页扫描 Milvus。旧实现遇到第二页空结果时直接返回，导致匹配数量恰好为 512、1024 等整页倍数时，前面已收集的 ID 没有进入删除阶段，造成物理向量残留。

修复为结束扫描后统一执行已收集 ID 的删除；新增 512 个 legacy 向量的集成测试，验证完整删除和重复删除幂等。

## 修复二：平台能力问答不再误用运维 RAG

新增两个受控、可审计的静态能力分支：

- `static_platform_model_resilience`：模型超时、有限重试、退避、熔断和共享准入。
- `static_quality_report_projection`：质量报告聚合指标、脱敏边界和禁止输出的模型原文/凭证/Token/DSN。

运维组件问题（例如 Redis timeout）仍保留 RAG 检索路径，避免静态分支扩大匹配范围。
