# 阶段 97：真实场景降级与部署验证
日期：2026-08-12

## 目标与范围

在本地集成环境（后端 `:8090`、Portal `:5173`、真实模型凭据来自本地 `.env`）验证企业 Agent 的用户问答、Ops 排障、并发会话清理、依赖降级、前后端部署和观测口径。该环境不是生产环境，没有真实业务用户或生产流量；以下指标不得外推为生产 SLA 或业务准确率。

## 发现与修复

### 可选 MCP 冷启动预算

时间 MCP 不可用时，启动代码固定等待 10 秒，放大了滚动发布和故障恢复时间。

- 新增 `mcp.time.init_timeout_ms`，默认 2000ms；环境变量 `MCP_TIME_INIT_TIMEOUT_MS` 可覆盖。
- 仅接受 250–10000ms；无效、过低、过高值均回退到 2 秒安全值。
- MCP 仍输出降级告警，未被静默忽略。

### 就绪探针隔离

`/health/ready` 会同步探测 Milvus，原先不存在独立 deadline。在 Milvus 不可用时，探针曾出现十秒级阻塞。

- `App.Ready` 对所有依赖探测使用共享 2 秒 context budget。
- 不可用组件仍返回 `503 not ready`；修复的是探针尾延迟，不是把依赖异常伪装为健康。
- 部署后首次 ready 响应为 149ms，状态为 503（Milvus/RAG 降级）；后续 ready 为约 2ms。

### RAG 降级工具目录

在线普通问答在 RAG 未初始化时，模型仍能看到并调用 `query_internal_docs`，导致工具依赖错误上升为 Chat HTTP 500。

- Gateway 默认不注册该适配器。
- 仅在 bootstrap 成功构建 Milvus、embedding 与知识管道后，同时连接 RAG service 并显式暴露该工具。
- 回归测试证明无 RAG 时调用该工具得到“不可用”而非执行器错误；在线复测中 Chat 路由恢复，不再返回 500。

这是一项能力目录与实际依赖一致性修复：RAG 不可用时用户仍可获得无引用的通用回答；凡需要企业内部文档证据的场景仍应显示为 RAG 不可用，不能将无依据回答视作知识问答成功。

## 评估集、RAG 与工具统计口径

| 维度 | 当前已验证事实 | 正确解读与缺口 |
| --- | --- | --- |

| RAG 文档/Chunk/向量 | 指标快照：active documents 13；published logical chunks 10；legacy documents 11；本次新进程 physical vectors 0 | active chunks 是逻辑检索规模；physical rows 是全 collection、跨 tenant、含历史/GC 的物理库存。RAG 本次未就绪，0 不是业务库真实规模也不是召回分母 |
| 工具数量与成功率 | 配置的工具目录需在运行期以 `ListTools` 为准；本轮 Ops 期望工具调用 2/2 成功，成功率 100% | 2/2 是该小样本的“期望工具调用成功率”，不能表示全工具平台成功率。应以 Trace 中的 `tool_name × status` 聚合，排除模型未选择工具的分母混淆 |
| 任务完成率/失败率/响应时间 | Chat 并发 4/4（100%）成功；在线评估完成 2/3（66.7%）；评测 P50 165ms、P95 11785ms；负载 P50 2063ms、P95 8076ms | 必须按 route、模型 profile、工具/RAG 依赖、状态码分桶；不要把依赖降级下的 knowledge miss 与模型幻觉混为同一种失败 |

| 真实用户/生产流量 | 无 | 当前是开发/集成环境与测试身份。生产发布前应接入脱敏真实流量镜像或人工标注回放，并取得数据治理与租户授权 |

## 后续门禁

1. 先恢复隔离 Milvus，并运行含标注 query/document relevance 的 RAG 评估，报告 Recall@1/3/5、MRR、nDCG、citation 到达率及越权泄漏数；评估集和索引版本必须冻结并可追溯。
2. 扩充真实业务回放集，按 Chat、Ops、RAG、审批、告警、流式和多租户分层；将评测失败按路由、检索、工具、模型、权限和基础设施分类。
3. 在受控压测环境提升并发档位，分别统计成功率、50304 准入拒绝、P50/P95/P99、会话/幂等清理和模型成本；依据容量 SLO 设硬门禁。
4. 生产前必须使 readiness 200（或由部署策略明确允许的降级组件决定），并处理前端大 bundle 告警。
