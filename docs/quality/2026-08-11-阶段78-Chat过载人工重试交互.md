# 阶段 78：Chat 过载人工重试交互

日期：2026-08-11

## 问题与根因

阶段 77 已将流式过载表达为 `50304 + retry_after_seconds`，但 Portal 在发送时清空输入框，仅展示错误文本。真实用户需要重新输入原问题，且容易在会话中造成重复用户气泡；这使服务端给出的可恢复语义无法形成用户闭环。

## 落地

- Chat 页面仅在收到明确 `50304` 时保存本次问题并展示“重试发送”按钮；其他错误不提供盲目重放。
- 点击重试执行用户显式动作，复用原 session、RAG/工具选项和问题，但不再添加第二个本地 user bubble。
- 新对话或用户自行编辑输入会清除可重试状态；因此不会在输入意图已改变后重放旧请求。
- 保持无自动重试：Agent 请求可能包含工具和审计副作用，未引入端到端幂等键之前不能静默重放。

## 验证

- TypeScript 严格构建曾发现可选 `retry_after_seconds` 未安全收窄，已用类型守卫修复。
- Portal TypeScript + Vite production build 通过，Chat 懒加载包可正常生成。
- 后端真实 10 并发 SSE 已验证可产生结构化 `50304 + retry_after_seconds=2` 事件，是该 UI 状态的真实输入契约。

## 剩余风险

当前环境没有浏览器 E2E runner。上线前应增加 Playwright/Cypress 场景：过载后按钮可见、点击只发起一次原请求、不会重复 user bubble、用户编辑后按钮消失、取消/新会话后不可重试。
