# 阶段 88：过载会话状态完整性

日期：2026-08-11

## 问题与根因

并发压测此前验证了 `50304` 和 session 最终删除，但没有验证在删除前的会话状态。若模型准入被拒绝仍写入 user/assistant 消息，用户手动重试会面对幽灵历史，且审计与任务完成率会失真。

## 落地

`run_concurrent_chat_load.py` 对每一个 `api_50304` 在删除前读取该 session history：

- history 为空：`overload_history=empty`；
- 有消息：`unexpected_messages`，作为质量门禁失败；
- 不可读：`unreadable`，同样作为门禁失败。

该检查仅记录受控类别，不输出任何消息正文。

## 真实回归

5 请求 / 5 并发结果：

```json
{
  "outcomes": {"success": 3, "api_50304": 2},
  "overload_history": {"empty": 2},
  "cleanup": {"verified": 5}
}
```

所有过载请求均未产生会话历史，所有 session 随后均精确删除并验证不可读。并发质量门禁通过。

## 边界

此不变量仅针对“本地 admission 未取得槽位”的 50304。客户端超时、网络断连或上游完成后客户端中断可能存在不同的服务端完成状态，必须分别以 request idempotency 和持久化状态机治理。
