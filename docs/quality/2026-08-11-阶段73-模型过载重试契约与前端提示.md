# 阶段 73：模型过载重试契约与前端提示

日期：2026-08-11

## 问题与根因

阶段 72 已将模型饱和收敛为稳定 `50304`，但 HTTP 响应没有标准重试提示；Portal 只能显示泛化失败文本。真实用户无法判断是可稍后重试的读型 Chat 过载，还是不可安全重放的超时、审批或写操作失败。

## 企业级方案与落地

- 后端统一响应仅对明确可重试的 `50304` 添加 `Retry-After: 2`。不对模型 timeout、Agent 失败、审批或高风险写工作流添加该头，避免鼓励不安全重放。
- 统一错误处理由类型断言升级为 `errors.As`，允许带上下文的 `AppError` 保持其 HTTP/业务码语义。
- Portal `ApiError` 保存受控范围（1–60 秒）的 `Retry-After`；Chat 页面将 `50304` 呈现为“建议 2 秒后重试”。
- 不实现客户端静默自动重试：当前 Chat 请求尚未建立端到端的 request idempotency/去重账本。对于可能包含工具调用的 Agent 请求，自动重放可能重复外部读写或制造重复审计。因此由用户明确点击重试，后续在具备请求幂等键、工具风险分类和执行证据后再评估自动退避。

## 验收证据

| 检查 | 结果 |
| --- | --- |
| middleware/Chat/model Go 测试 | 通过 |
| Portal TypeScript + Vite production build | 通过 |
| 真实 4 并发 HTTP 契约 | 3 个 200；1 个 `503 / 50304 / Retry-After: 2` |
| 清理 | 所有契约测试创建的 session 均在 finally 中精确删除 |

真实请求仅输出 HTTP 状态、稳定业务码与重试秒数，不记录 API key、模型回答、提示词或错误正文。

## 剩余风险

`Retry-After: 2` 是单实例固定准入下的保守提示，不是预测性排队时间。多副本部署需要全局预算、租户公平配额、优先级和真实队列时延指标；只有在 Chat/工具调用拥有持久幂等语义后，才可以采用受控客户端自动重试。
