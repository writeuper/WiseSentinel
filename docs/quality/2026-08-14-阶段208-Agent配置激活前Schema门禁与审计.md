# 阶段 208：Agent 配置激活前 Schema 门禁与审计

## 面试缺口

阶段 207 已让活动配置进入 Chat/Ops 运行时，但激活接口此前只检查版本是否存在，不校验 `config_json`。因此非法 Prompt、越界迭代次数或重复工具列表可能先成为 active，直到下一次请求才暴露运行时错误。

## 实现

- `AgentConfigRepo.ValidateAgentConfigJSON` 在事务切换 active pointer 前执行 fail-closed 校验；
- 校验 JSON object、Prompt 类型和长度、`max_iterations`（0～100）、工具列表数量/名称/重复项；
- Knowledge 配置校验 `chunk_size`（100～2000）和 `overlap`（0～500）；
- 校验失败返回稳定的参数错误，事务不会先关闭旧版本；
- Audit Middleware 为配置读取和激活增加独立动作：
  - `agent_config.read`
  - `agent_config.activate`

## 验证

专项测试覆盖：非法 JSON、非法 Prompt、迭代上限、重复工具、知识库 Chunk 边界、合法配置和审计动作分类。全量门禁沿用阶段 207 的 Go/Python/迁移/Portal 构建检查。

## 边界

本阶段只校验结构和安全边界，不引入配置创建 API、双人审批、灰度发布或配置内容版本差异审计；工具名称仍必须在运行时经过 Tool Gateway 的 allowlist、Schema、风险和权限检查。下一阶段应补充激活前工具存在性/兼容性检查、旧版本回滚接口和按配置版本的评测基线。
