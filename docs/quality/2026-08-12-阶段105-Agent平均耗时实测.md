# 阶段 105：Agent 平均耗时实测

## 测试口径

- 历史口径：查询 `ws_agent_trace.latency_ms`，按 `finished_at` 非空的持久化 Trace 聚合；成功/完成与失败/超时分开统计，并按 Agent 类型分组。
- 实时口径：使用 `scripts/run_concurrent_chat_load.py` 执行 5 个 Chat 请求、并发 2；仅记录聚合耗时和 outcome，测试会话 cleanup 逐个验证。
- 当前环境：本地开发/集成环境。测试期间 `/health/ready` 曾显示 Milvus down，因此不能将本次结果解释为完整 RAG 健康状态下的生产性能。

## 结果

### 历史持久化 Trace

- 已完成 Trace：941
- 成功 Trace 平均耗时：**7186.41 ms（约 7.19 秒）**
- 全部已结束 Trace 平均耗时：**7105.53 ms（约 7.11 秒）**
- Chat 成功 Trace 平均耗时：**约 12.46 秒**
- Ops 成功 Trace 平均耗时：**约 4.50 秒**
- 工具调用成功率：88.68%（当前聚合快照）

### 实时 Chat 并发样本

- 请求数：5
- 并发数：2
- 成功率：100%（5/5）
- cleanup：5/5 verified
- 平均耗时：**约 12.78 秒**
- P50：12.22 秒
- P95/P99：19.07 秒
- 最大耗时：19.07 秒

## 结论

如果只需要填写“Agent 请求平均耗时”，建议使用：

> **历史全体已结束 Agent Trace 平均约 7.1 秒；成功请求平均约 7.2 秒。按类型看，Chat 成功请求约 12.5 秒，Ops 成功任务约 4.5 秒。当前 5 并发 Chat 实测平均约 12.8 秒，P95 约 19.1 秒。**

## 解释与限制

1. 平均耗时不等于 P95；不能用 19.1 秒替代平均值。
2. 历史 Trace 包含不同阶段、模型状态和失败样本，适合做开发/集成基线，不是生产 SLA。
3. Chat 通常包含模型生成，耗时显著高于 Ops 工具链；需继续拆分模型、工具、RAG 和排队耗时。
4. 当前 RAG 检索只有 4 个样本，RAG P95 仍为 `N/A`；不能从 Agent 总耗时反推 RAG 延迟。
5. 建议正式性能门禁至少使用 30 条稳定成功样本，生产容量评估建议使用 100+ 条并按 Chat/Ops/RAG、并发级别和模型版本分层。
