# 阶段 21：Embedding 响应契约校验

## 根因

DashScope 的成功响应只校验 `data` 数量是否等于输入数量，未校验 item index、重复 index、遗漏 index 或向量维度。合法 JSON 但语义异常的供应商响应可能触发 slice 越界 panic，或把错位/错误维度向量写入 RAG。

## 企业级方案

将外部成功响应视为不可信契约：校验每个 index 在输入范围内且唯一、每个输入 index 都恰好出现一次、每个 embedding 维度等于已配置维度。任一违约返回稳定错误，不进行部分写入或补偿性猜测。

## 落地

- 校验负 index/越界 index。
- 校验重复 index 与最终遗漏 index。
- 校验每条 embedding 的长度等于 `dimensions`。
- 新增受控 HTTP 响应测试：越界、重复、维度不符均拒绝；乱序但完整的合法响应按 index 重排后成功。

## 回归证据

```text
go test ./internal/rag/embedder
make verify
```

均通过。

## 遗留项

- 仍需限制成功 JSON body 大小和 `data` 中单条向量的总字节预算，避免极大合法响应占用内存。
- 向量数值的 NaN/Inf 校验、模型版本/维度漂移检测、embedding 供应商的 schema version 仍需后续完善。
- 应在真实 Milvus 索引集成测试中验证契约失败不会发布任务成功或留下部分向量。
