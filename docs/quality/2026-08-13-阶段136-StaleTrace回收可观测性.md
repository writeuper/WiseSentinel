# 阶段 136：Stale Trace 回收可观测性

## 目标

为启动时 stale Trace 恢复增加 Prometheus 证据，避免只能依赖日志或数据库状态判断进程恢复效果。

## 变更

新增无标签低基数 Counter：

```text
ws_agent_trace_stale_reaped_total
```

仅在启动回收实际标记记录时递增；不会记录租户、Trace、错误原文或请求内容。`abandoned` 状态仍在质量报告中与业务失败分开统计。

## 真实启动验证

使用最新二进制启动：

- 启动日志：`reaped stale Agent Traces: 1`；
- Prometheus：`ws_agent_trace_stale_reaped_total 1`；
- 数据库状态：`abandoned=18`、`canceled=1`、`failed=102`、`success=1825`；
- 超过 10 分钟的 `running` Trace：0；
- `/health/ready`：`ready=true`。

## 测试

- 新增 Counter 单调递增与无标签边界测试；
- 可观测性和 Bootstrap 测试通过；
- 生产应使用 Prometheus 持久化窗口统计该 Counter 的增量，例如 `increase(ws_agent_trace_stale_reaped_total[15m])`。
