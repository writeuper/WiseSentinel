# 阶段 140：模型超时与 Citation 版本闭环

## 真实验证

- 130 条评测已完成：业务质量通过率 100%；
- 1 次 RAG Case 触发模型 504 超时，约 40.1s；模型指标记录 1 次 timeout，成功调用 P95 约 30s；
- SSE cancel：`cancel_not_persisted`；delete-race：`delete_race_not_completed`；Trace 访问合同通过；
- RAG 成功检索样本 62，均值约 183ms，P95 约 250ms bucket upper bound。

## Citation 版本修复

检索结果本身已经携带文档 `Version`，但此前 Chat REST/SSE Citation 投影丢弃了该字段，客户端无法判断引用是否来自当前 Active Pointer 对应代际。现已将 `version` 贯通：

```text
RetrievedDocument.Version
  → domain.Citation.Version
  → api/v1.CitationItem.Version
  → REST / SSE citation
```

字段使用 `omitempty`，兼容无版本的 legacy 文档；展示前仍经过长度限制和脱敏投影。

## 结论

业务质量链路已形成“当前版本检索 → Citation 带版本 → 前端可审计”的闭环。模型 30 秒超时仍是主要长尾风险，应继续通过模型路由/降级和生产 SLO 告警治理，不能把 RAG 检索 250ms 与端到端 30s 混为同一指标。
