# 阶段 60：Portal 路由懒加载与首屏包体治理

日期：2026-08-11

## 问题

Portal 在 `App.tsx` 中静态导入 Chat、Ops、知识库、审批、管理、故障知识和 Vector GC 页面，导致运营页面的表格、图表、图标和客户端逻辑全部进入首屏 bundle。阶段 59 build 报告入口约 1.27MB（gzip 398KB）。

## 实现

- 将登录以外的业务页面改为 `React.lazy` 动态导入。
- 用可访问的 `Suspense` 加载态（`role=status`、`aria-live=polite`）包裹页面；角色守卫仍在懒加载组件之前执行，服务端 RBAC 不变。
- 没有强行将全部 Ant Design 聚为 vendor chunk：构建实验会把共享 chunk 增至 1.06MB，反而加重登录/布局初始下载，已撤回。

## 构建回归

| 项目 | 结果 |
| --- | --- |
| TypeScript + Vite production build | 通过 |
| 入口 chunk | 793KB，gzip 254KB |
| Ops chunk | 64.68KB，gzip 20.31KB |
| Knowledge chunk | 55.26KB，gzip 19.41KB |
| 审批/管理/Vector GC/FaultKnowledge | 独立动态 chunk |

与阶段 59 相比，入口 gzip 从约 398KB 降至约 254KB（约 36%）。

## 剩余风险与后续

Vite 仍提示共享核心 chunk 超过 500KB。不得提高警告阈值掩盖问题；下一步应以真实 RUM/浏览器 waterfall 为准，对 Ant Design 做组件级按需导入、审查大型 Table/图标依赖，并在登录、Chat、Ops 三条真实用户路径上测量 LCP/INP 和缓存命中。
