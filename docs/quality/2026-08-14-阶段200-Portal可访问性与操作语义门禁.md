# 阶段200：Portal 可访问性与操作语义门禁

## 面试缺口

Portal 已有生产构建、Chat 流竞态和 API 契约测试，但此前没有系统校验 Chat、Ops、审批和 Trace 关键控件的可访问名称、状态语义和错误恢复入口。企业级运营平台不能只依赖鼠标和颜色区分状态，也不能让用户在失败后无法恢复。

## 实现

补充 Chat、Ops、审批和 Trace 页面语义：

- Chat 问题输入、RAG/工具/流式开关、新对话、发送和重试操作都有明确 `aria-label`；
- Ops Prompt、异步模式、最大执行步数、开始分析、状态筛选和刷新有明确名称；
- 审批批准/拒绝按钮包含目标审批 ID，刷新和审批意见输入可被辅助技术识别；
- Trace 加载失败提供带名称的重新加载操作。

新增 `scripts/test_portal_accessibility_contract.py`，作为静态可访问性契约门禁。

## 可信度边界

该门禁验证源码中的语义契约，不等价于真实浏览器 E2E、屏幕阅读器、键盘焦点、颜色对比度或移动端布局验证。当前项目仍没有 Playwright/Cypress 浏览器回归；上线前应在隔离环境接入浏览器测试并覆盖 SSE 断线、审批竞态、Trace 权限和键盘操作。

## 验证

- Portal 可访问性与 Chat 状态契约测试：6 项通过；
- `npm --prefix portal run build`：通过；
- 构建仍有既有 Ant Design 大 chunk warning，不影响构建成功。
