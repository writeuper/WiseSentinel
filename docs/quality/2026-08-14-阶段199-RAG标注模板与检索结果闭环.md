# 阶段199：RAG 标注模板与检索结果闭环

## 面试缺口

平台已经能计算 Recall@K、MRR、nDCG，也有双人复核 Gold 生成器，但默认 130 Case 没有 verified relevance 标签。缺少“评测运行结果 → 双人标注 → 专家仲裁 → Gold 集 → 严格排序指标”的操作入口，容易让 RAG 指标长期停留在 `N/A`，或被工程猜测标签污染。

## 实现

新增 `scripts/build_rag_judgment_template.py`：

```bash
python3 scripts/build_rag_judgment_template.py \
  --evaluation docs/整理与提升/agent_eval_results.csv \
  --output artifacts/rag-judgments.csv \
  --summary-json artifacts/rag-judgments-summary.json \
  --annotator reviewer-a --annotator reviewer-b \
  --top-k 5
```

脚本只选择 RAG Case 和评测 Trace 中真实记录的检索文档 ID，生成两个审阅者的 `draft` 行；`relevance` 永远留空，不会猜测相关性，也不能被 `validate_rag_judgments.py` 当作 Gold 集。审阅者可以补充未出现在 Top-K 中、但业务上相关的文档，再将完整结果交给既有双人一致性和 `expert_review` 生成流程。

输出摘要包含 Case 数、缺失检索结果数、候选行数和 `verified_rows=0`，不输出查询、文档正文、租户或用户信息。

## 当前事实

本地当前可用评测结果没有足够的 RAG 检索候选，因此模板摘要为 `candidate_rows=0`、`verified_rows=0`。这不是 RAG 质量为 0，而是评测运行/人工复核证据尚未形成；Recall@K、MRR、nDCG 继续保持 `N/A`。

## 验收

- 至少两名不同审阅者是硬性要求；
- 候选文档去重并限制 Top-K；
- 所有输出行初始为 `draft` 且 relevance 为空；
- 缺少检索结果时显式计入 `cases_missing_retrieval`；
- 通过 Python 单元测试验证不生成伪 Gold 标签。
