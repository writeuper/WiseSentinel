# 阶段 52：安全评测元数据与受控诊断表达

日期：2026-08-11

## 问题与根因

阶段 49 移除同步 Ops 响应中的工具正文后，原有评测中部分场景直接依赖 `Evidence.output` 的 source 或日志关键词，整体结果一度从 24/24 变为 20/24。恢复工具正文会重新打开数据泄露旁路；单纯删除断言则会降低评测有效性。

## 企业级解决方案

将“自由文本证据”与“可评测、可运维元数据”分离：

- `OpsEvidence.source` 是服务端按工具名映射的固定 allowlist（例如 `prometheus`、`logs`、`knowledge_base`），不是 adapter 输出。
- 结果展示按用户请求映射为固定诊断类别/信号词表：告警、指标、日志、发布变更、限流（`rate limit triggered`）、分布式锁（`distributed lock wait timeout`）。不回显原始 query、工具输入或工具输出。
- 信息不足场景输出固定补充项（服务、接口、时间范围、指标），保持零工具调用的安全澄清。
- 评测脚本使用工具名/状态、来源元数据与受控结论；不再读取工具正文或明细。

## 实现与前端契约

- API `OpsEvidence` 新增可选 `source`；保留状态、耗时、字节数、`suppressed=true`。
- Portal 在工具证据行展示 source tag，不显示工具 payload。
- `safeOpsResult` 只生成 allowlist 诊断表达，普通自由文本仍完全抑制。

## 剩余风险

- 受控词表必须经业务/合规审核，避免将错误信号词视为真实根因；其语义是“检测到的诊断类别/信号”，最终判断仍应查看结构化结论与 trace。
- source 映射是 adapter provenance，不证明数据值正确；工具正确性仍需 Trace 状态、下游健康和基准数据联合验证。
