# 阶段 6：对象级授权与读取审计

## 问题与根因

Trace、Ops task 和 Chat session 以前只按 `tenant_id` 查询。RBAC 虽限制了入口角色，却不能表达“同租户 operator 只能看自己创建的对象”，因此获授权的同租户用户可以通过猜测或获得 ID 横向读取他人的会话历史、Agent Trace 或 Ops 证据。

## 企业级方案

采用 RBAC + ABAC：RBAC 决定是否可以进入功能域，ABAC 以 `owner_id == current_user` 决定普通用户对单个对象的读取权限；只有 `sre_admin` 和 `platform_admin` 可跨用户读取同租户对象用于受控运维。对象不存在、跨租户或未授权均返回 Not Found，减少 ID 枚举信息。读取 Trace 写入 `trace.read` 审计 action。

## 落地实现

- Session 的 `GetSessionMessages`、同步 Chat 和流式 Chat 均先用 `ws_session.user_id` 校验所有者。
- `GetTrace` 在读取到 tenant-scoped Trace 后校验 `trace.user_id`。
- `GetOpsTask` 校验 `ws_ops_task.created_by`；Ops 列表对普通用户改为数据库 owner filter，管理员仍可读同租户队列。
- 新增 `OpsTaskRepo.ListByTenantAndCreator`，避免先读取全量数据再在内存过滤。
- 读取 Trace 纳入审计记录；Audit 不记录请求正文。

## 自动化回归

新增 `internal/gateway/handler/authorization_test.go`，验证：owner 可读、同租户 non-owner 拒绝、空 owner 不会成为公共对象，且仅 `sre_admin`/`platform_admin` 可跨用户读取。

## 遗留风险与后续门禁

- 目前测试验证了授权决策函数；还需以真实 MySQL/Redis 和 HTTP JWT 构造 owner、non-owner、admin、cross-tenant 的端到端用例，并确认审计行写入。
- 管理员跨用户读取尚无 break-glass reason、细粒度 evidence 访问级别或独立审批；这些属于下一阶段的运维访问治理。
- 现存 session/trace/task 若 `user_id`/`created_by` 为空会默认拒绝普通用户；需要在数据迁移中明确归属策略，不能回退为全租户可读。
