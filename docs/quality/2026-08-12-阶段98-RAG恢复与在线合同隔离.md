# 阶段 98：RAG 恢复与在线合同隔离
日期：2026-08-12

## 目标

以真实模型、MySQL、Redis、Milvus 与 Portal 组成的本地集成环境，复核上一阶段 RAG 降级问题，恢复完整 Agent 能力，并执行知识生命周期、全量冻结评测、租户隔离、流式、幂等和容量保护验证。所有测试都使用认证身份所属的 `default` 租户或测试创建的精确隔离资源；测试创建的会话、文档和临时 Milvus collection 均由测试自身确认清理。

该环境没有真实业务用户或生产流量，所有数字是集成环境事实，不可直接作为生产 SLA、用户成功率或业务召回率。

## 发现、根因与企业级方案

### 1. RAG 基础设施停止导致完整能力不可用

**现象**：API liveness 为 200，但 readiness 为 503，Milvus down、RAG degraded、Index/Vector-GC worker down；RAG 指标中 physical vectors 一度为 0。

**根因**：`milvus-standalone` 容器未运行。历史日志还出现 etcd deadline、时钟跳变和节点重连，属于向量数据库基础设施可用性问题，不能通过扩大应用层 deadline 伪装为可用。

**主流方案与取舍**：

- 生产优先采用编排平台 health check、依赖启动顺序、PDB/资源保留、etcd/Milvus 告警、时钟同步和受控重启；应用 readiness 继续 fail-closed。
- 应用级降级适用于普通无证据 Chat；凡要求知识引用、索引或删除回收的用户路径必须显示不可用，不能返回“成功但无证据”。
- 本地采取最小恢复：启动既有 Compose 的 `milvus` 服务，确认 `9091/healthz=200`，再重启 API 重新装配 RAG 依赖。

**回归证据**：恢复后 `/health/ready=200`，MySQL、Redis、Milvus、RAG、模型、Ops/Index/Vector-GC worker 均为 up；physical vectors 为 130。130 是整个 collection 的物理行数（跨 tenant、可包含 legacy/历史/GC），不是 active chunks 或 Recall 分母。

### 2. 并行在线合同污染全局模型计数

**现象**：将 Chat 负载、SSE 和幂等合同并行执行时，负载出现 `50304`，幂等合同显示 `request_outcomes=[conflict,success]` 却因 `model_calls_delta=7` 失败。

**根因**：三类测试共享同一模型准入预算和进程级 Prometheus `ws_model_calls_total`。后者不是按 test/session/turn 分桶的计数，其他测试的合法模型调用污染了幂等测试差量。

**主流方案与取舍**：

- 最优：为每个测试环境分配独立模型 deployment 或可关联 test-run id 的受控遥测；成本较高。
- 可行：在线容量/故障注入独占时段或单独环境；业务合同串行执行。
- 幂等正确性应由 durable turn 唯一键、CAS execution token、相同的可重放响应及 Trace identity 证明，不应只依赖非隔离总量指标。

**落地**：`scripts/run_chat_idempotency_contract.py` 不再读取全局模型调用计数。replay 要求安全响应完全一致且具备 trace；并发要求一个 `success`、一个 `40901 conflict`，串行 replay 的 trace 必须等于获胜请求的 trace。脚本仍验证精确会话删除。

**回归证据**：

- replay：通过，稳定响应哈希与同一 trace；同 key 不同请求仍为 `40901`。
- concurrent：通过，`[conflict, success]` 与同一 trace。
- SSE cancel：通过，断连后未持久化半回合。
- SSE delete-race：通过，删除后不再完成且会话不可读。

## 发布判断与后续

当前 API `/health/ready` 为 200，Portal/API 均可访问，RAG 主链路与安全隔离回归通过；可作为**集成环境继续迭代**基线。

仍不能宣称生产就绪：

1. RAG 评测集只有 3 条合成排序探针，需建设至少 100+ 人工复核、按租户/密级/文档版本/语言/业务域分层的冻结集，并报告 Recall@1/3/5、MRR、nDCG、citation 正确率、无结果率和越权泄漏数。
2. 真实用户/生产流量为 0。进入生产前须完成经授权的脱敏流量回放或影子流量，以及数据保留、访问审计和成本预算验证。
3. Chat/RAG P95 为 7.7–20.2 秒；需按模型 profile、区域和并发档位设定 SLO，压测中区分成功路径、50304 admission 和上游超时，并设置错误预算。
4. Milvus 历史 etcd deadline/clock-skew 日志必须由基础设施监控、资源与时间同步治理闭环；应用仍维持 readiness fail-closed。
5. 前端生产 bundle 约 795KB（压缩前）需继续拆包和浏览器交互性能验证。
