# 阶段 128：Milvus 重连可观测性与 RAG 回归

## 目标

为 Milvus 自动重连增加低基数、隐私安全的可观测性，并验证新增指标不会影响依赖恢复后的 RAG 能力。

## 变更

- 新增 `ws_milvus_reconnects_total{outcome}`；
- `outcome` 仅允许 `success` 或 `failure`，未知值归一为 `failure`；
- 指标只表示 WiseSentinel wrapper 的“重连尝试结果”，不代表 Milvus 容器重启次数；
- 不记录地址、租户、文档、Trace、错误原文或上游凭据。

## 验证

- 观测层单测验证 success/failure 标签和未知标签归一化；
- 重建并启动新平台二进制，readiness 全部正常；
- 受控终止并恢复 Milvus 后，平台 readiness 自动恢复；
- 指标捕获到 4 次 wrapper reconnect failure，恢复后没有出现 success 尝试计数；这说明本次 SDK/健康探测路径可能在恢复时自行复活或未进入替换分支，不能把 success 计数解释为容器恢复次数；
- 恢复后真实 RAG-001：1/1 通过，工具命中 1/1、关键词命中 4/4，端到端约 22.6 秒；
- `ws_rag_inventory_refresh_errors_total` 保持 0。

## 当前指标口径

当前重启后的进程内 RAG 样本只有 2，不能与前一进程生命周期样本合并。RAG P95 仍是 Histogram 桶上界；Agent 端到端耗时包含模型和编排，不应与 RAG 检索耗时混用。

## 剩余风险

1. 重连指标当前只覆盖 wrapper 主动尝试，无法代表所有 Milvus 网络恢复事件；生产建议同时采集容器/服务健康事件和 SDK reconnect 事件。
2. 当前没有对重连成功路径的可控 fake-client 集成测试，真实 SDK 的自动恢复行为仍需在专用故障注入环境进一步验证。
3. RAG-001 成功但端到端 22.6 秒，普通模型长尾仍是主要交互风险。
