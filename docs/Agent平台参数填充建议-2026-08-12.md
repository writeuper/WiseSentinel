## 可直接替换的正文

### 核心职责

- **RAG 知识库索引与异步链路：** 负责知识库文档解析、结构化分块、Embedding、向量写入和检索流程，按照 Markdown 标题层级与 Chunk Overlap 保留 Runbook 的故障上下文；当前有效知识库包含 **13 篇 active logical documents、10 个 active published logical chunks**，Milvus 中约 **130 行物理向量记录**。通过 DB Task、Index Worker、Redis 抢占锁、MySQL CAS 和 Lease 续约实现索引任务的异步执行、幂等控制和失败恢复。

- **知识库版本一致性：** 针对文档重复发布、旧版本向量残留和删除最终一致性问题，引入文档 Generation、Active Pointer、读侧版本过滤和事务 Outbox，保证只有当前生效版本参与检索，并通过异步清理机制处理旧版本向量和删除任务。文档发布采用异步 Index Task，当前不承诺固定生效时延；验收以索引任务完成和 active generation 可检索为准。本轮新增 Runbook 曾出现索引超时，已按精确 doc_id 清理测试资源；旧版本误召回已具备生命周期合同验证，但仍需扩大样本量统计。

- **Ops Agent 多步诊断链路：** 负责告警 Webhook 触发后的自动分析流程，采用 Planner-Executor 模式将告警分析拆分为诊断计划和工具执行步骤，围绕指标、日志、发布记录、Trace、当前时间和内部知识等 **10 个注册工具**生成诊断计划，汇总工具返回结果后输出带 Citation 的诊断结论。单次完成 Trace 平均执行 **3.795 步**；历史端到端 P95 约 **20.16 秒**，当前受控 10 条 Ops 样本 P50/P95 为 **193/317 ms**，两者均不代表生产 SLA。

- **工具治理与风险控制：** 建设 Tool Gateway 和工具注册表，统一管理 **10 个工具**的 Agent Allowlist、风险等级、RBAC、参数 Schema、调用超时、幂等策略和人工审批；当前配置为 **L0=7、L1=3、L2=0**，暂无已接入的 L2 高风险写工具。调用链路持久化记录调用主体、Agent、工具、参数摘要、执行状态、耗时和错误信息。

- **链路追踪、问题定位与评测闭环：** 以 Trace ID 串联路由、RAG、模型、Planner、Executor、Replanner 和 Tool Step，记录各步骤的输入摘要、输出摘要、执行状态、耗时和错误信息；基于 HTTP API 和 CSV Case 构建 Agent Evaluation Harness，当前设计评测集包含 **130 条 Case**，覆盖约 **10 类**告警、日志、指标、Trace、发布、RAG、普通问答、多工具和负向边界场景。历史冻结集 **25/25 通过**，当前受控 Ops 子集 **10/10 通过**；历史迭代已沉淀至 **第 104 阶段**。工具成功率按历史 Trace 聚合为 **88.62%（1479/1669）**，Citation 目前仅有 **1/1 生命周期合同验证**，广泛业务 Citation 有效率仍需补测。

### 项目成果

- 完成“告警 Webhook → 诊断规划 → 工具执行 → 异常重规划 → 证据汇总 → 诊断结论”的 Ops Agent 闭环，覆盖 **10 类 Runbook/故障主题**及告警、日志、指标、Trace、发布和多工具综合诊断场景；
- 建立覆盖 **13 篇 active logical documents、10 个 published logical chunks、约 130 个物理向量记录**的 RAG 异步索引和检索链路，实现文档版本切换、旧版本过滤、删除清理和失败恢复；
- 建立覆盖 **10 个工具**的工具注册、风险分级、RBAC、调用审计和 Trace 回放机制，当前 L2 高风险工具数量为 0；
- 基于 **130 条设计评测 Case**和历史 **25 条在线冻结 Case**验证 Agent 路由、工具命中、Citation、任务延迟和失败恢复能力。历史冻结集任务完成率为 **100%（25/25）**，当前受控 Ops 子集为 **100%（10/10）**；历史全量工具调用成功率为 **88.62%（1479/1669）**。Citation 仅能报告 **1/1 生命周期合同=100%**，RAG 检索 P95 暂为 **N/A（4 个样本不足统计门槛）**。

## 使用注意

不要将以下表述写入生产宣传材料：

1. “130 篇文档、130 个有效 Chunk”——当前 130 是物理向量行，逻辑 published Chunk 只有 10。
2. “RAG P95=20.16 秒”——20.16 秒是历史端到端 P95，不是 RAG 检索 P95。
3. “Citation 有效率 100%”——目前仅有 1/1 生命周期合同样本。
4. “全量 130 Case 通过”——130 条已生成，尚未完成全量在线回归。
5. “已有高风险自动修复工具”——当前 L2 工具为 0，不能虚构生产写执行器或自动恢复能力。
